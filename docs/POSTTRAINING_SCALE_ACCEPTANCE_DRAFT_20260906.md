# TravelAgent2 后训练规模与验收草案

2026-09-06。以下是本项目拟采用的工程验收目标，不是“大厂统一招聘门槛”，也不表示当前已达标。本轮执行范围是 multiday80 数据采集、审核与冻结；本草案不启动额外付费队列或训练。

## 当前证据边界

现有真实 SFT 对照只使用一个训练种子、14 个共同任务/13 个来源组。扩展48题开发集覆盖16个相关组合；仅示范和示范＋接手在普通规划、恢复题上的表现不同，不能依据总分自动替换模型。80题新train按20个相关组合生成，4个城市/日期变体不计成4种独立结构。37个教师配对任务在付费前按脚本可行性固定，不能报告成全80题无偏教师成功率。

数据规模必须同时报告：独立来源组、任务实例、完整轨迹、唯一动作、实际监督token，以及重复采样次数。合成场景不是实时旅行事实，固定脚本预检轨迹不是教师标签。

## 扩大训练数据前的准入

1. 原始场馆与餐厅事实先于请求定义；保留工具查询、输入参数、错误、时间和预算消耗。无进展与恢复样本来自真实学生状态，禁止根据dev失败复制事实或状态生成训练标签。
2. 以来源关系建立拆分组，城市/日期替换、同一目录和近似组合放在同组。仅字符串去重不构成语义独立证明；记录组合与工具技能之间的关联。
3. 教师输出按任务、独立质量、SFT结构三个层次审核；不得将解析器默认值当教师输出，不监督思考、学生前缀、控制器代答、未执行拒绝和未提交终态。失败与单边成功均保留。
4. 所有完成生成核对实际输入token哈希；取消请求没有哈希时单列证据缺口，不补造。发布数据使用实际训练框架的预处理和collator验证全答案监督、prompt屏蔽、单EOS及零截断。
5. 固定选题和停止条件后采集，禁止按教师成功结果付费重抽。可行性选择及被排除来源必须披露。

## 建议的下一阶段数据门槛

先通过当前配对发布包的审核，再按覆盖矩阵分批扩展。建议在正式比较前争取至少500个训练任务、50个可审计来源组，并在示范与接手两侧获得至少200个共同接受的规划任务。普通多日规划、具名餐饮证据和工具恢复分别报告，不用预算拒绝等容易终态增加规划通过率。

这些数值是阶段目标，不是充分质量条件。若共同支持或关键能力覆盖不足，应补独立来源，不能复制动作行数凑门槛。优先补没有可行接手样本的组合；固定脚本失败只说明该脚本未通过，不证明场景无解。

## 训练对照

- 原学生权重只读；所有新模型从同一明确初始适配器开始。先比较仅示范与示范＋接手，两侧使用相同来源、每步相同完整答案监督token、相同优化器和更新步数。
- 保留两侧共享示范锚点。混合比例在训练前按来源监督token声明；保留长度与重复次数上限，不截断答案或屏蔽部分答案凑预算。
- 每个配置至少3个预先声明的训练种子；固定训练轮次/检查点选择规则。报告每个种子与每个分组结果，不挑最好种子或最好终态。
- 按来源累加答案损失并除以该更新实际监督token总数；实际4B模型上核对损失、梯度、LoRA-only更新和冻结基模。来源与答案token相同不等于prompt token或FLOPs相同，分别记录耗时和输入量。
- 当前两批开发集用于诊断。训练方案、模型选择和评测统计口径固定后，再启用未用于调试的锁定测试集；不得重新命名旧dev充当最终测试。

本阶段的示范与接手属于工具动作SFT，二者起始上下文不同，不能直接拼成同一prompt的DPO偏好对。若后续做偏好优化，需要在同一真实状态下生成可比较的候选、执行校验并记录偏好理由，另行冻结数据与对照。

## 测试与发布门槛

拟准备至少200个锁定测试任务，按来源组隔离并报告组合相关性。除离线合成主测试，另做少量可核验真实工具适配测试，明确时效、供应商失败及用户确认边界；离线通过不代表实时旅行信息正确。

报告原始任务通过率、严格质量通过率、原始策略错误、原目录硬约束、工具恢复、无进展次数、未进入solver失败、截止取消、费用和延迟。统计不把同组合变体当独立样本；如给区间，按来源组聚合/重采样并说明组数有限的局限。

模型发布前要求固定测试中无未授权约束放宽、无伪造工具结果、无训练/测试泄漏；性能增益需在多个种子和关键分组保持，恢复或约束指标退化须解释并解决。保留原适配器、版本化运行环境、逐次证据和可执行回退路径。当前不自动上线。

## 资源与预算

所有数据构造、学生推理、教师调用、测试、token审核、训练和压缩均在既有云主机；本地只编辑与SSH/SCP。沿用同一个100元教师API总账，不因换批次重置。每批设置子限额与请求上限，先预留再按用量结算，未知用量保留计提，云算力单列。并发上调需新的预先声明队列配置与限流观测，不能用学生GPU吞吐直接推算教师API速度。

本轮核验的现行总请求上限为3000次。多步教师轨迹每条可能消耗十余次API，不能在此配置下直接承诺完成500个全配对任务。扩大前必须根据实际每轨迹调用数重新排期；若调整内部请求数上限，需另行记录配置迁移、保留全部既有请求和费用、维持100元总限额，并验证恢复/预留/熔断规则。当前运行中的配置保持不变，不能重置账本规避次数限制。

完成上述阶段后再整理项目陈述：讲清真实数据规模、对照设计、失败修复和复现证据；避免把“几百条动作”“一次较高dev分数”写成稳定生产能力。
