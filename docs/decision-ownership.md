# TravelAgent2 决策职责盘点：小模型现在到底能决定什么

日期：2026-09-05。状态：**第一件事“决策职责盘点”已完成；尚未开展 24 个真实模型诊断案例、统一基线或新训练。**

## 先看结论

**现在的项目是“固定阶段流程 + 阶段内模型决策 + 控制器自动处理”的混合 Agent Loop。小模型有真实决策空间，但六类目标能力并没有全部交给它。**

例如，系统知道需要景点、交通、开放时间等证据时，模型可以决定先查哪一项，也可以填写部分查询参数。但是，当只差开放时间时，系统会直接发起查询；当规定的证据类型齐全时，系统会直接尝试结束研究阶段。后面的求解、验证、草稿整理等步骤也通常自动执行。

这意味着：**工具调用成功、任务最终成功，都不能单独证明小模型学会了决策。必须看这个决定实际由谁作出。**

对后训练最重要的三个结论：

1. **现在可以重点训练：**实际交给模型的工具选择、有效关键词、结果理解，以及没有预置恢复答案时的语义恢复。训练前仍要确认所需证据真的进入模型输入。
2. **先调整决策边界，再训练：**是否澄清、证据是否足够、是否继续补查或结束等能力。当前不少场景已经被系统选好了下一步，仅增加同类训练样本不会让模型学会这些判断。
3. **继续由系统保证：**用户明确的城市日期、权限、硬约束校验、有限重试、求解器执行。保留这些工程能力，同时把它们与模型训练收益分别记账。

这里的“系统”包括控制器、调度器、验证器和工具执行器；“模型”主要指 Agent Loop 内的策略模型。上游意图解析可能调用其他模型，它的能力不自动归属于这个小模型。

## 2. 一次请求实际如何走过 Agent Loop

```text
用户需求被整理成目标、约束和缺失字段
    ↓
代码建立阶段任务图，调度器选择当前可执行阶段
    ↓
是否存在已把动作和改参方式确定好的可信恢复合同？
    ├─ 是：系统直接执行恢复
    └─ 否：控制器判断能否自动推进
              ├─ 能：系统直接产生动作
              └─ 不能：收窄可用动作和可见状态，调用策略模型
    ↓
检查动作权限，补入或改写部分参数
    ↓
执行工具 → 验证结果 → 更新状态 → 继续循环
```

默认 ReAct 任务图包含六个阶段：

`研究取证 → 求解行程 → 验证行程 → 审核行程 → 整理草稿 → 等待确认`

如果目标中已经记录缺失字段，前面再加“询问用户”阶段。**这张阶段图由代码生成，当前并非由小模型自由拆分任务。**研究与失败处理可以循环，因而项目仍具有 Agent Loop 行为，只是自主决策集中在部分阶段。

特别容易误解的是：`execution_mode="react"` 也会包装 `ControllerFirstPolicy`。这不等于启用了旧的 `controller_first` 模式，而是 ReAct 入口本身仍保留自动推进逻辑。[代码位置：A1、A2、A3]

## 3. 六类能力职责表

| 想训练的能力 | 小模型目前实际负责什么 | 系统已经决定什么 | 对下一步训练的影响 |
|---|---|---|---|
| 补信息与澄清 | 在交给模型的澄清轮中生成 `question` | 上游状态提供缺失字段；`needs_user` 或缺信息时只保留 `ask_user`，通常只呈现第一个缺失字段 | 当前主要能证明“问得清楚”；尚不能据此证明模型会判断是否该问、优先问什么 |
| 搜索与证据获取 | 多个证据缺口并存时，选择允许的工具及部分语义参数 | 所需证据种类由规则推导；只有一个缺口时自动调用；城市、部分日期和参数由执行器处理 | 工具顺序和关键词是已有训练空间；要排除自动查询、被覆盖参数对成绩的贡献 |
| 证据充分性 | 在仍有模型决策空间时选择补查动作、处理不足反馈 | 所需类型齐全时自动 `finalize_research`，之后仍由研究验证器检查质量 | “结束取证是否合理”目前经常不是模型判断；需要保留验证器，同时给模型真实的继续/结束选择 |
| 错误恢复 | 没有完整恢复合同、且进入模型分支时，根据失败证据改关键词等 | 可信合同确定动作和改参方式时绕过模型；其他场景还会限制恢复工具与次数 | 确定性重试算系统可靠性；真正需要读证据、选策略的恢复才用于证明模型能力 |
| 规划修订与约束冲突 | 在许可范围内选择补查、重新求解、请求折中或停止，并表达理由 | 求解器排程；验证器分类冲突；重试策略和可提出的折中选项由系统提供，部分状态只剩一种动作 | 目前是受限选择，不能宣称模型自由重规划；需要分清“识别冲突”与“根据已分类冲突选行动” |
| 收尾与授权 | 在确有选择时决定请求折中或停止；生成提问或理由 | 硬约束通过后自动接受；整理草稿、进入确认阶段自动推进；禁止未授权放宽约束 | 不把自动接受、自动完成算成模型结束判断；模型也不能代替用户给出授权 |

**判断标准：看有没有实质选择，而不是只数工具数量。**只允许 `search_pois`，但必须自行判断该删哪个关键词，仍有决策价值；模型被调用后只能输出无参数的唯一动作，则几乎没有策略学习空间。

## 4. 每个动作与参数归谁

以下列出策略层登记的全部 **19 个动作**。它们不会在每一轮同时出现；实际可用动作还要经过阶段、状态与权限过滤。表中“可填参数”不代表最终一定原样执行。

| 动作 | 模型可填参数 | 当前实际边界 |
|---|---|---|
| `retrieve_city_knowledge` | `topic` | 研究分支可选主题；城市由系统提供；唯一缺口时可能自动调用 |
| `search_pois` | `keywords` | 非空关键词通常保留并去重；空列表会用用户偏好等补齐；城市、必去景点和类别边界由系统处理 |
| `get_weather` | `date` | 可用研究工具之一；自动分支可直接带入开始日期；城市由系统提供 |
| `search_current_info` | `query`、`info_type`、`date` | 有模型分支时才有选择；已有明确查询时可能覆盖 `query`；活动待查时可强制 `event`；开始日期可覆盖 `date`；唯一缺口时三者均可由控制器构造 |
| `search_transport` | `mode`、`date` | 出发地、目的地、日期来自约束；用户只指定火车或飞机时覆盖 `mode`；没有这种限定时才保留方式选择空间 |
| `get_poi_detail` | 无 | 模型在允许时选择调用时机；具体批量查询哪些候选由执行器收集，不能据此声称模型选中了某个 POI |
| `get_route_matrix` | 无 | 模型在允许时选择调用时机；候选点、约束等由系统提供 |
| `finalize_research` | 无 | 当前证据类型齐全时通常自动触发；验证器仍可能判定证据质量不足 |
| `solve_itinerary` | schema 中有 `strategy` | 正常阶段自动调用；执行器默认强制 `cpsat`，除非已有重试覆盖记录；不算模型自主选求解算法 |
| `validate_itinerary` | 无 | 正常阶段自动调用；行程、事实与约束由系统提供 |
| `accept_itinerary` | 无 | `hard_pass` 为真时自动接受；未通过时禁止接受 |
| `retry_solve` | `reason` | 是否可用由冲突类型与预算约束；具体重试策略由系统注入 `greedy` |
| `propose_tradeoff` | 状态化 schema 中只有 `reason` | 可提出的选项必须来自控制器许可清单；原始参数类存在 `options`，不能因此把选项生成记成模型能力 |
| `ask_user` | `question` | 模型生成询问文字；很多场景已由系统确定必须问、先问哪个缺失字段 |
| `abort` | `reason` | 有时能与折中动作比较，有时唯一允许停止；固定停止理由由系统组装，模型补充具体说明 |
| `compose_draft` | 无 | 正常阶段自动整理求解结果，不是由这个策略模型从零生成行程 |
| `finish` | 无 | 正常确认阶段自动推进；不能解释成用户已经同意任何新增授权 |
| `capability_check` | 无 | 已登记但不是默认六阶段 ReAct 图中的独立节点；不要将旧图行为混入新图统计 |
| `accept_candidates` | 无 | 旧候选收集流程相关动作，不属于默认 ReAct 研究动作集合 |

对应代码：A3、A4、A5。日期城市等用户已明确事实的注入通常是合理设计；需要重点辨别的是关键词、查询策略、信息类型等**正在被考察的语义参数**是否也被系统决定。

## 5. 分支探针实际看到了什么

| 合成状态 | 是否到达模型委托入口 | 观察到的行为 |
|---|---|---|
| 同时缺多个研究证据 | 是 | 在本例的六个缺口工具中选择；不是所有已登记工具均可选 |
| 仅缺实时开放信息 | 否 | 控制器调用 `search_current_info`，生成查询、类型和日期 |
| 所需研究产物类型齐全 | 否 | 控制器调用 `finalize_research` |
| 行程验证硬约束通过 | 否 | 控制器调用 `accept_itinerary` |
| 求解阶段 | 否 | 控制器调用 `solve_itinerary` |
| 验证阶段 | 否 | 控制器调用 `validate_itinerary` |
| 草稿阶段 | 否 | 控制器调用 `compose_draft` |
| 确认阶段 | 否 | 控制器调用 `finish` |
| 缺出发地、开始日期且需要用户补充 | 是 | 只允许 `ask_user`，可见缺失列表收窄为出发地 |
| 无恢复合同的过宽景点查询失败 | 是 | 只允许 `search_pois`，但关键词仍需判断 |
| 研究重试耗尽且没有替代方案 | 是 | 本例只允许 `abort` |
| 重试耗尽、标记工具缺失且有许可替代方案 | 是 | 本例允许 `propose_tradeoff`、`abort` |
| 可信合同已确定删除某关键词 | 否 | 控制器直接执行改参后的 `search_pois` |

以上 13 个检查点中，8 个返回控制器动作、5 个到达委托入口。**这不是生产环境中的占比，也不是模型成绩。**委托入口用检查对象替代真实模型，因此“到达”只能证明代码把机会留给了模型，不能证明模型会作出正确决定。

另做了 5 个参数处理检查：

| 输入动作 | 参数处理结果 | 说明 |
|---|---|---|
| 实时查询写“自定义查询”、日期写 11 月 1 日 | 变成约束中的“西湖开放时间”和 10 月 1 日，补入杭州 | 模型填出的查询/日期不一定真正生效 |
| 交通方式填 `both`、日期写 11 月 1 日 | 变成用户限定的 `train`、10 月 1 日，补入往返地点日期 | 不能把遵守已注入约束的结果全算给模型 |
| 景点关键词填空列表 | 补入“无障碍、博物馆”等用户偏好 | 空参数也可能得到有效工具结果 |
| 景点关键词只填“无障碍” | 保留该显式关键词，补入其他系统字段 | 这是可训练的真实参数选择空间 |
| 求解策略填 `greedy` 且没有重试覆盖记录 | 执行参数变为 `cpsat` | schema 可填不等于策略有最终决定权 |

这些检查调用真实参数处理函数，没有继续调用外部工具或求解器。后续工具执行使用该函数返回值，源码入口见 A5。

## 6. 训练之前最需要处理的五个问题

### 问题一：目标能力比当前模型权限更宽

方案想训练“模型决定是否追问、是否证据足够、是否结束”，当前代码很多时候已自动决定。模型没有作答机会，就无法用这些任务证明训练收益。

**后续处理：**在隔离的开发环境里，先为这些能力各设计有真实选择的状态。提供证据、可用工具、预算和约束，允许模型提出继续查、请求补充、结束取证等动作；验证器继续检查其是否合理。不要只把自动动作改成让模型照抄一次。

### 问题二：只剩一个工具，不代表参数也无需判断

`controller_policy_action` 看到唯一证据缺口时，会直接产生动作。对于无参数动作可以节约调用；但搜索工具可能仍需要判断关键词、信息类型和查询内容。当前自动分支会默认或构造这些参数。

**后续处理：**拆开“工具已经确定”和“语义参数已经确定”两个判断。只有两者都确定才自动执行；若仍需结合证据构造查询，应留下模型决策轮。先通过 24 个开发案例确定必要范围，不在本次直接改运行时。

### 问题三：现有动作审计字段不能完整代表工具最终参数

`PolicyAction` 已有 `model_arguments`、`arguments`、`decision_source`、`controller_hydrated_fields` 等字段，但执行器的 `_hydrate_arguments` 另建参数字典。上述探针中，查询、日期、方式已经改变，原 `action.arguments` 和 `controller_hydrated_fields` 却没有同步更新。轨迹记录接收的仍是 `execution.action`。

**结论范围：这些动作字段本身不足以还原全部最终执行参数。**这不代表其他工具日志一定没有记录，而是不能仅凭它们判断“模型输出被原样执行”。[A5、A6]

**后续处理：**补齐或关联以下记录，比较时同时展示三份参数：

- 模型原始输出：`raw_model_arguments`；
- 权限处理后的动作参数：`authorized_arguments`；
- 工具实际收到的参数：`executed_arguments`；
- 各字段来源：模型、用户约束、系统默认、恢复合同；
- 动作来源及实际模型身份：小模型、教师模型、控制器；保留修复重试次数。

以上是建议字段名，本次没有修改日志 schema。统计模型参数正确性要先看原始提议，统计系统执行正确性再看执行参数，避免静默改参掩盖模型错误。

### 问题四：模型看到的是压缩状态，不一定是完整工具历史

在线 `propose` 路径通常构造“系统提示词 + 当前状态 JSON”，不是每轮直接拼接全部原始工具对话。当前状态包含最近 6 次决策、有限事实/产物摘要和失败摘要等；提示词投影还会压缩内容、移除内部字段。

本地模型另有 `propose_from_history` 接口，训练环境也会呈现状态与转移。**共用一个状态转换函数，并不保证训练、评测、在线发送给模型的完整消息序列相同。**本次确认接口形态存在差异，尚未做最终渲染输入逐条比对，也不能据此断言它已经造成成绩下降。[A7]

**后续处理：**在开发案例中保存最终模型输入，检查错误原因、当前约束、查询历史、证据来源和时效性是否足够；再固定训练与部署采用哪种历史形式。模型看不到证据的问题先修输入，不能全部归因于模型不聪明。

### 问题五：恢复合同和语义恢复必须分开验收

云端恢复合同可以确定重试哪个工具、怎样改参数，随后绕过模型。这类能力有系统价值，但不证明小模型理解了错误。没有完整合同的另一条恢复路径仍可能调用模型，所以也不能说所有错误恢复都由控制器完成。

**后续处理：**保留可信确定性恢复的系统回归；另设语义恢复开发任务，只给可观察错误和诊断证据，由模型决定如何修改。不能把隐藏评分答案或“正确应删除的关键词”作为输入，再当成自主推理收益。[A2、A8]

|---|---|
| 补信息与澄清 | 必要字段缺失、字段齐全、偏好含糊但可继续、用户已回答后避免重复问 |
| 搜索与证据获取 | 开放信息过期、交通方式未限定、活动信息待查、多证据缺口选取查询顺序 |
| 证据充分性 | 只有介绍缺开放证据、来源互相冲突、证据齐全应结束、证据失效应补查 |
| 错误恢复 | 暂时超时、无结果、语义不相关、参数格式或取值错误 |
| 规划修订与约束冲突 | 可通过调整求解解决、需要新增证据、需要用户同意折中、不可擅自放宽的硬约束 |
| 收尾与授权 | 已验证可交付、仍有未解决失败、需要用户批准替代方案、重试耗尽应停止 |

每例先检查四件事：**该轮有没有调用模型、模型看到什么、真的能选什么、输出最后有没有被系统改掉。**对于没有实质选择的案例，标为“当前模型能力不可测”，不能计为答对。一个场景可能存在多种合理动作，不强制与唯一标准工具序列完全一致。

下一项的完成条件：24 例都有决策记录；六类能力的决策空间和证据可见性问题能被定位；需要调整的接口有明确清单。完成必要调整与运行时冻结后，再进行可比较的模型基线。

本次完成的是职责盘点，**不是整个“第 0 步”已经通过**。后训练开跑条件仍按主方案执行。
