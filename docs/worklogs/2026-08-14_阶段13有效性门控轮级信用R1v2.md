# 2026-08-14 阶段 13：Validity-Gated 轮级信用 R1-v2

## 1. 阶段目标

修正第一版轮级 GRPO 的两个根本问题：

1. 原 `policy_return_to_go_credit()` 先按全部 episode step 计算折扣，再过滤 Controller step，导致自动 Controller 步错误地拉长模型动作到终局的距离；
2. 原信用为 `0.5 * local + 0.5 * discounted terminal`，成功轨迹中的非法或无依据动作仍可能因正终局分得到正信用。

阶段目标不是立即训练新模型，而是先建立一个可审计、可拒绝、不会污染 B0 历史结论的 R1-v2 信用合同。

## 2. 文献依据与项目取舍

实现依据来自阶段 11 精读的 ToolVerse、TRACE、MT-GRPO、Structured Reflection、PROGRA、CIGPO 等工作，主要吸收三条共同原则：

- 轮级信用必须只投影到模型产生的决策 token；
- 局部动作有效性与未来全局收益要分开处理，不能让终局成功补偿无效动作；
- 训练前后必须报告非零 advantage 和零方差比例，保存 checkpoint 不能作为“学到了”的证据。

没有直接照搬 TRACE/IGPO 的标准答案信息增益，因为旅行规划是多解任务。TravelAgent 使用的是可验证的动作合法性、grounding、工具结果、状态推进、Solver/Validator 与终局结果。

## 3. 保持不变的边界

- `hierarchical-b0.v1` 的轨迹级 Reward 和既有正式 B0 评测不被重写；
- 当前离线候选仍是 trajectory-level GRPO-B0；
- 新算法作为独立 R1-v2 研究路径存在；
- 只有通过训练信号门禁和公平对照后，才允许修改候选模型声明；
- 本阶段没有在 AutoDL 启动 GRPO，也没有声称模型质量提升。

## 4. Reward 事实层改造

在 `TurnReward` 中加入：

- `validity`: `invalid | external_failure | valid`；
- `future_credit_eligible`: 是否允许传播未来终局收益。

分类规则：

### 4.1 invalid

由模型决策造成的不可执行或不可相信动作，例如：

- action 不在 `allowed_actions`；
- 工具调用缺少可审计 observation；
- 参数未 grounding；
- 伪造受保护参数；
- snapshot 参数不匹配；
- 工具未授权、参数 schema 失败、调用上限违规。

结果：固定负信用，不允许未来信用传播。

### 4.2 external_failure

动作本身合法、参数有依据，但外部环境或工具返回失败，例如：

- `UPSTREAM_TIMEOUT`；
- 合法调用得到空结果；
- 上游数据不可用；
- 可重试的服务故障。

结果：信用为中性 0，不把基础设施故障错误归责给模型，也不让它继承终局成功。

### 4.3 valid

动作合法、参数有依据、调用可审计。只有此类动作允许使用局部过程信号与折扣终局信号。

Reward audit 新增：

- `invalid_model_steps`；
- `external_failure_steps`；
- `future_credit_eligible_steps`。

## 5. 模型轮 return-to-go 修正

新增 `PolicyTurnCredit` 审计记录：

- 原 episode `step_index`；
- validity；
- future eligibility；
- local reward；
- 按模型轮计算的 terminal distance；
- 最终 credit。

实现顺序改为：

1. 先把 reward turn 与 episode step 对齐；
2. 先过滤 `decision_source=controller`；
3. 在过滤后的模型决策序列中计算 distance；
4. invalid 固定为 -1；
5. external failure 固定为 0；
6. valid 才使用局部 reward 与折扣 episode reward。

因此 2 个模型决策之间无论插入多少 Controller 步，前一个模型决策到终局的距离都仍为 1。

## 6. Token advantage 投影改造

`turn-credit-projection.v2` 增加 validity 输入与以下统计：

- `compared_turn_buckets`；
- `invalid_model_turns`；
- `external_failure_turns`；
- `invalid_action_positive_credit_count`；
- `invalid_action_positive_credit_rate`；
- `zero_advantage_group_ratio`；
- `effective_nonzero_credited_turns`。

关键安全性质：

- group norm 只比较 `valid` 轮；
- invalid token 固定为 -1，不得回退到正的 trajectory advantage；
- external failure token 为 0；
- 无法与 credit record 对齐的额外模型段保守视作 invalid；
- Controller 和工具结果 token 仍为 0，不参与策略梯度。

## 7. Trainer 与训练报告门禁

Trainer 从环境读取结构化 `_policy_turn_credit_records()`，而不再只有匿名浮点列表。为了防止评估 rollout 掩盖训练失败，累计指标拆分为 train/eval：

- `train_compared_turn_buckets`；
- `train_zero_variance_turn_buckets`；
- `train_effective_nonzero_credited_turns`；
- `train_invalid_action_positive_credit_count`；
- 对应 eval 指标。

新增 `validate_turn_credit_totals()`。一个 R1-v2 run 要能被报告，必须同时满足：

- 训练阶段有效非零信用轮大于 0；
- 训练阶段至少存在一个可比较轮桶；
- 不是所有可比较轮桶都零方差；
- 无效动作正信用计数为 0。

如果训练完成但门禁失败：

- checkpoint 仍保存供诊断；
- `training_report.json` 写入 `status=rejected` 和具体 gate error；
- 进程以错误状态结束，禁止把该 run 表述为有效 R1-v2。

## 8. 测试过程中遇到的问题

### 8.1 旧测试与新安全合同冲突

旧测试要求“credit 数少于模型 token 段时，多出的模型轮继承 trajectory advantage”。在成功轨迹中，这会让一个无法审计的额外动作得到正信用，与 validity gate 直接冲突。

处理：将合同改为保守负信用，并断言 `invalid_action_positive_credit_rate=0`。这不是为了让测试变绿改结果，而是测试本身仍代表旧算法，需要与已确认的新安全目标同步。

### 8.2 旧报告兼容

历史 `TurnReward` 没有显式 validity 字段。Pydantic 默认值会将旧记录解析为 valid，可能让历史 `TOOL_FAILED` 获得未来信用。

处理：R1-v2 回放时对旧记录做保守重建：format/grounding 负分或显式 invalid signal 归为 invalid；`TOOL_FAILED` signal 归为 external failure。B0 原报告数值不变。

### 8.3 训练/评估指标混合

初版 Trainer 只维护合计指标，而 `trainer.evaluate()` 会在训练后继续累计。若门禁读合计值，验证 rollout 可能掩盖训练阶段零 advantage。

处理：增加 train/eval 分离累计，发布门禁只读取 train 指标。

## 9. 真实生产循环合同审计

新增脚本：

```powershell
python scripts/audit_turn_credit_contract.py \
  --case-index 7 \
  --gamma 0.95 \
  --output ml/agentic/reports/turn-credit-contract-case7.json
```

它使用真实：

- `TravelAgentEnvironment`；
- `ControllerFirstPolicy`；
- `CurriculumTeacherPolicy`；
- `HierarchicalRewardEngine`；
- `policy_turn_credit_records()`。

结果：

- 总 episode step：10；
- Controller step：8；
- 模型决策 step：2；
- episode reward：0.947；
- 第一次合法 `search_pois` 遇到 `UPSTREAM_TIMEOUT`：`external_failure`、credit=0、distance=1；
- 第二次成功 `search_pois`：`valid`、credit=0.5985、distance=0；
- invalid action positive credit rate：0。

该结果证明折扣距离只按两个模型决策计算，且合法外部超时不会被惩罚或继承终局奖励。报告文件是 UTF-8；PowerShell 某次直接进程输出出现中文乱码，但重新读取文件确认内容未损坏。
