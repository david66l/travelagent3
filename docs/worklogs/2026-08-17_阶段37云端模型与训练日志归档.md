## 模型结论

### 1. 当前应保留：Stage36 1.7B SFT

- 模型服务名：`travel-policy-qwen3-1.7b-stage36-boundary-sft-formal`
- 本地 checkpoint：`ml/agentic/checkpoints/qwen3-1.7b-stage36-boundary-sft-formal-v1`
- adapter SHA-256：`5802c03b6fb3a65449d3bfcf1c05ba58a5a38e2fb4b0c71d17ca81fc54250055`
- 训练方式：从 Stage32 SFT adapter 继续训练，对首次工具调用后的终止 token 施加 16 倍权重。
- 正式结果：原始标签 149/150、生产契约 150/150、多动作 0/150、目标案例 5/5。
- 发布级别：5% Shadow；它是当前最新候选，不是未经观察即可全量发布的生产版本。

### 2. 稳定回滚：Stage32 1.7B SFT

- 模型服务名：`travel-policy-qwen3-1.7b-stage32-sft-formal`
- 本地 checkpoint：`ml/agentic/checkpoints/qwen3-1.7b-stage32-sft-replay-formal-v1`
- adapter SHA-256：`cd958716d6329eac3b25e94ca51fce79631ceb1dc9188e2adb8494e5041fec6e`
- Stage32 正式结论将它设为 production default。Stage36 是在它之上修复一次重复工具调用，因此该版本应作为回滚基线保留。

### 3. 只做对照：Stage32 1.7B DPO v2

修正 reference policy 后，DPO 相对 Stage32 SFT 在模型原始输出上只增加 2/150，配对显著性不足，因此只进入 Shadow，不能替换稳定 SFT。其本地 adapter 已存在，未重复下载。

### 4. 上一代参考：Stage28 4B SFT V2

- 本地 checkpoint：`ml/agentic/checkpoints/qwen3-4b-stage28-sft-abort-diverse-v2`
- adapter SHA-256：`41e504fb59f0622c26410aa432523498d9c5044eb07cb98cdb36ae7891a43894`

该模型是 4B 路线的正确 SFT 成果，但已不是当前学生主线。Stage28 DPO 没有超过它，所以未将 DPO 视为正确部署模型。

### 5. 教师：Qwen3-8B Base

云端 8B 教师服务健康，但它是通用底座而不是本项目训练出的专属权重，约 16GB。为避免把本地项目盘空间耗在可公开重建的重复底座上，本阶段只保留其评测、服务日志与模型身份，没有重复下载 8B 权重。需要离线复现完整双模型路由时再单独同步即可。

### 6. 明确拒绝：Stage35 DPO

Stage35 三组 20-step DPO smoke 的离线偏好准确率虽然都是 100%，但三组生成门都在同一冻结案例输出两次 `abort`。这证明“偏好分数变好”没有转化为“生成能正确停止”，所以正式结论是拒绝启动完整 DPO、拒绝晋级所有 Stage35 smoke。训练与失败日志已归档，权重不作为部署成果保存。

- Stage36 目前只通过了合成冻结集和 5% Shadow 晋级条件，下一步仍需真实用户 Shadow 数据验证。
