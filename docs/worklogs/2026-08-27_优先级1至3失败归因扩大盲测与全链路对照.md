# 2026-08-27 优先级1至3：失败归因、扩大盲测与全链路对照

## 1. 本轮目标

按照以下优先级继续优化 TravelAgent：

1. 解释原128条盲测中 SFT 与 GRPO 共同失败的10条轨迹。
2. 扩大独立盲测，验证 RL 收益能否泛化。
3. 补齐纯 Agent、可验证规划和 GRPO 恢复策略的全链路证据。

本轮最终采用更严格的新协议作为主结论，不为了保留更大的旧指标而忽略评测夹具问题。

## 2. 优先级1：10条共同失败的根因

自动归因与逐条轨迹检查发现：

- 7条属于旧快照合同误杀。模型在兴趣词之外附带了可信城市或日期，真实搜索服务可以处理，但冻结快照要求关键词逐字相同，导致任务还没有观察到预期工具错误就被判为 `SNAPSHOT_ARGUMENT_MISMATCH`。
- 3条属于真实模型/解码问题。模型生成了 `max_items`、`maxItems`、`title`、`type` 等未声明字段，被策略参数模型拒绝为 `POLICY_ARGUMENT_INVALID`。

因此，不能把全部10条继续当作困难训练样本：前7条需要修评测环境，后3条才应该通过模型训练或解码协议解决。

### 已实施修复

1. 新增 `analyze_stage3_paired_failures.py`，分别统计共同失败、GRPO单独改善和反向退化，并要求对快照不匹配先完成人工语义归属。
2. 为冻结搜索快照新增 `context_tolerant_keywords` 合同，只允许忽略数据中明确声明的城市和日期；任意新增“购物”等偏好仍然判错，避免为了抬指标放宽验证器。
3. 新增 `AGENTIC_LOCAL_STRUCTURED_DECODING` 配置，生产本地策略可以启用 `qwen_tool_envelope`，按当前状态允许的工具 JSON Schema 约束生成。
4. 保留原始v1报告，不回写成功标签；修复后重新冻结v2数据集。

相关环境、集成、数据生成、失败归因和全链路报告共27个相关测试用例已在云端通过；本地 Ruff 与语法检查通过。

| 指标 | SFT | GRPO v11 | 变化 |
|---|---:|---:|---:|
| 成功数 | 430/448 | 440/448 | +10 |
| 成功率 | 95.98% | 98.21% | **+2.23pp** |
| 失败数 | 18 | 8 | -10 |
| 失败率相对变化 | － | － | **-55.56%** |
| cross-tool | 97.32% | 99.55% | +2.23pp |
| search-only | 94.64% | 96.88% | +2.23pp |

成对结果为GRPO单独成功10条、SFT单独成功0条、共同成功430条、共同失败8条。精确McNemar双侧检验 `p=0.001953`；按任务聚类bootstrap的95%置信区间为 `[+0.89, +3.57]pp`，不包含0。预设门禁全部通过。

10条GRPO单独改善中，8条来自原生工具参数Schema合法性改善，2条来自搜索关键词合同遵循改善；没有发现反向退化。这说明该轮GRPO最明确的收益是提高原生工具调用与失败恢复的稳定性，不应包装成通用复杂规划推理提升。

### 3.4 约束解码系统smoke

在另外16个不与v2原生主评测重合的任务上，启用 `qwen_tool_envelope`：

- SFT：64/64成功。
- GRPO：64/64成功。
- 两组非法动作、参数错误、空动作均为0。

该实验不能用来宣称RL提升，因为两组都达到100%；它证明部署约束能够消除模型偶发的Schema错误。生产推荐是“GRPO提高原生策略鲁棒性 + 状态级Schema约束兜底”。

## 4. 优先级3：全链路两轴对照

没有把不同测试集的成功率伪装成一个三臂排名，而是采用两个正交的同题配对实验。

### 4.1 规划架构轴：为什么使用CP-SAT

同一 DeepSeek v4 Flash、同一30个冻结任务：

| 指标 | 纯 Agent直接编排 | Agent + CP-SAT + Verifier |
|---|---:|---:|
| 硬约束通过 | 1/30（3.33%） | 29/30（96.67%） |
| 平均Token/任务 | 28,552.13 | 488.10 |
| 平均模型调用 | 5.50 | 1.00 |

可验证规划将平均Token降低98.29%，并避免模型直接安排路线时产生超时段、交通间隔不足和营业时间冲突。这里证明的是CP-SAT/Verifier的架构价值。

仓库真实 `run_agent_branch` 在同30个普通可解任务上达到30/30硬通过，平均559.5 Token、1次模型决策和13次工具调用。普通任务只需要一次模型委派；失败恢复任务则由上面的多轮恢复集单独评测。

### 4.2 后训练恢复轴：为什么使用GRPO

在相同Qwen3-4B、相同v2恢复任务和相同随机种子下，仅更换SFT/GRPO适配器，成功必须完成Agent Loop、到达求解器并通过确定性Verifier。最终得到 `95.98% → 98.21%` 的显著提升。

因此完整架构的技术分工为：

- Agent Loop：读取状态、选择工具、消费反馈并继续/停止。
- CP-SAT + Verifier：保证预算、时间、营业时间和路线等硬约束。
- GRPO：提高原生工具参数合法性和失败后的恢复稳定性。
- 状态级约束解码：作为服务层合法性兜底，不替代模型能力评测。

## 5. 最终可用结论

建议简历使用清洗后的主指标：

> 面向旅行Agent工具失败恢复，构建状态约束动作空间、可执行Verifier奖励与GRPO后训练；修复冻结快照参数合同并建立无泄漏盲测，在448条配对恢复轨迹上将Qwen3-4B成功率由95.98%提升至98.21%（+2.23pp，失败率相对下降55.56%，McNemar p=0.00195），10条轨迹改善且0条反向退化；同时通过状态级工具Schema约束将独立系统smoke提升至64/64无非法调用。

可同时补充CP-SAT架构结果：

> 设计Agent Loop与CP-SAT/Verifier协同规划链路，在30个同题任务上将硬约束通过率由纯Agent的3.33%提升至96.67%，平均Token由28,552降至488（-98.29%）。

## 6. 当前边界与后续建议

1. 最终RL结论是“工具失败恢复轨迹/原生工具调用稳定性”，不是整个旅行产品线上成功率。
2. v2主评测为112个任务、448条轨迹，已通过统计门禁；剩余16个测试任务用于约束解码smoke，未混入原生主评测。
3. 当前不建议继续盲目训练v12。剩余8条共同失败中包含3条Schema违规和5条关键词合同不一致，生产服务可由约束解码兜底；只有积累新的真实语义失败簇后才值得继续GRPO。
4. 下一步若面向上线，应做真实Shadow/A-B测试，记录任务完成率、人工接管率、P95延迟和每成功任务成本。
