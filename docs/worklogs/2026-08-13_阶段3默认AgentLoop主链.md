# 阶段 3：默认 Agent Loop 主链与真实闭环

日期：2026-08-13  
状态：已完成开发与验收，按用户要求暂不提交代码

## 阶段目标

在 API 大模型条件下，让 Long-Horizon Agent Loop 成为默认规划主链；模型只负责受约束的策略选择，控制器持有事实、状态迁移和完成权。真实链路必须能从完整需求走到可验证草案、人工确认和行程保存，异常时允许安全回退到确定性工作流。

## 完成的架构改造

1. 默认主链改为 `agent`，保留确定性工作流回退。
2. 引入 Controller-First 决策边界：能力检查、天气、POI 详情、路线矩阵、求解、校验、草案和确认均由控制器推进；模型只在候选搜索策略等允许节点中决策。
3. 每个动作使用白名单 Schema、工具预算、求解预算、Token/耗时账本、稳定错误码和版本化事实/产物。
4. Agent 工具接入真实本地 PostgreSQL、AMap、天气、路线矩阵、VRP 求解器和程序化 Validator。
5. 候选供给分层为本地规范库 → AMap → 原搜索技能，空结果不再伪装成成功证据。
6. 候选供给保持宽召回，兴趣偏好通过确定性相关度打分进入求解，而不是由模型随意过滤。
7. `travel_dates` 投影为 Agent 的 `start_date/end_date`；完整用户画像传递到输出文案层。
8. 新请求改变日期、目的地、预算或偏好时创建新的 Goal Version/Plan Version/Trajectory，旧事实和旧产物不能进入新一轮求解。
9. Writer 只装饰主题、推荐语和标签，最终 Markdown 从结构化行程确定性渲染；时间、价格、日期、地点等事实不可被 LLM 修改。
10. 增加画像语义守卫：没有儿童/老人时，文案禁止虚构亲子或长辈同行卖点。
11. 行程确认只关闭真正处于 `awaiting_confirmation` 的 Agent Ledger，工作流回退草案不会错误关闭失败 episode。
12. 前端聊天、预览和行程有状态面板收敛为单实例，避免桌面/移动端重复挂载。
13. 新建会话采用会话代际（epoch）隔离；旧异步请求的创建、重连和发送结果都会失效，避免同一消息同时发往旧会话和新会话。

## 过程中发现的问题、根因与解决方式

### 1. API Policy 越权复制控制器参数

- 现象：JSON Policy 返回 `city` 等控制器字段，被 Schema 拒绝。
- 根因：策略接口同时承担“选择动作”和“复制可信事实”。
- 解决：策略 Schema 只暴露允许选择的少量参数；目的地、约束、候选、矩阵和行程由 Executor 从 Ledger/Artifact 注入。

### 2. Native Tool 协议一次返回多个工具调用

- 现象：模型一次生成多个 tool call，破坏每步一个状态迁移的循环语义。
- 解决：默认使用结构化 JSON Action 协议，并保留 Native Tool 适配作为可选实验路径。

### 3. 工具预算在必需步骤前耗尽

- 根因：POI 详情逐个调用，没有为矩阵、求解和验证预留预算。
- 解决：默认预算调整为 16；详情最多 8 个，并始终为 3 个必需调用预留额度。

### 4. POI 详情重复或实体错配

- 现象：不同候选取回同一个实体详情，仍被当作有效事实。
- 解决：详情工具做规范化精确实体匹配；Executor 再做第二层 requested/actual identity 校验，错配产生稳定错误码并允许重试。

### 5. 餐饮缺失仍然硬校验通过

- 根因：求解候选混入餐厅但 Validator 没有约束餐次结构。
- 解决：景点求解与餐厅供给分离；求解后按路线注入餐饮；Validator 校验每日餐次数、连续餐饮和餐饮密度。

### 6. AMap 分类与供给失衡

- 现象：餐饮、住宿被误分为 attraction；带偏好关键词的单一查询又可能只返回餐厅。
- 根因：只读取 AMap 类型层级第一段，并把兴趣过滤和候选供给绑定。
- 解决：按完整类型层级分类；景点和餐厅分渠道查询；偏好只用于排序，不用于截断整个候选供给。

### 7. LLM 输出改写价格、日期或用户身份

- 现象：文案调用修改票价；无儿童历史文化用户被写成“适合带孩子”。
- 根因：事实保护只覆盖字段突变，没有覆盖语义声明；输出节点也没有传递完整画像。
- 解决：最终文本由结构化事实确定性渲染；完整画像进入 Writer；增加同行人群语义冲突守卫和模板回退。

### 8. 历史偏好未真正影响求解

- 现象：历史文化偏好仍可能把南京欢乐谷排在首位。
- 根因：本地/地图评分只表达热度，兴趣只存在于提示词，没有进入 Solver score。
- 解决：建立可解释的主题词簇相关度，在不减少候选供给的前提下重排并修正候选分数。

### 9. 目标修改后复用旧日期产物

- 现象：方案标题显示 2027 年，但内部逐日日期来自 2026 年旧行程。
- 根因：`initialize_agent_ledger` 看到已有 Ledger 就直接恢复，没有比较新旧目标。
- 解决：比较投影后的硬约束、软偏好和缺失信息；有实质变化则递增 Goal/Plan Version，创建新轨迹和新预算，旧 facts/artifacts 不可见。

### 10. 新建会话异步竞态

- 现象：同一完整需求同时 POST 到旧 conversation 和刚创建的新 conversation，界面长期 loading。
- 根因：页面先 `clear()` 再异步 `reconnect()`；旧 bootstrap/SSE 和用户发送并发运行，而且发送前等待长期 SSE。
- 解决：把清理、创建、切换封装为单一 awaitable 操作；新建期间禁用按钮；使用 conversation epoch 让旧异步结果失效；SSE 连接后台启动，消息通过明确 conversation ID 立即提交。

### 11. 响应式界面重复挂载有状态组件

- 现象：DOM 中出现两个确认按钮，局部状态和 effect 存在双份实例。
- 根因：桌面区和移动区分别渲染了 ChatPanel/ItineraryPanel。
- 解决：有状态主面板只挂载一次，通过响应式 class 调整顺序与显示。
