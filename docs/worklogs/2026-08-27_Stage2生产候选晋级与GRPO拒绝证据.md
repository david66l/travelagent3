# 2026-08-27 Stage 2 生产候选晋级与 GRPO 拒绝证据

## 1. 本阶段结论

本阶段将冻结 Agent Loop 基线从 `117/128（91.41%）` 提升到同协议压力测试的
`123/128（96.09%）`，其中 necessary-abort 从 `21/32` 提升到 `28/32`。

针对离散工具路由采用低方差生产解码（temperature=`0.2`）后，最终 SFT v7 候选在：

- 冻结集 seed 211：`128/128`；
- 冻结集额外 seed 977：`128/128`；
- 与 v4 训练/验证请求严格去重的 64 任务盲测：`256/256`；
- 三轮评测均为零非法动作、零空动作、零输出格式错误和零参数错误。

候选状态为 `offline_qualified`。这表示离线证据通过，不等价于已经完成真实流量
canary 或线上 SLA 验证。

## 2. 为什么前一版效果上不去

独立审计确认了三个主要问题：

1. necessary-abort 在旧 GRPO 语料中只占 `128/1024（12.5%）`，训练信号被简单任务稀释；
2. 风险终止样本高度模板化，模型容易记住“请直接终止”等标签泄漏措辞；
3. 旧 GRPO 只训练 20 步、约 `0.0195 epoch`，线性学习率迅速衰减，KL 和 clip ratio
   说明策略几乎没有移动。

Reward 本身不是主要瓶颈：v4 审计的正确/相反动作矩阵 `912/912` 通过，平均奖励间隔
约 `1.139`。问题主要在数据分布、决策模板和有效更新信号。

## 3. SFT 修复

### 3.1 数据

- 构建 `decision-boundary-grpo-corpus.v4`；
- unsafe 扩展为 8 类风险原因，missing-tool 扩展为 4 类；
- 加入“风险由我承担、仍按原要求规划”等对抗后缀，不再直接告诉模型答案；
- 构建平衡 SFT bridge：train `800`、validation `84`、test `84`；
- 训练动作分布：`propose_tradeoff=332`、`abort=332`、`search=231`、`ask=73`；
- prompt 唯一数 `968`，split overlap 为 0。

### 3.2 训练

从 SFT v6 继续训练 SFT v7：

- learning rate：`2e-6`；
- max steps：`50`；
- action-token weight：`6`；
- 对动作名 token 额外加权，让 `abort` 与 `propose_tradeoff` 的监督信号不会被长 JSON
  和解释文本稀释。

### 3.3 同协议压力结果

| 评测 | 总体 | 澄清 | 提示注入/搜索 | 可继续规划 | 必要终止 |
|---|---:|---:|---:|---:|---:|
| 旧冠军 SFT bridge v5，temp 0.8，seed 211 | 117/128 | 32/32 | 32/32 | 32/32 | 21/32 |
| SFT v7，temp 0.8，seed 211 | 123/128 | 32/32 | 31/32 | 32/32 | 28/32 |

同协议总体提升 `6/128 = 4.69` 个百分点；necessary-abort 提升
`7/32 = 21.88` 个百分点。高温压力下提示注入出现 1 次随机回退，因此该配置不作为
生产推理配置。

在更难的 v4 对抗 abort 子集上，旧冠军为 `58/96`，SFT v7 为 `82/96`，提升
`24/96 = 25` 个百分点。

## 4. 生产解码门禁

工具路由是离散决策，不需要文案生成式的高随机性。将 policy temperature 固定为
`0.2` 后，冻结集两个 seed 均为：

| 类别 | seed 211 | seed 977 |
|---|---:|---:|
| semantic clarification | 32/32 | 32/32 |
| terminal injection/search | 32/32 | 32/32 |
| actionable tradeoff | 32/32 | 32/32 |
| necessary abort | 32/32 | 32/32 |
| 总体 | 128/128 | 128/128 |

模型训练收益与推理配置收益必须分开表述：`123/128` 是同温度模型压力对比；连续两个
`128/128` 是 SFT v7 加生产解码配置的系统级结果。

## 5. 盲测

新建 `stage2-decision-boundary-blind-holdout-v2`：

- 64 个任务，每类 16 个；
- 与 v4 train 和 validation 的 task id、source request 均零重合；
- 风险原因包含边境关闭、火山空域、坍塌、海啸、武装冲突、雪崩、渡轮停航和水源污染；
- 只在生产候选确定后执行一次。

结果为 `256/256`，四类各 `64/64`，所有协议错误计数均为 0。

## 6. GRPO 对照与拒绝结论

### 6.1 在线可学习性路由

SFT v7 在 16 个未见 unsafe 任务上以 temperature=`1.2`、group size=`8` 生成 128 条
轨迹：

- 成功 `115/128`；
- `evaluation=11`；
- `grpo_update=5`；
- 没有全错任务和非法动作。

只有 5 个“同题有对有错”的 task 被送入 GRPO，避免全对/全错组浪费更新。

### 6.2 trajectory-level B0

配置：constant LR=`1e-6`、10 steps、group size=`8`、temperature=`1.2`。

- step 5：unsafe actionable `32/32`，unsafe abort `25/32`；
- step 10：unsafe actionable `32/32`，unsafe abort `25/32`；
- 与 SFT v7 完全持平，判定 `rejected_no_behavior_gain`。

### 6.3 validity-gated turn-credit R1

保持数据、步数、学习率和随机种子不变，只替换信用分配方式。训练结束后证据门禁自动
拒绝：

- trajectories：`80`；
- model turns：`950`；
- invalid model turns：`885`；
- effective nonzero credited turns：`0`；
- comparable turn buckets：`0`；
- invalid action positive credit count：`0`；
- gate errors：`NO_EFFECTIVE_NONZERO_TRAIN_TURN_CREDIT`、
  `NO_COMPARABLE_TURN_BUCKETS`。

结论：这批任务本质上是单步终止边界，不适合作为 turn-credit R1 的训练载体。R1 应用于
真正多轮、每轮都有可验证状态推进的搜索/恢复任务。不得宣称本阶段 RL 提升了准确率，
也不得用被拒绝 checkpoint 替换 SFT v7。

## 10. 边界与下一步

当前证据证明的是固定 snapshot 环境中的工具决策能力，不代表真实用户流量、实时地图
质量、外部 API 波动、端到端延迟和商业转化已经达标。上线前仍应完成 shadow/canary：

1. 在真实请求上只记录不执行的 shadow policy 决策；
2. 监控 abort 率、人工改判率、工具错误率、P95 延迟和 fallback 率；
3. 达到最小样本量后再小流量 canary；
4. 保留旧模型一键回滚。
