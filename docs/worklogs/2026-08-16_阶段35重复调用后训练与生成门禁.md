修复 Stage34 暴露的单条重复工具调用：模型在只允许 `abort` 时一次输出两个完全相同的
`abort`。本阶段要求同时体现数据构造、偏好证据、训练 preflight、smoke、离线 margin 和
冻结生成回归，不能只用训练 loss 宣布成功。

- 排除前一专项数据的 240 个上下文，新增上下文 240；
- 冻结评测精确和近重复仍为 0。

- 原冻结标签正确 148/150；

专项-only 和动作隔离 smoke 随后都直接复测同一目标例，输出 token 数均为 76，依然解析为

## 五、关键结论

三轮 smoke 的 DPO eval reward accuracy 都是 100%，离线 margin 也能上升，但生成故障完全
不变。这证明当前任务中“偏好验证通过”不能替代“真实解码行为通过”。如果只汇报 loss、reward
accuracy 或 margin，会得到错误的晋级结论。

因此：

- 不启动正式 Stage35 DPO；
- 不晋级三套 smoke checkpoint；
- 不修改当前生产冠军和 Shadow 默认配置；
- 下一方法转为首个工具调用结束边界加权 SFT，或服务端单工具调用解码约束；
- 新方法必须先通过 `ds-065`，再跑完整 150 条冻结回归和 Agent Shadow。
