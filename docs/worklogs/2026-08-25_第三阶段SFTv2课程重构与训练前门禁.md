# 2026-08-25 第三阶段：SFT v2 课程重构与训练前门禁

## 目标

解释短程 SFT 从 50% 提升到 78.125%、完整一轮却退化回 50% 的原因，
并在不修改模型权重的前提下完成下一轮训练的数据和工程准备。

本地旧归档只有 checkpoint、训练日志和评测轨迹，没有实际用于训练的
5,688 条 SFT 决策。已从用户授权的训练机只读复制：

`ml/agentic/datasets/stage2-policy-driven-sft-v1/sft-v2`

本地归档：

`artifacts/remote-backups/stage2-sft-dataset-20260825`

云端未写入或删除任何文件。

## 数据审计结论

原始数据 `sft-a2dcdf2d0f5c63e1`：

- 768/768 个 episode 接受，导出 5,688 个决策；
- 4,920 个是固定 Controller/DAG 迁移，占 86.50%；
- 搜索、恢复、澄清、权衡合计仅 768 个，占 13.50%；
- 4,305 个样本只有一个可选动作，占 75.69%；
- 2,460 个样本既只有一个动作，又要求空参数，占 43.25%；
- 615 个 `get_poi_detail` 样本全部向模型暴露 `candidate_poi_ids`，
  但该动作的 policy schema 是 `EmptyArguments`；
- 目标参数本身全部合法，无精确重复、无 scenario split 泄漏。

因此问题不是传统意义上的“脏数据”，而是课程权重和模型可见表示错误：
模型大量模仿不需要判断的流程，又被显眼的控制器字段诱导违反空参数协议。

## 实施改动

### 1. 在线上下文最小化

`policy_prompt_payload()` 不再向模型暴露 Controller/Verifier 专用的：

- `success_criteria`；
- `required_facts`；
- `artifact_refs`；
- `verifier_evidence_refs`；
- DAG 依赖和失效字段。

当动作空间只有一个动作且 schema 没有参数时，进一步移除原始请求、
约束、事实和 artifact payload，只保留动作、子任务、步数预算和
`controller_hydrates_arguments=true`。

### 2. 数据审计门禁

新增 `scripts/audit_sft_curriculum.py` 和
`backend/src/agentic/sft_curriculum.py`，自动检查：

- action/action-family 分布；
- singleton 和 singleton-empty 比例；
- 目标参数是否违反 JSON schema；
- 上下文是否包含会诱导复制的 Controller 字段；
- 精确重复、模板集中度和 split 泄漏；
- 上下文长度分布。

### 3. SFT v2 课程

新增 `scripts/build_sft_v2_curriculum.py`，生成：

`ml/agentic/datasets/stage2-sft-v2-curriculum-v1`

训练集从 3,928 条调整到 1,176 条：

- 搜索/恢复训练样本 425 条全部保留；
- 澄清 51 条、权衡 52 条全部保留；
- 固定动作只保留限量 replay；
- `get_poi_detail` 保留 128 条原始 Controller-rich 抗干扰样本；
- 空参数最小上下文按模型实际输入去重；
- 真正决策样本占比从 13.50% 提升到 44.90%；
- 保留原始 validation/test 作为字段复制挑战集，不参与训练；
- 训练集无精确模型输入重复，split 无泄漏。

错误动作没有作为 SFT target 使用；后续应进入 DPO/NAT-style 负例或
Verifier reward 流程。

### 4. 训练脚本安全参数

`train_sft.py` 新增：

- smoke 期间可选 eval；
- logging/eval/save cadence；
- warmup ratio；
- gradient clipping；
- checkpoint cadence 和优化安全参数写入 training report。

训练矩阵已保存到：

`ml/agentic/training/stage2_sft_v2_experiment_matrix.json`

## GPU 训练与对照

在同一张 RTX 4090 上，从当时的最佳 SFT adapter 分叉，运行
`3e-6`、`8e-6`、`1e-5` 三组独立 60-step QLoRA，每 10 steps
保存 checkpoint，没有覆盖线上模型。

| 学习率 | train loss | validation loss | 原始脏上下文协议集 |
|---|---:|---:|---:|
| 原 SFT 基线 | - | - | 46/48（95.833%） |
| `3e-6` | 0.10679 | 0.09300 | 48/48（100%） |
| `8e-6` | 0.07592 | 0.08283 | 48/48（100%） |
| `1e-5` | 0.06750 | 0.08159 | 48/48（100%） |

基线两次失败都是本应 `finish` 却多问了一次用户；三个 SFT v2
候选均消除了该随机偏移。这个 2/48 改善样本量较小，只能作为
抗干扰性证据，不单独声称已获得稳定的泛化提升。

### 架构增益与 SFT 增益拆分

在同一 checkpoint、同一独立 holdout、同一 `seed=42`、同一温度
`0.8` 和每题 4 次采样下：

- 旧上下文表示：25/32（78.125%），7 次失败全是未知参数错误；
- 原 SFT 模型 + 新上下文表示：32/32（100%），参数错误为 0；
- `3e-6` SFT v2 + 新上下文表示：32/32（100%），参数错误为 0。
- `8e-6` SFT v2 + 新上下文表示：32/32（100%），参数错误为 0；
- `1e-5` SFT v2 + 新上下文表示：32/32（100%），参数错误为 0。

因此已确认的主收益是架构修复带来的 **+21.875 个百分点**；
在新架构已经达到满分的这组 Agent Loop 上，SFT v2 与基线打平，
它的附加收益体现在保留原始脏上下文时的协议鲁棒性。

本地归档 `8e-6` 为候选 adapter，原始训练、协议筛选和全链路报告均已
复制到 `ml/agentic/reports/stage2-sft-v2-*`。候选不自动覆盖当前默认
模型，原因是在新架构全链路上只能证明不退化，尚未证明成功率超过基线。

### 晋级规则

本轮仍按下列顺序选模型，不用 validation loss 单独晋级：

1. 参数合法率；
2. 全轨迹成功率；
3. 最差动作族成功率；
4. 模型延迟。

目标门槛：参数合法率至少 99%，全轨迹成功率至少 90%，最差动作族
至少 85%。不得用 validation loss 单独晋级。

## 第四阶段：困难集复测

原 32 条 holdout 在新架构下已全部满分，无法继续区分模型。因此新建
`stage2-hard-holdout-v2`，使用 30000 以后的全新 generator index，
覆盖精确兴趣搜索、观测条件恢复和跨工具多故障。

- 64 个决策样本、2 次配对采样：原模型搜索/恢复精确参数 60/64，
  `8e-6` 为 64/64；
- 8 个全新任务、每题 4 次配对采样：原模型 29/32（90.625%），
  `8e-6` 为 32/32（100%），提升 9.375 个百分点；
- 原模型 1 次快照参数不匹配、1 次 policy 参数输出错误，候选均为 0；
- 单次模型请求平均延迟为 1,636 ms 对 1,628 ms，基本持平。

一道“同子任务第三次重试”题因超过生产 Scheduler 的
`max_attempts=2` 被判定为不可完成，已从模型正确率中排除，只作为架构边界证据。

结论：`8e-6` 从“鲁棒性候选”晋级为后续困难数据、DPO/GRPO 实验的
离线基线；由于全链路仍只有 32 条 rollout，尚不自动覆盖生产默认模型。
