# 阶段 19：推理剖析与蒸馏评测基线

日期：2026-08-14

## 1. 目标

在进入教师轨迹生成和 Qwen3-4B 蒸馏前，先建立可以解释“为什么慢”的推理观测，并冻结不允许进入梯度更新的评测集。本阶段不启动正式 SFT、偏好优化或 GRPO。

## 2. 推理观测契约

新增 `policy-inference-metrics.v1`，每个模型请求可以记录：

- model、backend、task type 和 thinking mode；
- prompt / completion / cached prompt Token；
- request latency；
- 流式 HTTP 场景的 TTFT 和近似 TPOT；
- finish reason。

指标可以附在 `PolicyAction` 并随生产 Agent Episode 保存。TRL 快照环境仍只接收工具动作，审计脚本通过旁路重新关联推理证据，避免把观测字段混入训练工具契约。

由于 `PolicyAction` 增加了推理指标字段，新写入轨迹的 Schema 升级为 `agent-episode.v2`。回放器对历史 `agent-episode.v1` 仍按旧字段集合校验内容哈希，避免把新增的空字段误判为历史数据遭到篡改。

新增流式 `benchmark_vllm_http.py`，使用 OpenAI-compatible SSE 接口测量 TTFT、TPOT、吞吐、工具动作合法性和 thinking 泄漏。API key 只从环境变量读取，不写入报告。

## 3. 阶段 18 延迟回归拆解

使用相同 8 个任务、每任务 4 次、相同 seed、NF4、`qwen_tool_envelope` 和最多两轮工具调用，重新配对评测 Qwen3-8B zero-shot 与 16-step adapter。

| 指标 | 8B zero-shot | smoke16 | 变化 |
|---|---:|---:|---:|
| successful rollouts | 32 / 32 | 32 / 32 | 无变化 |
| 模型请求数 | 40 | 40 | 0% |
| prompt Token | 27984 | 27984 | 0% |
| completion Token | 1340 | 1168 | -12.84% |
| completion / request | 33.5 | 29.2 | -12.84% |
| request mean | 1336.874 ms | 1988.393 ms | +48.74% |
| rollout mean | 1723.160 ms | 2532.040 ms | +46.94% |
| rollout P95 | 2319.519 ms | 3592.858 ms | +54.90% |

结论：smoke16 没有增加输出长度或 Agent 轮数。阶段 18 的主要延迟回归来自当前 `NF4 base + 在线 PEFT adapter + 约束解码` 请求计算路径。该路径不能代表合并权重或 vLLM server-side LoRA 的最终速度；后续部署对照必须单独测试。

## 5. vLLM HTTP canary

在 AutoDL RTX 4090 24GB 上创建独立环境，未改动训练环境。最终可复现版本为 vLLM 0.9.2、Torch 2.7.0+cu126、Transformers 4.53.2 和 OpenAI SDK 1.90.0。安装器最初解析到 Transformers 5.15.0，vLLM CLI 因重复注册 `aimv2` 配置而失败；在隔离环境内固定到 4.53.2 后服务正常启动，原始诊断和修复日志均已保存。

服务配置：Qwen3-8B FP16、`max_model_len=4096`、`gpu_memory_utilization=0.85`、`max_num_seqs=8`、前缀缓存、自动工具选择和 Hermes parser。请求使用流式 SSE、`max_tokens=192`、temperature 0.1，并通过 `chat_template_kwargs.enable_thinking=false` 关闭 thinking。

| profile | 成功请求 | mean latency | P95 latency | mean TTFT | P95 TTFT | mean TPOT | mean completion Token | throughput |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| regular c1 | 100 / 100 | 858.033 ms | 1463.726 ms | 337.242 ms | 352.060 ms | 10.956 ms | 45.51 | 1.165 req/s |
| hard c1 | 100 / 100 | 860.590 ms | 1419.809 ms | 334.470 ms | 353.749 ms | 10.977 ms | 45.73 | 1.162 req/s |
| adversarial c1 | 100 / 100 | 1017.480 ms | 1470.182 ms | 343.661 ms | 354.444 ms | 11.631 ms | 54.33 | 0.983 req/s |
| regular c4 | 100 / 100 | 1273.746 ms | 3262.929 ms | 577.823 ms | 2087.655 ms | 14.633 ms | 45.43 | 3.043 req/s |

四组共 400 个正式请求均无 HTTP 错误、动作不匹配或 reasoning 泄漏。另对 10 个常规任务重复三轮：各轮平均延迟为 839.490 / 831.784 / 829.689 ms，变异系数 0.506%，极差相对均值 1.176%。

并发 4 相对并发 1 吞吐提升 161.20%，但平均延迟增加 48.45%，P95 增加 122.92% 并超过 3 秒，因此不能把 `max_num_seqs=8` 直接理解为线上应放行 8 个并发；后续服务路由和负载门禁要按尾延迟约束设置。对抗集延迟增加主要对应更长输出，而 TTFT 基本稳定。

这些成功率只证明冻结单步工具决策在受限 Schema 下正确，不能替代完整 Agent 任务成功率。当前 vLLM usage 未暴露缓存命中 Token，报告中的 cached Token 为 0，不能据此断言前缀缓存没有生效。
