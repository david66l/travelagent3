# 阶段 25：部署演示、路由可观察性与项目表达收口

## 目标

把阶段 19～24 已经完成的后训练和推理实验变成可展示、可复查的产品闭环。演示不能只说“系统会自动选模型”，而要让轨迹、API 和 App 都能回答：

- 为什么这一步交给 4B 或 8B；
- 最初请求的模型和实际执行的模型是否一致；
- 学生失败后是否只升级了一次教师；
- 本轮用了多少生成 Token 和模型时间；
- 展示数字来自哪份冻结报告。

## 一、动作级路由审计

新增 `PolicyRouteTrace`，随 `PolicyAction` 一起写入可回放 episode。每个真正由模型决定的动作现在记录：

- `requested_target`：路由最初选择 student 或 teacher；
- `executed_target`：最终实际执行 student 或 teacher；
- `family`：clarification / search / recovery / tradeoff / complex；
- `reason`：稳定、可展示的路由原因；
- `fallback_used` 与 `fallback_error_code`；
- 原有 `inference_metrics` 中的模型名、Token、TTFT、TPOT 和请求延迟。

学生模型异常时只升级一次教师。教师异常不被吞掉，继续进入既有 deterministic fallback / guard。错误展示只使用稳定错误码，不把异常文本或敏感输入暴露给前端。

## 二、后端汇总与 App 展示

`summarize_policy_routing()` 从 episode 生成 `agent-policy-routing-summary.v1`：

- 4B / 8B 调用计数；
- 按任务族统计；
- 学生升级次数；
- 本轮模型生成 Token；
- 本轮模型请求延迟；
- 每一步动作、路由原因和模型证据。

该汇总被加入 Agent 分支 patch，并通过 partial、final、awaiting-confirm 和 state-restored SSE 路径传到客户端。App 顶栏新增“智能路由”胶囊：

```text
智能路由 · 4B 8 · 8B 1 · 升级 0
```

鼠标悬停可查看本轮 Token 和模型耗时。新对话会清空旧路由状态，避免跨会话误显示。

## 三、可复现 Showcase

新增 `scripts/build_stage25_showcase.py`。脚本不手抄数字，而是读取阶段 24 总报告和阶段 23 冻结 `runs.jsonl`，生成：

- `ml/agentic/reports/stage25-showcase-v1/showcase.json`；
- `ml/agentic/reports/stage25-showcase-v1/SHOWCASE.md`。

Showcase 包含四个现场演示场景及对应的真实冻结成功样本：

| 场景 | 路由 | 实测动作 | Token | 模型延迟 |
|---|---|---|---:|---:|
| clarification | 4B student | ask_user | 35 | 464.362 ms |
| search | 4B student | search_pois | 21 | 279.086 ms |
| recovery | 4B student | search_pois | 21 | 257.563 ms |
| tradeoff | 8B teacher | propose_tradeoff | 79 | 1703.506 ms |

这些单例用于解释路由行为，不替代总体 benchmark。总体结果仍使用阶段 24 的 516 次严格决策和 172 个完整多轮任务。

## 四、部署配置

最终部署契约支持学生和教师独立端点：

```env
AGENTIC_POLICY_MODE=agent
AGENTIC_POLICY_BACKEND=api
AGENTIC_POLICY_PROTOCOL=native_tool
AGENTIC_POLICY_ROUTING_ENABLED=true
AGENTIC_STUDENT_POLICY_MODEL=travel-policy-qwen3-4b-dpo-scale150-cudagraph
AGENTIC_TEACHER_POLICY_MODEL=travel-policy-qwen3-8b-base
AGENTIC_STUDENT_BASE_URL=http://student-vllm:8000/v1
AGENTIC_TEACHER_BASE_URL=http://teacher-vllm:8000/v1
```

当前 4090 只有 24GB，不能把两个 FP16 服务稳定同时常驻在同一张卡。因此：

- 正式在线形态：学生和教师使用两个独立端点；
- 单卡演示形态：顺序启动并回放，明确标注不是同时在线延迟；
- 不把顺序回放结果伪装成同卡双模型生产吞吐。

## 五、最终项目表达

### 一句话版本

在生产型旅行 Agent 上完成 verifier-guided 数据构建、QLoRA 蒸馏 SFT、DPO 偏好优化、真实多轮 GRPO-B0、checkpoint 晋升门、4B/8B 安全路由和 vLLM 推理消融，并用冻结任务、可回放轨迹与 App 可观察性证明质量和效率。

### 可量化版本

- Qwen3 最终路由系统：严格工具决策 516/516，完整多轮任务 172/172；
- 8B 仅处理 2.33% 的任务；相比全量 8B，生成 Token -28.52%，模型请求延迟 -47.87%；
- DPO 在完全相同的 172 个偏好对上将平均 log-prob margin 提高 22.60%；
- Qwen2.5-3B 多轮 GRPO-B0 在同协议下将 SFT 成功率从 80.47% 提高到 82.81%；
- CUDA Graph 预热后平均延迟 -7.52%，P95 -9.71%，吞吐 +8.10%。

### 必须同时说明的边界

- 冻结集是 TravelAgent 工程 benchmark，不是公开排行榜；
- GRPO 是 trajectory-level B0，不宣称解决逐轮信用分配；
- 路由总体结果是顺序模型回放，不宣称单张 24GB GPU 双模型常驻；
- 模型延迟不含外部地图、天气等工具 API 时间。
