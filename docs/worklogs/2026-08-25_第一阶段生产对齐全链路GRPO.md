# 第一阶段：生产对齐的全链路 GRPO

日期：2026-08-25

## 目标

修复训练环境与线上默认架构不一致的问题：线上 `policy_driven` 让模型逐步选择工具，而旧 GRPO 环境会用控制器自动推进固定步骤，模型通常只看到搜索、澄清或权衡等少数决策。这种设置可以作为低成本基线，但不能证明模型学会了完整 Agent Loop。

## 本阶段完成内容

1. 新增生产对齐的 `TRLPolicyDrivenEnvironment`，向 TRL 暴露完整线上动作合同，并继续复用同一套 Scheduler、Agent Ledger、Executor、参数校验、Subtask Verifier、全局完成门和 Reward。
2. `TRLTravelEnvironment` 与正式 `TRL_ENVIRONMENT_FACTORIES` 默认切换为 `policy_driven`；旧的 `search / clarification / tradeoff` 窄环境保留为显式 `controller_first` 成本基线。
3. 正常信息完整快照已能跑通 9 次模型动作：`capability_check → get_weather → search_pois → get_poi_detail → get_route_matrix → solve_itinerary → validate_itinerary → compose_draft → finish`。
4. GRPO 样本改为 `system + 原始用户请求` 开局，由环境创建全新 Ledger；`assistant`、`tool` 或 teacher tool-call 前缀会被拒绝，避免把教师答案当成 rollout 起点。
5. 正式训练默认工具轮次由 2 提升到 12，其中 9 轮覆盖名义生产 DAG，额外 3 轮用于有界恢复；`policy_driven` 少于 9 轮会在训练前报错。
6. 默认 completion budget 提升到 16,384，静态安全下限提升到 8,192；动态预检改为累计完整 rollout 的全部工具结果和动作 token，不再只测一次工具往返。
7. rollout 审计现在逐轮保存执行模式、初始状态合同、allowed actions、decision cardinality、动作参数、工具结果、Verifier 结果和 turn reward。
8. 训练报告新增 `execution_mode`、`policy_decision_scope`、`rollout_initialization_contract` 与 `teacher_trajectory_prefix=false`，防止后续把两种执行协议的结果混在一起。

## 验证结果

- 全量 Agentic 单元测试：`288 passed`。
- Ruff：相关 Python 文件全部通过。
- 训练入口 `--help` 可正常加载，并显示 `policy_driven/controller_first`、12 轮与新预算参数。
- 本阶段未使用 GPU，也未生成或宣称新的 RL checkpoint；完成的是正式训练前的环境与证据合同修复。

## 第一阶段边界

本阶段证明“训练时确实可以让模型走完整生产 Agent Loop”，不证明 RL 效果已经提升。下一阶段需要先在冻结快照上做 rollout 可学性审计，统计完整轨迹成功率、截断率、组内 Reward 方差、各状态失败分布与单动作状态占比，再决定哪些样本进入 SFT 修复、GRPO-B0 或逐轮信用 R1 对照。
