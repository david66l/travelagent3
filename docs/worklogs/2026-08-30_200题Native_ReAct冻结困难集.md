# 2026-08-30 200题 Native ReAct 冻结困难集

## 目标

修复上一轮 GRPO 只有 6 个独立专项任务、23 个全链路任务的问题，建立能支持任务级统计的正式困难评测集。数据必须与生产 Native ReAct、CP-SAT 和 Verifier 合同兼容，同时禁止进入任何后训练语料。

## 完成内容

- 新增 `native_react_hard_benchmark.py`，确定性生成 200 个不同任务。
- 建立 10 个能力族、40 个语义簇和 20 个城市的分层矩阵。
- 按城市隔离 40 题开发集与 160 题最终测试集，城市重合为 0。
- 每道题保存期望意图字段、业务终态、必经动作/产物、修改约束和可选故障注入合同。
- 增加唯一任务、规范化文本、任务指纹、内部近重复、历史语料原文/近重复污染门禁。
- 生成文件和完整数据集均保存 SHA-256，并记录生成代码基线 Git SHA。
- 增加标签一致性测试，禁止把用户没有明确说出的预算、人数等字段写成必答标签。

## 代表性开发题

- 澄清：`9月中旬想出去玩2天，1个人，预算2600元，偏爱京味菜，帮我规划。`
- 时效信息：`北京2日游，出发前先查天气；如果下雨就多排室内场馆，预算2600元。`
- 约束冲突：`一个人去北京玩2天，总预算只有500元，故宫必须去，住宿交通吃饭都算在内。`
- 故障恢复：`去北京玩2天，预算2600元，想去故宫并体验京味菜；即使查询暂时失败也请给出可验证的处理结果。`
- 混合语言：`plz plan 北京 2天, budget 2600 RMB, MUST=故宫, no 颐和园，别太赶哈`

## 主张边界

200 行是不同的冻结统计任务，但由程序化组合生成，尚未完成独立人工双标。因此可以声称“200 个不同任务、20 城市、40 语义簇、通过训练污染审计”，不能声称“200 道独立人工评测题”。最终比较必须按任务统计，并对语义簇做 Cluster Bootstrap；同题多次采样不能当成更多独立题。
