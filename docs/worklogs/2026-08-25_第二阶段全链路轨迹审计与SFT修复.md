# 第二阶段：全链路轨迹审计与 SFT 修复

日期：2026-08-25

## 阶段目标

在正式 GRPO 前，用当前 Qwen3-4B DPO checkpoint 对生产对齐的 `policy_driven` Agent Loop 做可学性审计，区分环境/数据故障、模型协议错误、零方差评测锚点和真正适合 GRPO 的样本。

## 运行环境

- GPU：单卡 RTX 4090 24GB。
- 基模：Qwen3-4B，通过国内 ModelScope 下载到数据盘。
- 初始策略：`qwen3-4b-stage28-dpo-abort-diverse-v2` LoRA adapter。
- 推理与训练：NF4 double quant，BF16 compute。
- Python 包使用清华 PyPI 镜像，实验过程中设置 Hugging Face/Transformers offline，避免外部模型下载。

## 审计入口修复

旧 `scripts/audit_model_curriculum.py` 仍固定使用首轮动作白名单，并默认只运行两轮；即使环境已经切到 `policy_driven`，也无法正确测量九步生产 DAG。本阶段将审计循环改为：

1. 每轮从环境返回的 `policy_state.allowed_actions` 重建工具 schema；
2. `policy_driven` 至少允许 9 轮，默认 12 轮以覆盖恢复；
3. 报告写入 execution mode、完整动作范围、逐轮 task/action/allowed actions/Verifier/observation；
4. 初始 reset 显式校验 `system + 原始用户请求`，禁止 teacher trajectory prefix。

## 数据故障与修复

第一次 4×搜索 smoke 的四条轨迹都在 POI 详情阶段失败，Verifier 报 `POI_DETAIL_IDENTITY_MISMATCH`。这不是模型选错工具，而是旧 GRPO 快照与新批量详情执行器不一致：执行器只请求可规划景点，旧快照却按前八个混合候选保存详情，并且历史数据缺少 `expected_arguments`。

修复 `build_curriculum_case` 后，详情快照按与执行器相同的可规划景点集合生成，并补充三日行程回归测试。重新生成的 128 个案例全部通过生产 Loop、Replay 和 Reward Gate：108 个训练任务、20 个验证任务，Reward 范围 0.889125–0.976。

## 当前 4B 原生能力诊断

同一组 8 个任务，每类各 2 个、每个任务采样 4 条：

- Qwen tool-envelope 结构化解码：32/32 成功，但 8/8 任务 Reward 零方差，只能证明带工程护栏的系统执行稳定，不能证明模型原生合法率，也不能直接提供 GRPO 学习信号。
- 原生无约束解码：16/32 成功；澄清 8/8、冲突权衡 8/8，搜索与恢复 0/16。
- 16 个失败全部是 `search_pois` 参数错误：生成旧字段 `maxItems`，或把 `keywords` 生成为二维数组。参数错误率 50%，未知参数错误率 40.625%。
- 四个失败任务都是全失败、零方差，应先进入 SFT repair；此时直接 GRPO 的组内 advantage 全为 0。

## 全链路 SFT 数据

`generate_agentic_corpus.py` 新增显式 execution mode：

- `controller_first` 保留历史低成本基线；
- `policy_driven` 让教师策略拥有 production DAG 的每一个模型决策，输出完整 9–10 轮轨迹。

生成 768 条 verifier-approved 完整轨迹，再经 `SFTDatasetBuilder` 做 Replay、PII、参数、工具证据、终止状态和 split leakage 门控。发现并修复 `finish` 等待用户确认时被错误排除的问题；最终数据：

- 768/768 episode 接受，0 拒绝；
- 5,688 条 SFT 决策；
- train 3,928 / validation 568 / test 1,192；
- 所有样本都有且只有一个 Qwen 工具调用终止边界；
- 最大序列 1,493 Token，P95 1,353，2,048 上限内无截断；
- 77 个故意失败的首次恢复搜索动作被排除，不作为模仿目标。

## 20 步训练 Smoke

从原始 4B DPO adapter 继续 QLoRA，使用 128 条训练/32 条验证、20 步、LR 5e-5、gradient accumulation 4、termination token weight 2.0：

- 42.26 秒完成，约 2.11 秒/步；
- 前后两个十步窗口 loss：2.294 → 0.5558；
- train loss 1.4247，eval loss 0.1094；
- 无 OOM、NaN 或梯度爆炸，checkpoint、tokenizer、训练报告均成功保存。

同协议原生 8×4 复测：

- 成功率 16/32 → 24/32，即 50% → 75%，提升 25 个百分点；
- 参数错误率 50% → 21.875%；
- 未知参数错误率 40.625% → 21.875%；
- 5/8 个任务出现非零 Reward 方差并进入 `grpo_update`：两个恢复任务成功率均 3/4，两个搜索任务分别 1/4、2/4，一个冲突任务 3/4；
- 两个澄清任务保持 4/4，另一个冲突任务保持 4/4，作为 evaluation anchor。

该结果只证明训练方向和可学性门成立；20 步、小样本审计不作为正式泛化结论。

## 正式 1 Epoch SFT 与过拟合诊断

正式训练使用 3,928 个训练决策、gradient accumulation 16、LR 5e-5、termination token weight 2.0，共 246 个优化步：

- 训练耗时 2,218.46 秒，train loss 0.3497；
- 568 条同分布 validation 的 eval loss 为 1.33e-05；
- 5,688/5,688 条样本通过序列长度、工具边界和终止 Token 预检；
- 无 OOM、NaN 或训练中断。

但同协议原生 Agent Loop 复测只有 16/32（50%），与训练前相同；step-200 也是 16/32。搜索与恢复再次变为 0/16，失败主要是在本应为空的 `capability_check` 参数中生成类似 `{"$oid": "..."}` 的未知字段。说明同分布 eval loss 已失去模型选择价值，完整一轮训练造成协议记忆和行为塌缩，不能晋升该模型。

## 最终模型选择

保留独立的 20 步 SFT checkpoint 作为本阶段最佳候选：

- 第一批 8×4：24/32（75%）；
- offset=2 的第二批 8×4：27/32（84.375%）；
- 两批合计 51/64（79.6875%），相对初始同协议 50% 提升 29.6875 个百分点；
- 第二批产生 3 个成功/失败混合的非零方差任务组，可进入后续 GRPO；
- 该扩展审计仍来自同一合成语料分布，因此只能作为 checkpoint 选择证据，不能冒充真实用户泛化结论。

模型已保存到 `ml/agentic/checkpoints/stage2-policy-driven-sft-smoke20-v1`。完整云端归档、训练报告和对照审计保存在 `artifacts/remote-backups/stage2-best-20260825`，原始压缩包 SHA-256 为 `2C856399412759568B2C45951425715C6EF85187DDC67E18524D7BCCD3931C6D`。

## 独立编号 Holdout 验证

为避免“换了文件名但仍从案例 0 开始生成”的隐性泄漏，`generate_agentic_corpus.py` 新增 `--start-index`，并在生成报告中记录首尾编号。相关单测 6/6 通过。

随后生成案例 900–1027 共 128 条独立 holdout：

- 128/128 通过生产 Loop、Replay 和 Reward Gate；
- 与 0–767 的 768 条 SFT episode ID 交集为 0；
- GRPO 格式拆分为 109 train / 19 validation，但整个目录冻结为评测用途，不用于训练；
- 初始 Stage28 DPO 在固定 8×4 协议上为 16/32（50%）；
- 20 步 SFT 为 25/32（78.125%），提升 28.125 个百分点；
- 两组 recovery 均从 0/4 提升到 3/4，一组 search 从 0/4 提升到 3/4；
- 7 条剩余失败均为 `get_poi_detail` 参数把合法字段 `poi_ids` 写成 `candidate_poi_ids`。

因此短程 SFT 的提升可在不重叠编号上复现，但剩余瓶颈已收敛为详情工具字段协议，而不是工具选择能力。

独立 holdout 与报告归档在 `artifacts/remote-backups/stage2-holdout900-20260825`，压缩包 SHA-256 为 `3B443E2C8FA19A433B4C1402EC44F189CB4716E3FF8FFC02557E744B12CF22ED`。

## GRPO 烟测阻塞

GRPO corpus 预检通过：108 个训练任务、20 个验证任务、环境/快照版本一致，4-generation、12 轮 policy-driven 配置合法。实际 1-step 烟测在导入 Trainer 时退出，尚未执行任何优化步：

- 云端为 `torch 2.5.1+cu124`、`trl 1.9.2`；
- 当前 TRL 导入 `torch.distributed.fsdp.FSDPModule`；
- PyTorch 2.5.1 不导出该接口，2.6.0 开始导出；
- 正确修复是升级 PyTorch 2.6 系列并重新做依赖/显存 smoke，不应在项目代码中伪造兼容对象。

经用户确认后，已通过清华镜像升级为 `torch 2.6.0+cu124`、`torchvision 0.21.0+cu124`：CUDA、RTX 4090、BF16 矩阵运算、bitsandbytes、`FSDPModule` 和 `GRPOTrainer` 导入全部通过，相关环境/GRPO单测 24/24 通过。

升级后第二次启动仍在优化前被工具结果 Token 预算预检拦截。原因是 Qwen3 chat template 会在“助手工具调用是最后一条消息”时插入空 `<think>`；追加工具结果后该块消失，导致旧的严格 token-prefix 假设不成立。修复包括：

- 使用完整对话中的 assistant EOS 边界切分工具结果 suffix；
- 标准 GRPO 与 turn-credit trainer 共享相同兼容实现；
- 增加条件 thinking 模板回归测试；
- 16/16 相关单测通过；
- 真实 Qwen tokenizer 成功测得 9 轮最小 completion budget 为 8,192 Token，最大工具结果 6,162 Token。

两次失败都发生在 `trainer.train()` 之前，累计 GRPO 优化步仍为 0；模型权重未被修改。

## GRPO 1-Step V3 结果

在兼容修复后启动新实验 `stage2-policy-driven-grpo-smoke1-v3`：原训练分布前 4 个任务、4 generations、trajectory B0、LR 1e-6、beta 0.04、16,384 completion budget。

- 成功完成 1/1 优化步，耗时 98.32 秒；
- train loss -0.03204，KL 8.985e-05，entropy 0.0546；
- reward mean 0.4694，reward std 0.9796，`frac_reward_zero_std=0`；
- 训练组实际奖励 `[0.945833, 0.959167, 0.9725, -1.0]`，3/4 成功，存在真实组内偏好差异；
- adapter 已在验证前保存，SHA-256 为 `da07d147076cb21d836b5469b968606ac906053103c5e1d41f492a356fc2b06c`；
- 随后的内部 grouped eval 因额外申请 11.63 GiB 显存而 OOM；OOM 前的验证 rollout 为 `[0.976, 0.976, -0.67, 0.976]`，同样 3/4。

因此本次结论是“GRPO 在线环境、奖励、组内 advantage、反向优化和保存链路已经跑通”，不是“一步训练提升了准确率”。OOM 原因是 smoke 配置关闭 Trainer eval 后，脚本仍无条件调用 `trainer.evaluate()`。现已改为：`max_steps>0` 的 smoke 保存后跳过高峰值 grouped eval，改用独立的顺序 Agent Loop 审计；正式训练仍执行内部评估。

V3 checkpoint 与审计归档在 `artifacts/remote-backups/stage2-grpo-smoke1-v3-20260825`，压缩包 SHA-256 为 `833E8DFF6080278B358718560C254A7B8CB32C6B19B82C4A67C78694DDB58714`。当前线上/本地主候选仍是 20 步 SFT，V3 只有通过冻结 holdout 对照后才可晋升。

5. GRPO 必须继续使用 `policy_driven`、fresh ledger、无 teacher prefix、至少 9 轮、完整工具结果预算和逐轮 credit audit。
