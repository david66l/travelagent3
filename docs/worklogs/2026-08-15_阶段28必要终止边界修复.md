# 阶段 28：必要终止边界修复

日期：2026-08-15

## 目标

解释并修复 Qwen3-4B SFT / DPO 在 `abort` 与 `propose_tradeoff` 边界上低于 Base 的问题，同时保持澄清、搜索、恢复和正常取舍能力。

## 根因审计

Stage21 / Stage22 的最终训练分布中没有任何正向 `abort`：

| 数据集 | train 总数 | propose_tradeoff | abort |
|---|---:|---:|---:|
| Stage21 SFT | 664 | 54 | 0 |
| Stage22 DPO chosen | 667 | 57 | 0 |

已有的 `qwen3-stage20-verified-abort-preferences-v1` 名称容易误解。它训练的是“不要过早 abort”：正确答案是 `ask_user`，`abort` 位于 rejected 一侧，并不是必要终止正例。

代码层还有两个合同缺口：

1. system prompt 要求“有可行替代才 tradeoff，否则 abort”，但 `GoalCapability` 没有 `actionable_alternatives`；
2. Reward 将两种动作都视为安全终止，无法把错误 tradeoff 判成失败；
3. `abort` 被 Agent Loop 当作普通失败重试一次，导致错误的轮级信用。

## 运行时修复

- `GoalCapability` 新增 `actionable_alternatives` 和 `alternatives`；
- feasibility report 可显式投影 `infeasible`、`unsafe`、`missing_tool`；
- Reward 新增 `TERMINATION_ACTION_MISMATCH` 门禁；
- teacher 根据可行动替代项选择 tradeoff 或 abort；
- policy abort 改为一次立即终止，不再制造虚假重试轮；
- SFT 清洗仅在“非可解 + 明确没有替代项”时接受 failed transition 上的 abort。

相关单测：24 项通过。

## 数据修复

新建 `qwen3-stage28-necessary-abort-repair-v1`：

- 160 条 verifier 通过的 abort 正向 rollout；
- 160 条被 `TERMINATION_ACTION_MISMATCH` 拒绝的 tradeoff 反向 rollout；
- 160 个唯一 DPO 上下文；
- 五类语义：固定闭馆、固定时序、安全封控、必要工具缺失、恢复预算耗尽；
- capability 分布：94 infeasible、36 unsafe、30 missing_tool；
- 与 30 题 AI Pilot 归一化文本精确重叠为 0；最大字符序列相似度 0.311688；
- 与冻结 Stage19 holdout 的模型 payload 重叠为 0。

最终合并集不是把 160 条全部灌入，而是保留旧数据 replay，并按五类分层抽样：

- SFT train：原 664 + abort 60 = 724；五类各 12；
- DPO train：原 667 + abort preference 60 = 727；五类各 12；
- SFT / DPO tokenizer preflight 均通过，最长序列分别不超过 1015 / 1027 token。

## 远端实验

### V1：单一预算冲突语义（未晋升）

- 从 Stage21 SFT adapter 继续训练；
- 24 条 abort train；学习率 `1e-5`，1 epoch；
- train loss：0.005493；eval loss：0.340096；
- Pilot：26/30，与旧 SFT 持平；四个 abort 全部仍错成 tradeoff；
- 结论：标签方向正确，但语义覆盖不足，不进入 DPO。

### V2：五类必要终止语义

- 从原 Stage21 SFT adapter 重新开始，不继承 V1；
- 60 条 abort train，五类各 12；学习率 `1e-5`，1 epoch；
- train loss：0.006805；eval loss：0.029303；
- Pilot：28/30；旧 SFT 为 26/30；
- 26 个非 abort 样本全部正确，未出现过度终止；
- 已修复 unsafe hard gate 与 exhausted recovery；
- 剩余错误：固定闭馆 017、固定时序 018 仍选择 tradeoff。

因此 V2 SFT 通过进入偏好优化的条件。

### V2 DPO：训练有效，但不晋升

- 以 V2 SFT 为起点；
- 727 个 train preference，包含旧能力完整 replay 与五类 abort preference 各 12；
- `beta=0.1`，学习率 `2e-6`，1 epoch；
- train loss：0.225118；eval loss：0.139569；
- eval preference accuracy：1.0；reward margin：1.930869；
- Pilot：28/30，与 V2 SFT 持平；
- 剩余错误仍为 017 与 018，26 个非 abort 样本仍全部正确。

DPO 在训练目标上有效，但没有带来 Pilot 外部增益，因此保留为后训练能力证据，不晋升为默认 checkpoint。

## 最终决策

- 当前最佳 4B：`qwen3-4b-stage28-sft-abort-diverse-v2`，28/30；
- Stage28 DPO：28/30，未超过 SFT，不晋升；
- Qwen3-8B：30/30；
- 生产策略：4B 负责高频澄清、搜索和恢复；复杂 tradeoff 路由 8B；
- 不再针对同一 Pilot 的 017/018 继续调参，避免把 AI-assisted Pilot 变成事实训练集；
- 下一项可信增量应来自真正独立的人类双标外部集。
