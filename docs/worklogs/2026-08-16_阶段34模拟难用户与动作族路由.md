# 阶段 34：模拟难用户与动作族路由工作日志

日期：2026-08-16  
状态：POI 合同故障已修复；150 条难例四模型配对评测完成；动作族路由完成离线回放，尚未作为生产默认路由发布

## 本轮目标

在 300 个模拟真实用户回放之后，完成两件事：

1. 修复苏州、丽江场景中“餐厅结果冒充景点搜索成功”的工具合同问题；
2. 使用同一批冻结难例比较 1.7B Base、SFT、SFT+DPO 和 8B Base，判断后训练是否带来
   可测增益，并用控制器可见字段验证双模型路由价值。

## 一、POI 合同修复

### 根因

两个失败场景的策略动作都是正确的 `search_pois`。故障发生在工具层：供应商返回非空的
餐厅列表后，执行器没有验证请求类别，直接将其视为景点供给成功，最终造成下游
`CANDIDATE_POIS_MISSING` 和路线矩阵缺少 `pois`。

### 改动

- 在 `tool_executor` 中新增请求类别供给校验；
- 只有归一化结果真正包含所需类别才允许进入下游；
- 所有供应商均返回错误类别时，返回明确的 `unavailable`；
- 为苏州和丽江补充受控内置景点兜底；
- 增加“供应商只返回餐厅”和“所有供应商结果不可规划”的单元测试。

### 验证

- POI/动作执行器定向测试：41/41 通过；
- Ruff：通过；
- 重建 Stage33 后端镜像并恢复全栈，容器均健康；
- 原两条失败场景端到端重放：2/2 硬通过、2/2 有效草案、2/2 完成、0 兜底；
- 该批次是故障回归，不因 2/2 结果声称模型晋级。

## 二、150 条冻结难例评测

### 数据边界

- 数据来自 Stage29 冻结集，共 150 条；
- 动作分布：`search_pois` 45、`ask_user` 35、`propose_tradeoff` 40、`abort` 30；
- DeepSeek V4 Flash 合成并双路标注，2 个冲突已裁决；
- 它不是人工用户 benchmark，也不替代真实 Shadow/Canary；
- 每个模型采用确定性解码各运行一次，用于严格配对比较。

### 四模型结果

| 模型 | 原冻结标签正确 | 当前生产合同正确 | P50 | P95 |
| --- | ---: | ---: | ---: | ---: |
| Qwen3-1.7B Base | 148/150 | 149/150 | 2,397 ms | 4,788 ms |
| Qwen3-1.7B SFT | 148/150 | 149/150 | 2,879 ms | 5,810 ms |
| Qwen3-1.7B SFT+DPO | 148/150 | 149/150 | 3,130 ms | 6,346 ms |
| Qwen3-8B Base | 145/150 | 146/150 | 2,769 ms | 8,002 ms |

四组各 150 次请求均无 HTTP 错误。

### 配对观察

- SFT 修复了 Base 的 1 个搜索决策错误，但新增了 1 个重复 `abort` 工具调用错误，净正确数不变；
- DPO 与 SFT 的动作序列在 150/150 条上相同，正确结果也完全相同；参数有 21/150 条
  文本差异（搜索 13、澄清 4、终止 3、权衡 1），但当前评测没有证明这些变化带来效用增益；
- 8B 在这个“受限工具动作选择”任务上没有提供路由的独有胜例，且 P95 更高；
- 这不等于 8B 没价值：它仍应面向开放式复杂规划、歧义裁决和小模型低置信度兜底，
  本评测只覆盖窄动作决策。

## 三、动作族路由回放

离线回放规则：只要控制器当前允许 `search_pois`，使用 SFT；否则使用 Base。该规则只读取
`allowed_actions`，不读取 `expected_action` 或其他金标字段。

- 路由分配：SFT 45、Base 105；
- 原冻结标签正确：149/150；
- 当前生产合同正确：150/150；
- P50/P95：2,897/4,841 ms；
- 唯一原标签失败是冻结标签要求 `abort`、而现行生产合同允许 `ask_user` 的已知标签冲突。

这是可部署规则的离线反事实回放，不代表该路由已经上线。正式发布仍需把路由接入运行时，
再进行 Shadow 和回滚验证。

## 当前决策

- 保留 1.7B Base/SFT 双模型动作族路由为当前候选；
- 不晋级当前 DPO：它没有改变动作或正确性，参数变化也尚无效用增益证据；
- 不把 8B 设为受限工具决策的默认模型；
- 8B 保留为复杂规划教师和低置信度升级路径；
- 真实流量证据仍为 0/300，Stage33 的真实 Canary 门禁没有因此放宽。

## 下一轮后训练重点

1. 构造“只输出一个动作”的重复调用难例，专项修复 SFT 的双 `abort`；
2. 构造能区分 chosen/rejected 的偏好对，先验证 log-prob margin，再训练 DPO，避免同质化；
3. 将动作族路由接入 Shadow，只执行冠军动作并保留完整审计与一键回滚；
4. 增加真正需要 8B 的多约束冲突、跨轮恢复和开放式规划难例，单独评价教师价值；
5. 继续收集真实、结果可观测的 300 对 Shadow，合成数据不冒充发布证据。
