# 2026-08-27 Stage3 GRPO 恢复策略提升与最终验收

## 1. 本阶段目标

在不重新定义 TravelAgent 整体架构的前提下，验证强化学习是否能真实改善一个明确、可复现且可验证的子问题：当搜索工具返回 `QUERY_TOO_BROAD`、结果为空或需要切换工具时，模型能否根据当前状态选择正确的恢复动作，而不是重复调用、过早结束或生成非法参数。

本阶段不把训练奖励、训练集通过率或单次演示结果当作最终结论。最终结论必须同时满足：独立盲测、同题配对、公平解码协议、统计显著性和原能力回归门禁。

## 2. 系统与训练边界

- **完整系统**：Agent Loop 负责读取状态、选择工具、消费工具反馈并更新状态；CP-SAT 负责满足预算、时间、营业时间等硬约束的行程求解；记忆与上下文模块向策略提供用户偏好和当前任务状态。
- **SFT 的作用**：先让 4B 模型学会 TravelAgent 的动作格式、工具语义和基本决策边界，形成稳定基线。
- **GRPO 的作用**：不重新教授全部知识，重点优化“工具失败后的恢复子策略”。同一状态采样多个候选动作，通过可执行验证器按照任务是否恢复、动作是否合法、是否重复和是否满足状态约束给奖励。
- **训练实现**：采用 controller-first、state-scoped tools。控制器先构造确定的失败状态，再仅暴露该状态允许的工具集合，让 GRPO 学习真正有方差且可验证的下一步决策，避免奖励被无关文本生成噪声淹没。
- **能力声明边界**：本阶段证明的是“GRPO 提升了工具失败恢复轨迹成功率”，不是泛化为“整个旅行规划系统所有任务准确率都提升”。

## 3. 关键问题与修复

检查 Stage3 多轮数据时发现，首轮搜索已经携带用户兴趣关键词，但快照仍把期望参数写成空对象。验证器因此把本应触发 `QUERY_TOO_BROAD` 的合法调用判为 `SNAPSHOT_ARGUMENT_MISMATCH`，训练和评测测到的是错误的数据合同，而不是恢复能力。

修复内容：

1. 将首轮搜索的快照参数改为 `{"keywords": interests[:2]}`，使演示轨迹、快照和运行时校验保持一致。
2. 新增端到端单元测试，覆盖搜索参数和后续恢复状态，防止数据生成器再次漂移。
3. 新增困难分层课程生成器，可按 strata 精确扩展高方差样本，避免大量已经全对或全错的样本稀释 GRPO 信号。
4. 保留成对增益报告脚本，对相同 task/seed 下的 SFT 与 GRPO 结果做逐条比较，并加入 McNemar 检验和按任务聚类的 bootstrap 置信区间。

## 4. 训练与筛选过程

- 基线：`stage2-sft-v7-actionweighted-balanced-lr2e6-step50`
- GRPO 训练链路：先以 v10b 学习精确困难恢复，再以 v11 引入困难分层与表达多样性，降低只记住固定失败模板的风险。
- 最终候选：`stage3-grpo-v11-hard-stratum-from-v10b-lr5e6-step10/checkpoint-5`
- 最终模型形式：Qwen3-4B 的 LoRA adapter，rank 16、alpha 32。
- 评测采用独立的失败后用户表达模板；最终盲测数据不用于训练或 checkpoint 选择。

## 5. 最终结果

### 5.1 恢复子策略独立盲测

评测规模为 32 个任务、每题 4 个固定随机种子，共 128 对 SFT/GRPO 配对轨迹。

| 指标 | SFT 基线 | GRPO v11 | 变化 |
| --- | ---: | ---: | ---: |
| 恢复轨迹成功数 | 111/128 | 118/128 | +7 |
| 恢复轨迹成功率 | 86.72% | 92.19% | **+5.47 个百分点** |
| 失败率 | 13.28% | 7.81% | **相对下降 41.18%** |
| cross-tool 恢复 | 81.25% | 87.50% | +6.25 个百分点 |
| search-only 恢复 | 92.19% | 96.88% | +4.69 个百分点 |

成对结果为：GRPO 单独成功 7 条、SFT 单独成功 0 条、共同成功 111 条、共同失败 10 条。精确 McNemar 双侧检验 `p=0.015625`；按任务聚类 bootstrap 的 95% 置信区间为 `[+1.56, +10.16]` 个百分点，不包含 0。预先设置的证据门禁全部通过。

### 5.2 原决策能力回归门禁

在 Stage2 未见决策边界集上，以 `policy_driven`、temperature 0.2、固定 seed 421 运行 64 个任务、每题 4 次，共 256 条轨迹：

- SFT：256/256 成功。
- GRPO v11：256/256 成功。
- GRPO v11 的空动作、非法动作、策略输出错误、参数错误均为 0。

这说明 GRPO 在提升恢复子策略的同时，没有破坏澄清、常规搜索和偏好权衡等原有决策边界。该回归集用于验证“不退化”，不用于宣称生产成功率提升。

## 6. 可用于简历和面试的严谨表述

> 面向旅行 Agent 工具失败后的恢复决策，构建状态约束动作空间与可执行 Verifier 奖励，并基于 Qwen3-4B 开展 GRPO 后训练；在 128 条独立盲测配对轨迹上，将恢复成功率由 86.72% 提升至 92.19%（+5.47pp，失败率相对下降 41.18%，McNemar p=0.0156），同时在 256 条原决策边界回归轨迹上保持 100% 通过且无非法工具调用。

面试时需要明确：这里的 92.19% 是“工具失败恢复轨迹成功率”，评测单位是完整恢复轨迹，不是单步分类准确率，也不是整个产品的线上订单成功率。

## 8. 当前限制与后续方向

1. 当前显著提升集中在工具失败恢复子策略，不能把结果外推成所有旅行任务均提升 5.47 个百分点。
2. 盲测包含 32 个任务和 128 条随机轨迹，已经达到本阶段统计门禁，但若用于论文或正式上线，应继续扩大不同城市、工具故障类型和用户表达的覆盖。
3. 当前适配器配置记录的是云端基模路径 `/root/models/Qwen3-4B`。本地部署时应复制为部署版本并修改基模引用，不改动原始证据包。
4. 下一步优先做失败簇分析和更大外部盲测，而不是继续堆训练轮数；只有发现稳定的新失败模式后才继续 GRPO。
