# 阶段 6：训练语料治理与 3B SFT 验证

日期：2026-08-13

## 阶段目标

为 TravelAgent 的真实策略决策构建可审计、可复现、无数据泄漏的中文 SFT/GRPO 语料，并在独立 GPU 环境中验证本地模型训练、保存、重载和固定测试集评测链路。

本阶段只验证工程闭环和早期能力信号，不把短步训练结果表述为正式模型效果。

## 训练语料建设

新增了通过生产 `BoundedAgentLoop` 执行的中文课程环境生成器，而不是直接拼接“问题—答案”文本。每条样本包含独立任务、不可变工具快照、完整 Agent episode、程序化校验结果和六类 Reward。

最终生成 4500 个中文场景，覆盖上海、北京、杭州、南京、苏州、成都、西安和广州，包括：

- 3600 个经过程序校验的正常规划场景，其中包含可重试工具故障；
- 450 个缺少必要信息、应向用户澄清的场景；
- 450 个约束不可行、应安全提出取舍的场景。

正式数据门禁结果：

- 候选 episode：4500；
- 接受：4500；
- 拒绝：0；
- 导出 SFT 策略样本：4500；
- 失败后重试前的 450 个未验证动作被排除，没有作为正确答案模仿；
- SFT 训练/验证/测试：3095 / 468 / 937；
- GRPO 训练/验证任务：3804 / 696；
- 场景 ID 和初始状态指纹无跨集合重叠；
- SFT 数据集版本：`sft-555ef2b376072c93`；
- 环境及快照版本：`travel-curriculum.v1`。

本地产物位于 `ml/agentic/datasets`，属于可再生训练产物，已由 Git 忽略，不提交大体积语料。

## 数据质量问题及解决

### 1. 首版中文语料存在编码污染

首版批量生成结果中出现 Unicode replacement character（`U+FFFD`）。如果继续训练，模型会学习损坏文本，而且仅凭文件可以被 JSON 解析无法发现问题。

解决方式：

1. 重写中文课程生成内容并重新生成全部 4500 个场景；
2. SFT 和 GRPO preflight 同时增加 `U+FFFD` 深度扫描；
3. 检测到编码污染时直接阻断训练，不允许降级成 warning。

### 2. PII 规则误判哈希与 UUID

原有隐私规则会把部分长数字片段、哈希或 UUID 误判为手机号/身份证，导致干净轨迹被拒绝。

解决方式：收紧号码边界规则，保留真实手机号、邮箱、身份证和敏感字段脱敏，同时不误伤轨迹 ID、内容哈希和数据版本。

### 3. 离线训练被 API 配置耦合

训练脚本只导入 Agent 模块时也会构造 API 客户端；没有 API Key 的纯离线训练节点因此在导入阶段失败。

解决方式：无 Key 时允许客户端使用不可调用的占位配置完成模块加载；只有真正发起 API 请求时才报配置错误。训练和数据 preflight 不再依赖线上 LLM 密钥。

## 本地 0.5B 工程烟雾试验

在本地完成 Qwen2.5-0.5B 的真实单步 SFT 和单步 GRPO，两个适配器均可保存和重载。这证明训练入口不是占位脚本。

10 场景范围烟雾评测结果：

| 模型 | Gate 通过率 | 硬约束通过率 | 平均 Reward |
|---|---:|---:|---:|
| Base 0.5B | 100% | 80% | 0.9611 |
| 单步 SFT | 20% | 0% | -0.3502 |
| 单步 SFT+GRPO | 10% | 0% | -0.5061 |

结论：训练代码能运行不等于模型变强。单步检查点明显破坏工具格式，因此只保留为工程证据，不作为效果结论。该测试还是显式范围测试，不是严格未见集。

## 3B SFT 试验

### 过拟合预警与主动停止

首次按 2 epoch 启动训练时，约 100/388 步损失已经降至接近 `7e-5`，token accuracy 很快到 1.0。这说明当前策略目标种类较少，继续训练很可能只是记忆固定动作。

本次训练被主动停止，且中断时没有形成可报告检查点。未把它描述成训练成功。

### 20 步受控试验

随后使用更低学习率和 20 步上限进行受控 SFT：

- 模型：Qwen2.5-3B-Instruct；
- 训练步数：20；
- 学习率：`2e-5`；
- 训练时间：93.41 秒；
- 训练损失：0.15435；
- 验证损失：0.11852；
- 验证 token accuracy：0.97425；
- 运行范围：`smoke`。

适配器已成功保存和重载。

### 严格未见集固定对比

从 SFT test 与 GRPO validation 的场景交集中选取固定 30 个任务，对 Base 3B 和 20 步 SFT 使用相同 Agent Loop、快照、解码参数和 Reward 评测：

| 模型 | Gate 通过率 | 硬约束通过率 | 平均 Reward | 策略错误终止 |
|---|---:|---:|---:|---:|
| Base 3B | 66.67% | 46.67% | 0.39485 | 10/30 |
| 20 步 SFT | 76.67% | 50.00% | 0.57293 | 7/30 |

结论：短步 SFT 出现正向能力信号，主要减少了策略输出错误；但样本只有 30 个、训练只有 20 步，不能据此声称 SFT 已正式提升模型。硬约束通过率只提高 3.33 个百分点，仍需扩大盲测和改进决策数据多样性。

## 当前结论

SFT 数据生成、质量门禁、训练、保存、重载和严格未见集评测链路已经打通。当前 3B SFT 检查点是受控烟雾检查点，不是最终模型。

发现的关键数据问题是：正常规划中真正由模型决定的动作通常只有一次候选搜索，确定性求解和校验均属于 Controller。这保证了线上可靠性，但也使 SFT 目标相对单一。后续数据增强必须增加有依据的搜索、澄清和恢复决策，不能把确定性安全门禁错误地下放给模型，只为了增加训练动作数量。
