> 联合分析：本机工程师 + 外聘"大厂 Agent 专家"角色（独立读码 + 文献查证，结论交叉验证后合并）。

## 0. TL;DR

09-01 的 v8→v13 六个 SFT 实验（理由质量专项）全部失败/作废，不是训练基建问题，而是**"监督什么、测什么"这一层的合同错误**：

1. **真根因一（数据合同）**：教师 reason 用 `sha256(action:evidence) % 8` 随机选前缀（`backend/src/agentic/reason_quality.py:120-138`），给监督目标人为注入了 ln8 条件熵。1.7B + QLoRA + 460 行根本没学会这个 8 模混合分布（实测前缀段每 token NLL 4.51，是混合分布理论下限 ~0.1 的 45 倍），生成时落到基座先验的"约束冲突：…"式转述——语义正确但词面不合规。
2. **真根因二（Goodhart 代理同一性）**：GRPO 奖励（`trl_environment.py:1625`）、DPO chosen 构造（`build_verifier_reason_dpo_preferences.py:316`）、eval 五门检查，**三者是同一个词面函数**。系统内不存在任何对"理由语义质量"的测量。v8 的 eval token acc 1.0 / grounding 0.45 就是 Gao 2022 代理过优化曲线的起点形态。
3. **独立根因三（retry_solve 动作面）**：v11（任何加权之前）retry_solve 已 10/10 失败、action_match 挂 6；其中 37.5% 是纯格式失败（empty_action 18.75% + policy_output_error 18.75%），**零训练成本可用已有 Outlines 约束解码结构性消灭**。retry 环境动作面最宽（多路分类），tradeoff 环境近乎单选——94% vs 35% 的差距主要是状态构造差异，不是模型能力差异。
4. **表象（组织症状）**：一天六个实验、越来越激进的 loss 加权（v12 权重3 → loss 38.1 的梯度累积 bug；v13 修复后全面回归 full_success 0.0），没有一个实验开跑前预登记"什么结果算失败"。

**修复主线**：短期去哈希改 canonical 前缀（每 action×violation_code 一个固定模板）→ 目标态把 reason 从模型生成面移走（模型输出可验证槽位，controller/grammar 确定性渲染 prose，理由合规由构造保证）→ 约束解码消灭格式失败 → pass-rate 前沿带采样重启 GRPO → 评测扩容 + 训练/评测目标解耦。

## 1. 证据链（全部已核实）

### 1.1 监督目标不可学的精确机理

`build_grounded_repair_reason`（`reason_quality.py:120-138`）：

```python
index = int(hashlib.sha256(f"{target_action}:{evidence}".encode()).hexdigest()[:8], 16) % len(suffixes)
rationale = suffixes[index]
return f"{rationale}：{evidence}。"
```

三个层次（专家裁决，比我最初的"不可学"论断更精确）：

- **层1（不成立）**："算不了 sha256 所以 NLL 恒高" —— 错。不可预测的只有 8 选 1 的分支 token；若模型完美学到条件混合分布（各 1/8），前缀段总额外 NLL = ln8 ≈ 2.08 nats，摊到 20-30 token 上每 token 仅 ~0.07-0.1。分布是完全可学的。
- **层2（系统卡死的最糟位置）**：teacher-forcing 下，对 8 模均匀目标，"永远输出某一个固定前缀"的期望 NLL 严格劣于学混合分布——**SFT 没有梯度压力收敛到"固定前缀"这个 eval 可通过的解**；而能收敛到那里的 reward 驱动优化（RL/拒绝采样）又被零方差卡住。SFT 不想去、RL 去不了、eval 只认那里。
- **层3（真根因）**：实测 4.51/token = 模型在每个模板位置只放 ~1% 概率质量，**连混合分布都没学起来**。机理：460 行×2ep ÷ 24 模板（3 动作×8 前缀）≈ 每模板 ~38 次梯度曝光，同动作相近 evidence 对应不同前缀 → 分支区梯度对冲 → 净信号趋零 → 模型保留基座先验。temp 0.8 采样进一步把 1-3% 的模板质量稀释到 90%+ 概率落在模板外。

零优化器诊断（v11 checkpoint，12 样本分段 NLL）：**rationale_prefix 4.510 / evidence 0.057 / action 0.045 / eos ≈ 0** —— 复制能力和训练量都没问题，失败被精确隔离在"不可预测分支"上。这不是数据量不足，是监督目标的条件熵被人为注入。

### 1.2 五门检查的失败分类学（v11, 80 题 internal-dev）

| target | 步无效 | 主导失败 | 次要失败 |
|---|---|---|---|
| propose_tradeoff | 59/60 | **reason_action_rationale_match ×56**（cue 词表未命中） | grounding ×22, specificity ×23 |
| abort | 10/10 | **rationale_match ×9** | grounding/specificity ×5 |
| retry_solve | 10/10 | **action_match ×6**（动作选错） | 英文回退 ×4（含 "verifier" 等私有词） |

典型假阴性：模型输出"约束冲突：任意两个景点之间通勤时间不能超过35分钟，但目前方案存在景点间通勤时间超出35分钟的约束。"——**人眼看语义完全正确**，但不含 cue 词表（选择/取舍/确认/放宽/调整方案）任何一个词。

### 1.3 GRPO 零方差与奖励悬崖

- tradeoff 语料 v9 成功率 94% → group 4 全 reward 1.0 → advantage 全 0 → `ineligible`（rollout_only_report 实锤）。
- retry 语料成功率 35%，其中 37.5% 是纯信封失败。
- 奖励公式（`trl_environment.py:1545-1549`）：`score = 2*mean(checks)-1` **仅当 action_match 且输出合同全过时生效，否则一律 -1.0**。部分分只在"动作已对"的样本内产生方差——恰是饱和样本。方差源与难度分布错位。

### 1.4 参考项目对照（D:\TravelRLAgent）

ms-swift GRPO 全参 Qwen3-4B（6 卡），850 条蒸馏 SFT + 200 prompt + 200 步 GRPO → RL 6.85 > SFT 6.31 > Qwen3-14B 原生 5.86（80 题 LLM judge A/B）。奖励 = 6 子奖励课程调度（格式→过程→效率→judge，后期 judge 权重 0.75），MAX_TURNS 13，反馈式纠错而非硬终止，全部 assistant 轮计损失。

**专家点破的问题**：他们的评测分是 judge 打的，而 judge 同时占训练奖励 0.75 权重——**train-eval 循环**，与我们"reward==eval 同函数"是同一个病的两个菌株；只是 judge 的语义容量比词表大，所以"碰巧"也改善了真实体验。
**该抄**：子奖励分解+课程调度、反馈式纠错、全 assistant 轮计损失、"全参 vs LoRA 是 RL 表达能力瓶颈"的提醒。
**不该抄**：judge 同时进训练与评测。

## 3. 面试 80 分差距分析

### 3.1 当前最容易被挑战的 3 个问题（附答法）

**Q1："连跑六个 SFT 实验全失败，为什么第一个之后没止损？"**
承认组织失误（无预登记假设、变量越加越多）→ 展示诊断方法论：零优化器分段 NLL（4.510/0.057/0.045）把失败定位到"监督目标注入 ln8 条件熵"，与混合分布理论下限差 45 倍 → 结论是目标构造错误而非训练量不足 → 修复是确定性合同而非更多数据。**把六连败重构为"我建立了能定位监督信号失效层的诊断工具"**——坏事变亮点的唯一诚实路径。

**Q2："训练奖励和评测是同一个词面函数，你的 94% 算不算 Goodhart？"**
直接承认（说"不算"就出局）。举证 token acc 1.0 vs grounding 0.45 的代理-目标背离，引 Gao 2022。然后讲修复：理由从"被词面检查的自由文本"改为"可验证槽位+确定性渲染"，机器可查的进规则、自然度进校准裁判（只监控），训练与评测目标解耦。**面试官想听的是你能在奖励设计层识别 proxy identity，而不是你的指标数字。**

**Q3："GRPO 没跑出东西、DPO 只有 300 对——这个项目里 RL 到底买到了什么？"**
零方差诊断（94% 状态全同奖励 → advantage 全 0）说明问题在状态难度分布而非算法；正确入口是 pass-rate 前沿带采样；RL 的价值定位是"闭合 SFT 覆盖不到的边界状态的动作选择残差"（RLVR-as-selection），不是学新能力；在 4080/1.7B 约束下有意选择"窄决策面+约束解码+小步 RL"而非"自由生成+judge 奖励"，并说明为什么。**展示"我知道 RL 在这个规模买什么、不买什么"比展示一个涨点更有说服力。**

### 3.2 修完后的一句话叙事

> "我把旅行 agent 的失败修复决策从'自然语言理由生成'重构为'可验证槽位+确定性渲染'——模型只学 3 动作决策，理由合同由构造保证 100% 合规（原 41%）；在 Qwen3-1.7B+QLoRA 单卡上，用 pass-rate 前沿采样 GRPO（group 16，DAPO 式零方差过滤）把 verifier-repair 决策准确率从 X% 提升到 Y%（sealed test，n≥300/类，McNemar p<0.05），格式失败经约束解码归零，全程 promotion gate + 四臂配对评测守住零幻觉底线。"

量化成果四件套：理由合同合规率（41%→100% 构造保证）、动作决策准确率（带 CI 与显著性）、格式失败率（37.5%→0）、一个诚实的未解决项（如多步序列泛化）——保留一个已知未解决项加分不减分。

### 3.3 从 75 到 85 还缺什么

1. **一个端到端"真提升"闭环**（最缺）：现在所有故事都是"防住了退化"。需要完整正循环：合同修复→SFT→前沿 GRPO→sealed test 显著→（理想）影子流量 A/B。8-10pp 的显著可复现提升 > 十个防御性设计。
2. **多轮长程证据**：决策状态全是单步；哪怕只加"3 步修复序列成功率"。
3. **外人可信的语义评测**：κ≥0.6 校准裁判 + 公开协议，让"理由质量"从自说自话变成可外部审计。
4. **对 QLoRA 瓶颈的受控回答**：r16 vs r64。
