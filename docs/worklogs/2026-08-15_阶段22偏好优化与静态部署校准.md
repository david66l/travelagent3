# 阶段 22：Qwen3-4B 偏好优化与静态部署校准

日期：2026-08-15

状态：阶段 22 的正式 DPO adapter、偏好评测和动态/静态多轮评测均已完成；Agentic + Evaluation 全量回归通过。1.5 倍静态合并候选在独立验证集 172/172、多轮冻结测试 172/172，但严格单步测试为 509/516，7 次均为正确 `propose_tradeoff` 后额外生成 `abort`。因此该静态模型进入阶段 23 的服务路由与输出契约治理，不直接宣称为完全无损生产版本。

## 1. 本阶段目标

阶段 21 已得到平衡 SFT 学生，但静态合并会在 clarification/tradeoff 边界掉点。本阶段以该 SFT adapter 为起点，完成：

- 构建类别平衡、无泄漏的 chosen/rejected 偏好数据；
- 使用 DPO 扩大正确动作与错误动作的概率间隔；
- 分别验证动态 LoRA、静态合并和完整 Agent 循环；
- 用独立 validation 选择静态合并参数，冻结后只运行一次正式 test；
- 记录正确率、奖励、步数、token、延迟与负结果；
- 为下一阶段的小模型路由和推理加速提供可复现基线。

## 2. 文献与官方实现依据

本阶段在遇到动态 LoRA 与静态合并结果不一致时核对了以下资料：

- DPO 论文：<https://arxiv.org/abs/2305.18290>；
- QLoRA 论文：<https://arxiv.org/abs/2305.14314>；
- TRL DPOTrainer 官方文档：<https://huggingface.co/docs/trl/dpo_trainer>；
- PEFT LoRA 合并接口：<https://huggingface.co/docs/peft/main/package_reference/lora>；
- PEFT checkpoint 与量化注意事项：<https://huggingface.co/docs/peft/developer_guides/checkpoint>。

采用的工程结论：

1. 已加载的 PeftModel 可以直接继续做 DPO，不重复注入一套 LoRA；
2. PEFT 场景的 DPO 学习率采用官方建议量级 `5e-6`；
3. QLoRA 用 NF4 双重量化降低 24 GiB 显存压力；
4. 量化 adapter 的动态低秩计算与反量化后静态写盘不保证边界输出逐 token 等价，因此必须单独设置静态部署验收门；
5. 静态合并倍率只能在 validation 上选择，不能根据 test 结果反复调参。

## 10. 完整 Agent 多轮冻结验收

动态正式 DPO 与 1.5 倍静态模型都在同一批 172 个冻结任务上执行真实 ControllerFirstPolicy 循环：

| 模型/服务 | 成功任务 | 平均奖励 | policy steps | completion tokens | 请求延迟总计 | 每任务平均模型延迟 |
|---|---:|---:|---:|---:|---:|---:|
| Qwen3-4B Base | 172/172 | 0.965842 | 222 | 6677 | 165051.673 ms | 959.603 ms |
| 阶段 21 平衡 SFT，动态 LoRA | 172/172 | 0.965842 | 222 | 5463 | 302685.404 ms | 1759.799 ms |
| 阶段 22 正式 DPO，动态 LoRA | 172/172 | 0.965842 | 222 | 6636 | 279490.631 ms | 1624.946 ms |
| 阶段 22 正式 DPO，1.5 倍 FP16 静态 | 172/172 | 0.965842 | 222 | 5045 | 88037.382 ms | 511.845 ms |

静态服务相对正式 DPO 动态 LoRA：

- 每任务模型延迟快约 3.17 倍；
- completion tokens 少 1591，下降约 24.0%；
- 成功率、奖励和 policy steps 不变。

静态服务相对 Base：

- 每任务模型延迟快约 1.87 倍；
- completion tokens 少 1632，下降约 24.4%；
- 成功率和奖励不变。

多轮评测中 clarification 14/14、recovery 50/50、search 104/104、tradeoff 4/4。严格单步的额外 `abort` 没有造成真实 Agent 任务失败，但阶段 23 仍需把“一次 policy step 只允许一个动作”做成服务输出契约。

## 12. 阶段结论

可以对外表述：

- 完成从 SFT adapter 继续进行 QLoRA DPO 的正式训练链路；
- 构建 1011 个唯一、分层、无冻结集泄漏的偏好对；
- DPO 将 test chosen/rejected 平均 log-prob margin 从 0.672975 提高到 0.825050，提升约 22.6%；
- 动态与静态模型都在 172 个完整 Agent 任务上 100% 成功；
- validation 校准后的静态服务相对动态 LoRA 快约 3.17 倍，token 降约 24.0%；
- 完成 SFT、偏好优化、量化训练、静态合并、冻结评测与部署校准闭环。

不可以对外表述：

- 静态模型在所有严格单步调用上 100% 等价；
- 1.5 倍倍率是通过 test 调出来的；
- 训练 loss 本身证明 Agent 能力提升；
- 动态 LoRA 已获得推理加速。

## 13. 阶段 23 交接

下一阶段按以下顺序推进：

1. 实现一次 policy step 只接收一个工具动作的输出契约，显式拒绝或截断多动作响应；
2. 建立 4B 高频动作学生与 8B 复杂规划教师的服务路由；
3. 为 clarification、search、recovery、tradeoff 定义可观测路由规则和 fallback；
4. 加入前缀缓存、连续批处理、固定短输出预算和并发配置对照；
5. 复跑严格单步、多轮冻结、延迟、吞吐、显存与 token 门；
6. 形成 Base / SFT / DPO dynamic / DPO static / routed system 的统一对照报告；
7. 只有路由回退和输出契约均通过后，才把静态 4B 升级为正式高频决策服务。
