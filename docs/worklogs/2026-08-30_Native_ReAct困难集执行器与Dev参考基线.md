# 2026-08-30 Native ReAct 困难集执行器与 Dev 参考基线

## 本轮目标

把 200 题冻结困难集真正接入生产 Agent 链路，验证评测不是根据静态标签打分，也不是单次模型调用，而是完整执行：意图解析 → ReAct 工具决策 → 证据检索 → CP-SAT 排程 → Verifier → 修复/安全终止 → 草案或用户修改。

## 完成内容

1. 新增困难集运行时与故障执行器。每个恢复题只在真实动作边界注入一次声明故障，随后继续调用生产 `TravelActionExecutor`，覆盖超时、限流、空结果和过期数据。
2. 新增可恢复评测脚本。支持按 case、能力族、难度筛选，支持中断续跑；恢复时强校验数据哈希、模型、服务地址、随机种子和温度，防止把不同协议的结果拼在一起。
3. 建立任务级评分。除原全链路结果外，还检查意图合同、必经动作、必备产物、故障是否真实触发、恢复是否在 3 个决策回合内完成、是否伪造成功，以及安全终止是否有事实依据。
4. Test 隔离。默认只能运行 40 题 Dev；160 题 Test 必须显式传入解封参数，避免边调边测。
5. 增加 19 项定向测试，覆盖四类故障、恢复评分、伪成功拒绝、过期信息权衡、冻结哈希、Test 封印、Cluster Bootstrap 和续跑协议不一致。

## 从 v1 冒烟中发现并修正的数据问题

v1 首次 Dev 运行得到 32/40，但其中至少 6 个失败来自评测题作者合同，而不是 Agent：普通题预算被意外设成不可行、题面与标签旅行天数不一致、过期信息题没有明确要求时效查询、修改字段落在错误约束域、英文“核实开放状态”被误写成“必去”等。

因此发布 v2，而不是通过放宽评分把错误掩盖掉。v2 重新生成后保持 200 个不同任务、20 城市、40 语义簇；Dev/Test 城市不重合；扫描 280 个历史 JSONL、13,929 个唯一历史请求，原文和近重复污染均为 0。v1 已标记退役，不再参与模型比较。

## 唯一失败与真实瓶颈

失败题：`nrhb-v2-noisy-multilingual-004-chengdu`。

用户用英文要求成都 5 日行程，金沙遗址博物馆必去，并要求排程前核实开放状态。Agent 正确识别全部字段，完成时效检索、POI 检索、8 个 POI 详情、路线矩阵、求解和验证；Verifier 随后报告 `MUST_VISIT_MISSING`。

问题发生在修复阶段：策略没有针对缺失必去点做局部候选替换或约束增强，而是重新调用城市知识检索，触发全局重规划。第二轮只剩 5 个 POI 详情，最终报 `RESEARCH_EVIDENCE_INSUFFICIENT:5/8` 并安全终止。整题使用 7 次策略调用、21 次工具调用和 25,425 Token。

这说明当前主要瓶颈已经从“会不会选基础工具”转移到“Verifier 失败后能否根据 violation code 选择最小修复动作”。下一批后训练数据应重点覆盖：

- `MUST_VISIT_MISSING` → 保留已有证据，增强必去约束或替换候选，不全局清空。
- 软约束失败 → 局部换点/调序，不重新执行全部研究。
- 证据缺口 → 只补缺失的 POI 详情，并保留已验证产物。
- 奖励函数同时惩罚无必要的全局重规划、重复策略动作、Token 浪费和最终缺失草案。

## 工程观察与边界

- Tavily 在评测中持续返回 HTTP 432，系统自动切换公共搜索源，证明降级链路能够接管；但生产环境仍应修复主供应商配额/鉴权并增加供应商级指标。
- 少数结构化输出出现枚举越界或浮点天数，现有一次修复重试可以恢复；后续应把 `schema_valid_first_try` 单独列为模型指标。
- LangSmith 追踪配额已耗尽，本轮关闭远程追踪，但本地逐步动作、验证结果、Token、延迟和失败证据仍完整写入报告。
- 这 40 题是确定性组合生成、尚未双人标注的 Dev，不可包装成独立人工测试；160 题 Test 仍未运行。
