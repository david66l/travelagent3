## 关键发现

### 发现一：之前拒绝两次“轮级训练”是正确的

多个研究都明确指出：同组奖励相同会导致 advantage 为 0。checkpoint 能保存、loss 有小数并不证明策略得到有效更新。项目将 `effective_nonzero_credited_turns > 0` 设为 R1 门禁是必要的。

### 发现二：新恢复任务应先 SFT，不应直接硬做 RL

模型成功率接近 0 时，同组全部失败，GRPO 没有比较信号。最合理路径是使用真实 Agent Loop 历史做少量恢复 SFT，加入旧能力 replay，确认独立 validation 出现非零成功和行为差异后再做 RL。

### 发现三：原来的线性混合 R1 还不够严谨

若局部过程分和终局总分直接相加，成功轨迹中的无效动作仍可能得到正信用。新设计需要：

- 先判断动作格式、权限、参数和 grounding 是否有效；
- 只有有效动作才能获得未来成功传播；
- 合法调用遇到外部超时不能误判为模型错误；
- 无效动作不能被正终局分补偿。

### 发现四：TravelAgent 不应直接照搬标准答案信息增益

TRACE/IGPO 针对有唯一标准答案的搜索任务。旅行计划存在多解，更可靠的信号是：任务状态推进、事实新增、约束满足、Solver/Validator 和安全终止。参考模型信息增益只适合后续 R2，不作为首个可信 R1 的前提。

### 发现五：现有 PolicyContext 已具备进度感知骨架

PROGRA 所需的目标摘要、历史进度、失败诊断和未来计划，已经分别存在于 TravelAgent 的约束、事实/artifact、`failure_summary`、当前/剩余任务与允许动作中。不需要新增长篇私有思维链，只需确保 SFT 和 RL 真正使用这些结构化状态。
