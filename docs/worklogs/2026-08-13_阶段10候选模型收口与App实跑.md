## 一、正式 Base / SFT / SFT+GRPO 配对对照

在相同 32 个 validation holdout 任务上，每任务运行 4 次 NF4 随机 rollout，共 128 次；三组使用相同 `sha256-task-sample-v1` rollout seed，不允许不同 checkpoint 消耗不同随机数后形成伪对照。

| 模型 | 成功率 | 平均 Reward | 澄清 | 恢复 | 搜索 | 权衡 |
|---|---:|---:|---:|---:|---:|---:|
| Base 3B | 60.16% | 0.2301 | 84.38% | 81.25% | 75.00% | 0.00% |
| SFT 3B | 80.47% | 0.5934 | 87.50% | 93.75% | 84.38% | 56.25% |
| SFT+GRPO 3B | 82.81% | 0.6373 | 90.62% | 93.75% | 84.38% | 62.50% |

原始 `rollouts.jsonl` 保留 task、动作、终止原因、独立 seed、六类策略 Reward 和 audit-only quality 字段；报告明确限定为受控工程实验，不冒充论文级 benchmark。

## 三、本地 checkpoint 正式接入 App 配置

此前本地模型可以被离线脚本加载，但 App 集成层仍只会选择 API Policy。现已增加：

- `AGENTIC_POLICY_BACKEND=api|local_checkpoint`；
- `AGENTIC_LOCAL_CHECKPOINT`；
- NF4 和最大生成 token 配置；
- 每 worker 单例懒加载与缓存；
- 并发请求 GPU generation lock；
- Episode 中记录真实 checkpoint identity；
- 默认仍为 API，因此不会改变当前用户主链。

在 GPU 环境中验证配置实际返回 `LocalCheckpointAgentPolicy` 且同 worker 复用同一实例。

## 四、App Agent 分支实跑及暴露的问题

新增 `scripts/smoke_local_app_branch.py`。它不是另建一个简化 Agent 环境，而是调用 App 使用的 `run_agent_branch`，只把外部实时工具换成版本化快照，以保证可重复。

第一次运行误用了系统 Python，缺少 `pydantic`。改用训练虚拟环境后，模型完成了全部动作，但 Solver 结果投影失败：

1. 首先缺少 `langgraph`；
2. 安装最小 LangGraph 后，又因为 `graph/__init__.py` eager import 整套数据库编排而要求 `sqlalchemy`；
3. 根因不是模型，也不是 Solver，而是复用纯投影函数时被 Python 包初始化拉入无关依赖。

解决方式不是在 Agent 分支吞异常或复制一份投影逻辑，而是把 `graph` 公共 API 改为 `__getattr__` 延迟导入：

- 既保持 `from graph import build_graph / AgentState` 兼容；
- 又允许 `graph.node_impl` 在轻量推理环境中独立导入；
- 新增 lazy import 与公共 API 回归测试；
- 相关回归 32 项通过。

最终 GPU 实跑结果：

- policy：`grpo-qwen25-3b-aligned-learnable-step1`；
- App 分支状态：`awaiting_confirmation`；
- stage：`agent_draft_ready`；
- 动作完整经过 capability、天气、搜索、详情、矩阵、求解、校验、草案和 finish；
- `hard_pass=true`；
- 生成 1 天前端行程；
- Episode policy identity 和 content hash 均被保存；
- 无 fallback。

这证明 checkpoint 已与生产 Agent Loop、Controller-first 职责、Solver、Validator 和前端行程投影契约连通。它仍不是完整 HTTP/UI 部署或线上灰度。
