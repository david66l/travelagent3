# 阶段 16：Qwen3-8B 底模升级 A/B 评估

日期：2026-08-14

## 1. 目标

判断阶段 15 剩余的 adaptive recovery 失败是否已经属于 Qwen2.5-3B 的模型能力瓶颈，以及升级到 Qwen3-8B 是否比继续微调 3B 更有价值。

本阶段先做零训练、同协议 A/B。只有新底模在未微调状态下通过小门，才扩大正式评估；不会直接替换当前 checkpoint，也不会在结论产生前启动 SFT/GRPO。

## 2. 现有失败重新归因

R3 + Qwen 原生外壳约束在 adaptive recovery 正式集为 33 / 48，剩余 15 个失败全部具有相同结构：

1. 首次 `search_pois` 使用两个用户兴趣词；
2. 工具返回 `QUERY_TOO_BROAD`；
3. 可见错误消息明确要求只保留其中一个已知关键词重试；
4. 模型第二次仍原样重复两个关键词；
5. 环境以 `SNAPSHOT_ARGUMENT_MISMATCH` 拒绝重复动作。

失败例：用户兴趣为 `["亲子", "公园"]`，工具明确返回“请保留用户已提供的关键词‘公园’，并仅用该关键词重试”，但模型再次提交 `["亲子", "公园"]`。

这 15 个失败中：

- policy output error：0；
- JSON/schema error：0；
- unknown argument error：0；
- protected argument error：0；
- 全部是读取工具反馈后没有改变策略。

最困难的 `["地标", "历史"] -> ["历史"]` 组合在 R3 训练集已有 41 条同类 adaptive 样本，但正式评估仍失败 11 / 12；因此问题不能简单归因于“训练数据没有覆盖”。R2/R3 还显示继续增强 recovery 会与 clarification 保持发生拉扯，符合小模型容量/稳定性不足的表现。

## 3. 候选模型选择

当前底模为 `Qwen/Qwen2.5-3B-Instruct`，3.09B 参数。首个升级候选选择 `Qwen/Qwen3-8B`，而不是直接使用 14B/27B：

- 8.2B 参数，仍为纯文本 Causal LM；
- 官方 chat template 原生支持 `<tool_call>` JSON 工具协议；
- 支持 `enable_thinking=False`，可与当前低延迟 policy 协议对齐；
- 官方说明 Qwen3 相比 Qwen2.5 加强 instruction following、multi-turn 与 agent/tool 能力；
- RTX 4090 24GB 可以用 NF4 执行同条件评估，并保留后续 QLoRA 的可行性；
- 比 Qwen3.5-9B 的原生多模态架构迁移面更小，适合作为第一项受控实验。

官方依据：

- [Qwen3-8B model card](https://huggingface.co/Qwen/Qwen3-8B)；
- [Qwen3 release](https://qwenlm.github.io/blog/qwen3/)；
- [Qwen2.5-3B-Instruct model card](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct)。

Qwen3.5-9B 保留为第二候选。官方报告其 BFCL-V4 为 66.1，并强调大规模 Agent 环境训练，但该模型包含视觉编码器和新的 hybrid attention，实现/部署改造更大，本阶段不先引入额外变量。

## 4. A/B 协议与预注册门槛

Qwen3-8B 使用与阶段 15 完全相同的：

- curriculum corpus 与 split；
- task selection / family offset；
- rollout seed 协议；
- temperature；
- group size；
- NF4 double quantization；
- state-scoped JSON Schema；
- `qwen_tool_envelope` 生成时约束；
- strict parser 与 unknown/protected argument 硬门。

执行顺序：

1. tokenizer / chat-template 协议检查；
2. 两个固定历史语法失败的小样；
3. adaptive recovery 4×4 小门；
4. 小门通过后跑 adaptive recovery 12×4；
5. 再跑固定 curriculum 能力门；
6. 记录成功率、分能力结果、policy/schema 安全错误和 mean/p50/p95 latency。

升级值得继续的判断标准：

- adaptive recovery 至少明显超过 R3 的 33 / 48；
- 目标参考为不低于 42 / 48（87.5%）；
- fixed curriculum 不出现能力族回退；
- unknown/protected argument error 必须为 0；
- 延迟必须单独报告，不用成功率掩盖成本。

若零训练 Qwen3-8B 没有明显超过 R3，则不因为参数更大就迁移；若通过，下一步才设计数据迁移和小步 QLoRA，而不是复用不兼容的旧 adapter。

## 7. 分级小门

### 固定 clarification 烟测

使用历史固定失败任务、seed 44、temperature 0.8、NF4 与 Qwen envelope：

- 4 / 4 成功；
- policy/schema/unknown/protected argument error 均为 0；
- mean latency 1461.139 ms；
- p95 latency 2443.734 ms。

### Adaptive recovery 4×4

使用与 R3 smoke 完全相同的前 4 个 recovery 任务、seed 42、temperature 0.7：

| Arm | 成功 | 成功率 | Mean | P95 |
|---|---:|---:|---:|---:|
| R3 + envelope | 15 / 16 | 93.75% | 2985.438 ms | 3386.735 ms |
| Qwen3-8B zero-shot + envelope | 16 / 16 | 100% | 2203.832 ms | 2542.008 ms |

小门通过，允许扩大正式评估。

## 8. Adaptive recovery 正式 A/B

协议：12 tasks × 4 rollouts、seed 42、temperature 0.7、NF4、最多 4 次 tool-calling iteration、同一 Qwen envelope 约束。

| Arm | 成功 | 成功率 | Mean | P95 |
|---|---:|---:|---:|---:|
| Qwen2.5-3B B0 | 10 / 48 | 20.83% | 3049.772 ms | 3618.110 ms |
| Qwen2.5-3B R3 | 33 / 48 | 68.75% | 3029.356 ms | 3488.494 ms |
| Qwen3-8B zero-shot | 48 / 48 | 100% | 2180.139 ms | 2196.979 ms |

Qwen3-8B 在没有 TravelAgent 微调的情况下：

- 相对 R3 提升 31.25 个百分点；
- 相对 B0 提升 79.17 个百分点；
- R3 最薄弱的 `["地标", "历史"] -> ["历史"]` 组合全部按反馈恢复；
- policy output / policy argument / unknown argument / protected argument error 全为 0；
- mean 和 p95 均明显低于两个 3B arm。

该结果确认阶段 15 剩余失败的主要瓶颈是 Qwen2.5-3B 的多轮工具反馈适应能力，而不是环境、schema 或 decoder。

## 9. 固定 curriculum 正式门

协议：32 tasks × 4 rollouts、每能力 8 tasks、family offset 2、seed 44、temperature 0.8、NF4、同一 Qwen envelope。

Qwen3-8B zero-shot：

- clarification：32 / 32；
- recovery：32 / 32；
- search：32 / 32；
- tradeoff：32 / 32；
- 总计：128 / 128；
- mean latency：1602.554 ms；
- p95 latency：2229.020 ms；
- policy/schema/unknown/protected argument error 全为 0。

因此 Qwen3-8B 没有用 adaptive 提升交换旧能力，满足预注册能力门。

## 10. 决策与边界

结论：`Qwen/Qwen3-8B` 被选为下一阶段底模迁移候选。该结论比“继续给 3B 加训练数据”更强，因为未经 TravelAgent 微调的新底模已经在相同协议下达到 48 / 48，并且延迟更低。

但本阶段仍不做以下动作：

- 不直接修改线上默认模型；
- 不把零训练离线结果写成生产晋升；
- 不复用 Qwen2.5-3B LoRA adapter；
- 不启动 GRPO；
- 不删除 B0/R3 权重和证据。

下一阶段先做迁移工程，而不是训练竞赛：

1. 检查 Qwen3 SFT/GRPO target modules、chat template 与数据消息协议；
2. 以零训练 Qwen3-8B 作为新的强基线；
3. 只有 SFT 能在不降低 48 / 48 与 128 / 128 的情况下增加未覆盖能力时才保留；
4. 升级并固定 vLLM，完成 required tool call 的服务端结构化约束；
5. 跑新 offset/seed、并发吞吐和 shadow traffic 门。
