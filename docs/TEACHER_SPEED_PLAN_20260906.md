## 已核实的限制

当前客户端固定 `reasoning_effort=max`、`stream=false`，每请求输出上限 8192、读取超时 180 秒，4 条轨迹并发。本批中途检查时，已记录输出的最大长度达到 6655 token；不能直接把上限缩到几百 token 后仍宣称监督质量不变。

官方文档明确 GLM-5.3-Flash API 支持 `max/high/low`，不支持关闭思考。下一轮优先比较 `max` 与 `high`；该参数存在不代表本项目已经验证提速或质量不变。[智谱深度思考文档](https://docs.bigmodel.cn/cn/guide/capabilities/thinking)

## 实验顺序

1. **推理强度**：选择同一批 train 来源的完整示范和真实接手任务，分别运行 max/high，冻结环境、起点、剩余工具预算、温度和并发。按预注册顺序交错派发，记录 API 时间、输出 token、任务成功、原目录硬约束和最终可训练动作数。所有失败计入分母和原总账；不为了选中成功结果重复抽样。
2. **队列异常处理**：当前单次供应商错误会停止派发并等待在途任务完成。本批已暴露这种机制的吞吐损失。下一版本区分单请求失败、账户限流、身份验证/预算错误和持续供应商故障：单请求失败保留失败测量，剩余新任务可继续；限流遵循服务端重试信息；认证或预算异常立即停止。持续故障采用窗口阈值熔断。必须先用模拟客户端测试并发、断点恢复和费用计提，再实际运行。
3. **并发**：先核对账户额度，再做 4 路与更高并发的同任务对照；同时检查 429、超时和 p95，不能只看平均吞吐。单任务的工具依赖仍按顺序执行。
4. **传输**：流式响应可提供首 token/心跳与分阶段延迟，但不能声称它提升模型生成速度。若实现，必须完整保存工具调用片段、结束状态和 usage；中断、缺 usage、截断都不能静默导出为成功标签。
