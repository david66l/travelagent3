# TravelAgent2 描述质量 + 用餐优化方案 v2

## 根因分析

当前输出"推荐游览XXX"的原因是：LLM enrich 成功生成了文本（没走到 fallback），但 LLM 不了解景点细节，只能生成通用描述。需要改策略：**已知景点直接用模板（省 token + 保证质量），未知景点才让 LLM 发挥。**

---

## 🔴 P0: 已知景点跳过 LLM，直接使用模板描述

**文件**: `backend/src/planner/core/writer.py`

**问题**: LLM prompt 要求生成推荐语，但对不熟悉的景点只能输出"推荐游览XXX"
**方案**: 在 `_llm_enrich_day_batch()` 之前预检查：如果 `activity.poi_name` 在 `_REASON_TEMPLATES` 中，直接从模板生成，不送 LLM。

修改 `enrich()` 函数：
```python
# 在调用 LLM 之前：
for day in itinerary:
    for act in day.activities:
        if act.poi_name in _REASON_TEMPLATES:
            act.recommendation_reason = _REASON_TEMPLATES[act.poi_name]
            day.has_prefilled = True
    # 只把未预填的 activity 送给 LLM
    if not all_prefilled(day):
        await _llm_enrich_day_batch(day, profile)
```

**效果**: 已收录景点（故宫/西湖/灵隐寺等 50+）100% 保证优质描述，且省 LLM Token

GENERIC_PATTERNS = ["推荐游览", "值得一游", "口碑推荐", "推荐", "不错的地方"]
for item in result["activities"]:

## 🟡 P5: 餐厅 POI 合并

**文件**: `backend/src/planner/core/daily_scheduler.py`

**问题**: "Lunch(11:30-13:00) ¥80" + "盐水鸭(13:00-14:00) ¥40" → 两顿紧挨着
**方案**: `_create_meal_activity()` 匹配到真实餐厅 POI 时，不再额外插入通用 Lunch，而是把餐厅 POI 当作正餐，在其之前或之后不再插入午餐窗口。
