**终止契约已修复并同步云端。最新 8 题定向复测：Qwen3-4B 基模合理停止 2/4，GLM-5.3-Flash 教师 4/4；有效行程分别 1/3、2/3，必要澄清均 1/1。这是系统修复验证，没有更新模型权重，也没有新的后训练收益。**

## 1. 修的是什么问题

原来系统会把“当前行程遗漏必去景点”统一标为还可以解决；奖励又要求任务已被证明不可行，才认可停止。因此，即使博物馆全天闭馆、必付门票已经超出预算，模型也可能永远拿不到正确停止的分数。

现在把两个问题分开判断：

- **这份行程合不合格？** 由原来的行程校验器检查。空行程、漏景点都不能通过。
- **现有事实是否足以证明要求无法同时满足？** 新的证据检查只认可两种充分条件：必去场馆在全部旅行日期明确闭馆；必去项已知门票的合计下界超过硬预算。没找到景点、一次求解失败、推测博物馆每周闭馆，都不等于证明无解。

详情到达后，Harness 自动核验上述事实，把理由和证据 ID 交给模型。模型可以直接引用证据停止，也可以继续查证；不再暗中要求先走“矩阵 → 求解 → 校验”才能停止。模型仍负责选动作，代码负责检查事实和权限。

旧证据随输入变化失效；伪造、缺失或过期的引用不能授权停止。折中选项只能来自用户已声明的可放宽范围。证据 ID 能核验停止依据，不能自动证明任意自然语言解释都正确，所以训练示范仍要审查解释文本。

## 3. 还没解决的问题

Qwen 两个闭馆案例拿到搜索正文后直接问是否调整行程，未取得本轮停止契约要求的可核验证据，也没有针对用户已锁定的日期和必去项作出合格处理。查询与过期证据案例仍会反复调用同一搜索。这些失败应进入后续学生错误分析，不能靠奖励放水改成成功。

餐厅检索仍返回景点或泛化结果，教师会因此反复补查；这个环境缺陷尚未修复。相关过期证据失败也不能简单全部归为模型能力不足。当前运行不代表真实旅游服务的可用性。

- Qwen `evidence-01`：`policy_error_fallback`；动作：search_current_info → solve_itinerary → search_current_info → search_current_info。

## 4. 怎么验证的

- 本地相关回归：637 通过、5 跳过；增加反事实详情更新及每周闭馆假设不算证明的测试。
- 本地较广单元测试：1269 通过、5 跳过、21 取消选择；排除 API 和数据库范围。首次较广测试有一个价格回退测试因本地已配置联网凭据而返回 API 数据；临时清空该进程的 `TAVILY_API_KEY` 后离线测试通过，未修改价格业务代码或永久配置。
- 云端相关回归：488 通过、1 跳过。两端依赖与可执行测试集合不同，因此数量不同。
- 48 条对照轨迹重新做哈希回放、统一判分和真实工具/求解次数核账。凡提交有效行程，均对真实求解输入和输出再次独立校验；新版合理停止的引用还与原始案例日期、费用重新计算的证明比对。
- 第一、第二轮执行源码各保存独立哈希快照；同轮 Qwen 与 GLM 共用文件的哈希一致。未重新加载训练适配器、未开始 SFT/GRPO、未修改原始结果。

回归中的脚本策略只用于证明系统路径可达，绝不计入上表的模型成绩。

另外逐条阅读了最新 6 条成功停止回复，事实理由均与案例相符；GLM 的一个闭馆解释包含 `candidate`、`infeasible` 等内部术语，不能直接当作面向用户的优质文字示范。此项为本次人工阅读，不是独立盲审，记录在 `terminal-reason-review.json`。

## 5. 运行设置与成本证据

研究工具使用固定合成数据，矩阵、求解器和校验器实际运行。预先提供用户约束，不测意图解析。Qwen 用真实 `/root/autodl-tmp/models/Qwen3-4B` 基础权重，不思考、贪心解码；GLM 用智谱国内站实际 API，返回模型标识以原始响应为准。

两者均为最多 24 步、24 次实际工具调用、3 次实际求解、32000 输出 token。Qwen 每题 120 秒；GLM 开启 max 思考，每题 600 秒，单请求 180 秒、8192 输出 token，并使用每轮一个调用的协议提醒。这是同架构能力诊断，不是等算力对照。

## 6. 下一步做什么

**下一件具体工作是修好示范数据环境，再采集独立示范。**

1. 餐厅查询返回真实匹配的餐厅记录，包含位置、营业时间、价格和来源；无结果就返回无结果。事实冲突、过期、错误查询应分别定义，不能把 fixture 错误当模型考题。
2. 另建首批 20–30 条训练任务，按实体和场景模板与这 24 条开发诊断隔离，覆盖补证据、改写过期查询、冲突处理、故障恢复和及时提交。
3. GLM 从任务起点自主运行；只保留同一 Harness 执行通过、参数有来源、解释经审核的示范。再让 Qwen 自主跑这些任务，收集它实际遇到的失败状态做局部纠错。
4. 通过数据质量检查后再做小批 SFT，以相同环境和独立 dev 对照判断小模型有没有真正变好。当前不能宣称已经达到某个“大厂评分”。
