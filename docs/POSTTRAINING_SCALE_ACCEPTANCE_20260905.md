# TravelAgent2 规模化后训练与工程验收

版本：scale-program.v1，2026-09-05。状态：正式建设目标已确定，规模化数据、训练及生产验收尚未完成。

用户要求面向大厂社招，将项目做成可复现、可解释、可运行的 Agent 后训练项目。下列规模是本项目选定的建设目标，不是招聘行业统一门槛，也不代表达到数量就能证明能力。后训练实验为主线，服务运行能力作为必要交付。

## 1. 已核实的起点

- 当前 Harness：evidence-progress-retry-v9；学生模型：Qwen3-4B 加首轮 SFT adapter。
- 新 train 学生 20/24；教师真实状态续跑集合 12/12，导出 60 个动作、1,346 个监督 token。新任务仍属于六个已有训练场景组，不能算独立结构扩充。

- v9 agentic + evaluation 云端回归 644 passed、2 skipped；该数字不是生产完整链路或模型质量验收。
- 当前训练交互到 ask_user 会暂停，完整用户回复、修改、恢复和最终确认需要显式脚本及同一会话的端到端验证。
- 旧 INDUSTRIAL_READINESS.md 的生产候选、压测及发布证据属于旧架构，不能沿用为 v9 已验收。

## 2. 正式规模目标与计数口径

| 资产 | 目标 | 必须同时满足的质量条件 |
|---|---:|---|
| train 独立任务实例 | 2,000–5,000 | 至少 40 个会改变正确决策条件的结构组；改城市、改名字、措辞改写不增加结构组计数 |
| 可训练动作 | 20,000–60,000，按真实轨迹统计 | 是观察目标，不为凑数增加步骤；同时报告实际监督 token、独立任务和结构组数 |
| 学生状态纠错 | 500–1,500 个独立源任务的续跑起点 | 同任务多个 step 单列相关性；保留源状态、预算、工具计数、错误归因和失败尝试 |
| dev | 300 个独立任务 | 从分组隔离的场景来源构建；调参、选模型与消融只在这里完成 |
| 正式 locked test | 500 个独立任务 | 300 个同类新实例、200 个未见结构组合；在模型选择前锁定并记录访问，保持隐藏判据与答案隔离 |
| 故障与越权专项评测 | 200 个独立任务 | 与正式 test 分开汇报；包括恢复、取消、证据失效、提示注入与权限边界 |
| 真实工具验证 | 100–200 个独立任务 | 记录真实只读工具响应、时间及来源；模拟、录制回放、实时请求分别报告 |
| 核心训练对照 | 3 个训练种子 | 与推理重复分开；训练数据、环境、起始权重、实际监督 token 和预算可比 |

任务、动作、token、源任务组、工具快照来源组分别计数，不能混用。dev/test 及其同源派生不进入训练。旧八题 dev 继续作诊断回归，旧 locked test 保持历史冻结，不冒充新增五百题验收。正式测试的所有预选 checkpoint、推理重复次数和比较指标在揭盲前登记；一旦根据 test 调整模型，该集合必须降级为 dev。

## 3. 需要补齐的场景覆盖

至少覆盖以下十二类能力，组合时改变事实、可行动作或成功条件，不强制模型遵循唯一工具顺序：

1. 候选与详情依赖：缺候选、空搜索结果、别名和候选更新。
2. 实体证据新鲜度：A 过期/B 新鲜、同名异地、证据只覆盖部分日期。
3. 来源冲突：详情与公告冲突，来源时间不同，无法判定时继续研究或澄清。
4. 时间与出行：跨日到达、演出时间窗、交通取消、不同出发地。
5. 预算与不可行：成本下界超预算、当前求解失败但尚无不可行证明。
6. 必去与偏好冲突：硬约束保持、偏好让步需用户授权，不能静默放宽。
7. 用户补充与修改：询问后回复、日期/预算/必去项修改，同会话继续。
8. 证据和产物失效：目标版本更新，矩阵、行程或验证过期，重新提交。
9. 工具故障：超时、限流、空结果、格式损坏、恢复后重试；基础设施故障与策略错误分开。
10. 冗余与无进展：重复查询、不同措辞但同一证据、必要二次查询不能误罚。
11. 权限与不可信内容：工具结果含指令、诱导更改约束、伪造确认、跨会话污染。
12. 会话生命周期：暂停、恢复、取消、重复请求、进程重启、用户确认后状态一致。

其中多轮交互、动态工具故障和真实工具录制必须先补执行支持；不能给现有单轮模板贴新标签宣称已覆盖。先声明 source_group / lineage_group / snapshot_group 的拆分规则，再创建数据；隐藏测试期望不出现在模型可见环境中。

## 4. 按门槛推进的执行批次

| 阶段 | 具体工作 | 出口条件 |
|---|---|---|
| M0：扩充基础与成本测量 | 设计 96 条结构覆盖试产任务；实现缺失的多轮/故障执行能力；补等 token 普通示范对照；测量教师及学生实际成本 | 可执行场景矩阵、数据来源契约、逐类通过/拒绝原因、每条接受轨迹的成本；不是正式规模交付 |
| M1：首批正式数据 | 分批完成 500 条独立 train 任务和 300 条隔离 dev；建立新 test 的来源隔离与冻结流程 | 每条接受轨迹执行、重放、独立约束和标签审计通过；分层人工抽查至少 100 条并记录审核者，不能用模型审查冒充人工 |
| M2：规模 SFT 与纠错 | 按 500→2,000→5,000 画学习曲线；到质量/收益平台期可有依据停止；主要配置三个训练种子 | 普通增量与定向纠错的等监督 token 对照、置信区间、分场景失败、成本和回归均可解释 |
| M3：RL 试验 | 先对训练任务每题采样 4–8 条完整轨迹，测组内方差、基础设施噪声、奖励漏洞；达到条件再做 GRPO | 行为策略/旧 logprob/动作 mask/工具响应边界核对；有效分组数、KL、熵、梯度及成本可追踪；允许记录 RL 无收益 |
| M4：独立验收与云端服务 | 按预登记协议运行 locked test、专项与真实工具任务；部署候选服务并作故障恢复、分级压测和持续运行 | 完整实验包、发布/回滚演练、实测容量与 SLO、24 小时以上稳定运行记录；无真实用户时明确为云端受控运行 |

质量门槛未通过就修复或降低批次，不用重复模板填满目标。普通示范和纠错的首批对照可以与扩充执行能力并行推进，但未经验证的 exporter、reward 和环境版本不能直接用于大批采集。

## 5. 实验与评测验收

- 主对照：基模、原 SFT、等预算普通增量 SFT、纠错 SFT；GRPO 以同一 SFT 起点作额外对照，DPO 非必需。
- 冻结 Harness、工具接口、状态投影、参考时钟、fixture、模型模板和判分器。系统修复后各组重跑；不把 Harness 收益写成模型训练收益。
- 记录预处理后的 labels、无截断比例、监督 token、数据顺序、梯度累积、优化器步数、实际训练曝光量。匹配不了的变量逐项说明。
- 推理使用匹配的任务、环境与故障随机种子，并做重复尝试。报告首次成功率，以及同任务重复多次全部成功的可靠性指标；不以多次择优掩盖不稳定。
- 报告任务原始计数、分层/按来源组的置信区间和成对差值。每个 checkpoint 不视为独立任务样本。三个训练种子与三次推理不是一回事。
- 规划完成、必要澄清、证据充分的不可行停止分别计分；完整多轮任务需要用户回复后继续直到真实目标终态。
- 效率比较优先使用两模型都成功的配对任务，另报整体每个成功任务成本和失败成本，避免通过提前放弃获得低延迟。
- 结果类指标：完整任务成功、硬约束、恢复、不必要提问、重复调用、越权、证据引用。成本类指标：输入/输出/思考 token、教师失败尝试、GPU 时间、工具费用、P50/P95/P99、队列等待。
- 严重越权、伪造用户确认、隐瞒硬约束失败是发布阻断项；测试中未观察到不等于总体风险为零。
- 事先定义有实际意义的改进，例如成功率差的置信下界大于零且关键类别不退化，或保持质量下显著降低成本。若证据不足，保留候选，不反复调到“好看”为止。

## 6. 云端运行与可复现性

建立幂等任务队列、分片采集、限流、退避、断点续跑、失败隔离、逐次计费和预算自动停止。限额包括最大任务数、模型请求数、输出 token 和运行时间；未知单价必须标记未知，不能记成零。重试费用计入总成本，教师服务失败与模型策略失败分别记录。

每个运行保存 run_id、数据/代码/权重/模板/镜像哈希、依赖锁、解码与种子、教师配置、每任务终态、原始错误和重放命令。训练器数据预处理后的真实 mask、策略 logprob、参考模型、断点恢复、有效参数更新需在实际训练配置中验证。

先在现有云机测量推理容量，再决定是否需要独立推理节点或多卡。数据和大模型不下载本地；本地只做轻量编辑、SSH 与小型摘要。nvidia-smi 的产品名或显存不能替代真实训练峰值显存测量。

服务侧先做 1/2/4/8 并发阶梯测量，再根据饱和点决定更多并发和隔离部署。区分 HTTP 接入、模型 token 生成和完整 Agent 任务吞吐；控制面压测不能冒充模型端到端容量。分别测冻结工具和真实 provider 限额下的性能，不要求单卡凭空达到 100 路有效规划。

SLO 在初次容量测量后冻结，包含队列等待、完整任务延迟、基础设施错误率和恢复时间；24 小时测试在已验证的持续负载下运行。演练 worker 重启、队列重投、SSE 断线、取消、超时和模型版本回滚。部署脚本或 K8s YAML 存在不算部署验收。

## 7. 本次落地与立即下一步

本次新增本验收方案和机器可读建设配置，更新检查点、后训练方案与工业化状态说明，并只读核查现有云资源。没有新增租机、没有启动规模化付费采集，也没有将计划写为已完成结果。

第一批应交付：96 条试产任务的结构定义与可执行环境支持、隔离 dev 的构建规则、等 token 普通示范对照、分片采集的成本/失败报告。96 条是进入规模阶段的门槛，正式目标仍是数千条独立任务及完整验收。

用户已明确教师使用 GLM-5.3-Flash，每批 API 费用上限 100 元；教师、审查与重试等本批模型 API 开销合并计入上限，不通过拆分批次规避预算。云端算力另计，新增租机预算尚未确定。批量调用前必须核实实际端点价格与计费 token，设置余量和停止阈值；不能承诺 100 元必然完成全部规模。先审查可复用的公开数据与环境，再将教师预算投入接口适配和学生失败纠错。

## 方法参考

评测采用结果状态、完整轨迹、多次尝试与多种判分方式，并区分能力与回归评测，参考 [Anthropic Agent 评测实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。完整工具与用户交互及重复可靠性参考 [τ-bench](https://arxiv.org/abs/2406.12045)。以用户体验指标定义服务目标、根据误差预算安排可靠性工作，参考 [Google SRE：Implementing SLOs](https://sre.google/workbook/implementing-slos/)。上述来源支持验收方法，不为本方案的数据量或招聘评价背书。
