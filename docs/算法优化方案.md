# TravelAgent2 规划算法优化方案

## 🔴 Bug 修复

### B1. 缓存命中跳过远程检测
**文件**: `backend/src/pipeline/planning_pipeline.py`
**问题**: L87-106 缓存命中后直接使用 cached_draft，跳过了 POI 收集和远程检测逻辑
**修复**: 缓存命中后仍需加载 POI 并运行远程检测（cross_city/half_day/full_day），过滤后再用缓存
**影响**: 千岛湖被错误安排的根本原因

## 🟡 算法优化

### A1. POI 分组：行政区 → 坐标聚类
**文件**: `backend/src/planner/core/daily_scheduler.py`
**当前**: `_group_pois_by_area()` 按 `poi.area`（行政区）分组
**改进**: 新增 `_group_pois_by_proximity()`，用 DBSCAN/Hierarchical 聚类实际坐标
  - 距离阈值 3km 内聚为一组
  - 优先用聚类结果，area 作为 fallback
  - 解决「跨行政区但相邻」的 POI 被分到不同组的问题

### A2. 路径优化：Greedy NN → NN + 2-opt
**文件**: `backend/src/planner/core/daily_scheduler.py`
**当前**: `_nearest_neighbor()` 从 index=0 固定起点，贪心选择
**改进**: 
  - 多起点尝试（每个 POI 作为起点），选最短路径
  - 加 2-opt 局部搜索（交换两条边看是否缩短总距离）
  - 路由 < 5 个点时用多起点 NN，≥ 5 个点加 2-opt
  - 新增 `_optimize_route_2opt()` 函数

### A3. 用餐匹配真实餐厅
**文件**: `backend/src/planner/core/daily_scheduler.py`
**当前**: `_create_meal_activity()` 生成通用 "Lunch ¥80"
**改进**:
  - 查找 POI 列表中 category=="restaurant" 的项
  - 按用户 food_preferences 匹配标签
  - 按当前地理位置排序（最近优先）
  - 找不到餐厅时才用占位符
  - 早餐/午餐/晚餐都有真实餐厅推荐

### A4. 描述丰富化
**文件**: `backend/src/planner/core/writer.py`
**当前**: `_template_reason()` 只有 15 个知名景点，其余全是「推荐游览XXX」
**改进**:
  - 扩展 `_REASON_TEMPLATES` 到 50+ 常见景点
  - 增加杭州景点：西湖/灵隐寺/雷峰塔/三潭印月/断桥残雪/龙井村/西溪湿地/宋城/岳王庙/九溪烟树
  - 默认描述从 tag 生成：「{poi_name}，{category}景点，适合{tags[0]}、{tags[1]}」
  - 不再输出「推荐游览XXX」这种无意义描述

### A5. 日多样性检查
**文件**: `backend/src/planner/core/daily_scheduler.py`
**新增**: `_ensure_daily_diversity()`
  - 同一天内不超过 2 个同类型 POI（如不要 3 个寺庙）
  - 超过时用下一个同分异类型 POI 替换
  - 在 `_assign_days` 完成后调用

### A6. 预算包含交通和住宿预估
**文件**: `backend/src/planner/core/daily_scheduler.py`
**当前**: `day.total_cost` 只含门票+餐费
**改进**: `_build_day_plans` 结束时增加：
  - 交通估算：市内 ¥30/天，含远程景点按距离加计
  - 住宿估算：按 travel_days-1 晚 × ¥200/晚 = ¥400
  - 追加 summary 行展示完整预算
