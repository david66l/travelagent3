# TravelAgent 架构优化方案 v5

> **目标**：把"同步阻塞的大模型黑盒"改造成"异步分层的生产级 Agent 系统"
> **核心原则**：API 只负责会话和任务控制；后台工作流负责规划执行；LLM 定策略和表达（权重受限），程序负责排程与硬约束（可审计）；DB 是唯一事实源，Redis 只是通知；结构化行程先返回，Critic 不阻塞，文案流式增强。
> **验收标准**：P50 < 25s，P90 < 45s，TTFI（首版行程草稿）< 10s，P99 可降级返回结构化行程

---

## 一、当前架构根因诊断

### 1.1 真正的问题不是"LLM 慢"，而是"请求协程被长任务独占"

```
当前真实链路：

用户请求
  ↓
FastAPI WebSocket handler（单个协程）
  ↓
await graph.ainvoke(...)   ← 占用协程 90s+
  ↓
一次性返回结果
```

**后果：**
- 一个用户规划行程，占用一个 API worker 协程 90 秒
- 并发 10 个用户，10 个协程全被占满，新用户连不上
- 前端 90 秒看不到任何进展，只能显示"正在思考…"
- LLM 超时、搜索超时、DB 慢查询，任一环节失败就全盘崩溃
- 没有取消机制：用户关闭页面，后端继续跑完 90 秒

### 1.2 各节点真实耗时（非内置城市，无缓存）

| 节点 | 当前实现 | 真实耗时 | 风险点 |
|------|---------|---------|--------|
| intent_node | LLM structured_call | 1-3s | 低 |
| prepare_context_node | 程序逻辑 | <10ms | 无 |
| poi_search_node | 内置 fallback / Tavily + LLM 提取 | **0s / 5-15s** | **尾延迟可控** |
| weather_node | 模拟数据 + 可选后台搜索 | <1ms | 无 |
| budget_init_node | 程序逻辑 | <10ms | 无 |
| planner_node | LLM 一次性输出完整行程 JSON | **30-90s** | **最大瓶颈** |
| validation_node | 规则校验 + POI existence 搜索 | 0.5-10s | **搜索采样慢** |
| route_node | 算法优化 | <100ms | 无 |
| proposal_node | LLM 写 Markdown 文案 | 5-15s | 中等 |

**诊断结论：**
- POI 搜索：已修复（内置 fallback + 15s 超时）
- Planner：单次 LLM 调用承担过多（理解 + 排时间 + JSON + 预算 + 路线 + 推荐理由）
- Validation：不是 LLM，是规则 + 搜索采样，搜索慢会拖住
- **根因**：所有节点串行在**同一个 API 协程**里跑，没有任务隔离

## 二、新架构总览

### 2.1 两层架构：API 层 + 执行层

```
┌─────────────────────────────────────────────────────────────┐
│  API 层（FastAPI + WebSocket）                                │
│  - 接收用户消息                                               │
│  - 创建 planning_job                                          │
│  - 推 job stage 状态到前端                                    │
│  - 接收用户取消/修改指令                                      │
│  - 返回结构化行程 + 流式文案                                  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼ 创建 job，立即返回 job_id
┌─────────────────────────────────────────────────────────────┐
│  执行层（后台 Worker / 异步任务队列）                          │
│  - 从 job queue 取任务（DB lease + SKIP LOCKED）              │
│  - 按阶段执行 PlanningPipeline                                │
│  - 每完成一阶段，写入 job_event                               │
│  - 通过 Redis pub/sub 通知 API 层推送                         │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 执行层 Pipeline

**Phase 1（P0）Pipeline：**
```
[Stage 1] Supervisor LLM（1-3s）
  输入：用户消息 + 历史上下文
  输出：{intent, destination, days, budget, interests, tasks_needed[], missing_recommended[]}
  动作：创建 job，写入数据库

[Stage 2] 数据收集（0-5s，并行）
  并行执行：
    - POI Agent：内置 fallback → Tavily 增强（15s 超时）
    - Weather Agent：模拟数据（<1ms）
    - Memory Agent：查用户历史偏好
    - City Info Agent：查交通/消费水平
  输出：{pois[], weather[], memory{}, city_info{}}
  动作：写入 job_event

[Stage 3] Strategy LLM（3-5s）
  输入：用户需求 + 收集的数据
  输出：PlanningStrategy
    {
      theme: "行程主题",
      must_include: ["景点A", "景点B"],
      optional: ["景点C"],
      avoid: ["景点A和B同一天"],
      grouping_rules: ["区域X集中", "雨天室内优先"],
      pace: "moderate",
      daily_activity_target: 3,
      indoor_outdoor_balance: "auto"
    }
  动作：写入 job_event

[Stage 4] Planning Core（<100ms，程序）
  输入：Strategy + POI 数据 + 天气 + 硬约束
  算法：
    1. 按 final_score 排序筛选 POI
    2. 按 grouping_rules 分组到天数
    3. 按 recommended_hours 排时间段
    4. 插入餐饮（固定时段）
    5. 检查每天总时长 ≤ 12h
    6. 检查预算 ≤ 用户预算 × 1.1
    7. 雨天优先 indoor（程序做可枚举语义规则）
  输出：itinerary_draft（DayPlan[]）
  动作：写入 job_event

[Stage 5] Rule Validator（<10ms，程序）——强制门禁
  硬约束检查：
    - 时间冲突
    - 预算超标
    - 景点重复
    - 每天活动数超限
  输出：{passed, violations[]}
  动作：如有 violation，回到 Stage 4 重排；通过则推 itinerary_final

[Stage 6] LLM Writer（5-15s，流式）——Phase 1 简化版
  输入：itinerary_final + 用户需求
  约束：Writer 只引用和解释结构化行程的事实，不允许修改事实结构
  输出：自然语言文案（逐 token 流式返回）
  动作：流式推送 token，完成后 status = "completed"
```

**Phase 2（后续迭代）扩展：**
```
[Stage 5b] LLM Critic（3-5s，可选增强）——非阻塞
  输入：itinerary_draft + 用户需求 + POI 信息
  输出：CriticResult（机器可执行格式）
    {
      passed: false,
      issues: [
        {
          type: "too_rushed",
          severity: "high",
          day: 1,
          activity_ids: ["act_1", "act_2"],
          suggested_action: "remove_or_move",
          reason: "故宫和长城同天过赶"
        }
      ]
    }
  动作：
    - Critic 成功且有 issues → Repair Core → 更新为 itinerary_final
    - Critic 失败或超时 → draft 直接升级为 final，标记 critic_skipped: true
    - Rule Validator 通过后即可推送 draft，不因 Critic 阻塞

[Stage 5c] Repair Core（<100ms，程序）
  输入：CriticResult + itinerary_draft
  修复逻辑：
    - too_rushed → 移除低优先级 activity 或移到其他天
    - missing_must_include → 强制插入并重新排时间
    - bad_weather → 雨天 swap 到 indoor
    - budget_over → 移除高价 activity
  约束：修完后必须再跑 Rule Validator，避免修出新问题
  输出：itinerary_final
  动作：写入 job_event

[Stage 6] LLM Writer（流式）
  同 Phase 1，但输入可能是经 Critic/Repair 后的 final
```

**关键发布顺序（Phase 1）：**
```text
Planning Core 完成 + Rule Validator 通过 → 立即推 itinerary_final
Writer 开始 → 流式推自然语言说明（不改变结构）
```

**Phase 2 发布后顺序：**
```text
Planning Core 完成 + Rule Validator 通过 → 立即推 itinerary_draft
Critic/Repair 完成（如有） → 推 itinerary_final
Critic 失败/跳过 → draft 直接升级为 final，标记 critic_skipped
Writer 开始 → 流式推自然语言说明
```

### 2.3 三类流式输出

```
状态流（每阶段完成推送）：
  {type: "stage", stage: "data_collected", elapsed: 5.2}

结构化结果流（关键节点推送）：
  {type: "itinerary_draft", days: [...]}      ← Phase 1 就有
  {type: "itinerary_final", days: [...]}

内容流（Writer 逐 token 推送）：
  {type: "writer_delta", content: "第一天我们..."}
  {type: "writer_done"}
```

### 3.1 核心表

```sql
CREATE TABLE planning_jobs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id      VARCHAR(64) NOT NULL,
    user_id         VARCHAR(64) NOT NULL,
    user_input      TEXT NOT NULL,
    
    -- 当前状态
    status          VARCHAR(32) NOT NULL DEFAULT 'pending',
    -- pending / running / intent_ready / data_collected / strategy_ready / 
    -- draft_ready / critic_done / itinerary_final / writing / completed / failed / cancelling / cancelled
    
    -- 阶段耗时（毫秒）
    stage_timings   JSONB DEFAULT '{}',
    
    -- 中间结果
    intent_result   JSONB,
    strategy        JSONB,
    itinerary_draft JSONB,
    itinerary_final JSONB,
    proposal_text   TEXT,
    
    -- 错误信息
    error_message   TEXT,
    error_stage     VARCHAR(32),
    
    -- Worker 租约（防止 worker 崩溃后 job 永久卡死）
    locked_by       VARCHAR(64),     -- worker 标识
    lock_expires_at TIMESTAMPTZ,     -- 租约过期时间
    heartbeat_at    TIMESTAMPTZ,     -- 最后心跳时间
    attempt_count   INT DEFAULT 0,   -- 已尝试次数
    max_attempts    INT DEFAULT 3,   -- 最大重试次数
    last_error      TEXT,            -- 上次失败原因
    
    -- 用户交互
    user_feedback   JSONB,           -- 用户修改/确认记录
    version         INT DEFAULT 1,   -- 版本号，支持多轮修改
    
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    completed_at    TIMESTAMPTZ
);

-- 事件日志（每个 stage 的完整记录，前端订阅 + 审计）
CREATE TABLE planning_job_events (
    id          BIGSERIAL PRIMARY KEY,
    job_id      UUID NOT NULL REFERENCES planning_jobs(id) ON DELETE CASCADE,
    stage       VARCHAR(32) NOT NULL,
    event_type  VARCHAR(32) NOT NULL,  -- started / completed / failed / cancelled
    payload     JSONB,                  -- 阶段结果
    error       TEXT,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 行程版本（支持多轮修改 + 回滚）
CREATE TABLE trip_plan_versions (
    id          BIGSERIAL PRIMARY KEY,
    job_id      UUID NOT NULL REFERENCES planning_jobs(id) ON DELETE CASCADE,
    version     INT NOT NULL,
    days        JSONB NOT NULL,
    
    created_at  TIMESTAMPTZ DEFAULT NOW(),
    created_by  VARCHAR(32),  -- system / user / critic
    
    UNIQUE(job_id, version)
);

CREATE INDEX idx_jobs_session ON planning_jobs(session_id, created_at DESC);
CREATE INDEX idx_jobs_status ON planning_jobs(status, created_at);
CREATE INDEX idx_jobs_lease ON planning_jobs(status, lock_expires_at) 
    WHERE status IN ('pending', 'running');
CREATE INDEX idx_events_job ON planning_job_events(job_id, created_at DESC);
```

```

  ↓        ↓                                                    ↓
```

### 3.3 取消机制（DB 为事实源，Redis 为通知加速）

```python
async def cancel_job(job_id: str):
    """取消任务——DB 是 source of truth"""
    # 1. 更新 DB 状态
    await db.execute(
        """
        UPDATE planning_jobs 
        SET status = 'cancelling', updated_at = NOW() 
        WHERE id = $1
        """,
        job_id
    )
    # 2. Redis 发快速通知（可选加速）
    await redis.publish(f"job:cancel:{job_id}", "cancel")
    
async def mark_cancelled(job_id: str, worker_id: str):
    """Worker 确认取消并释放锁——必须调用"""
    await db.execute(
        """
        UPDATE planning_jobs 
        SET status = 'cancelled',
            locked_by = NULL,
            lock_expires_at = NULL,
            updated_at = NOW()
        WHERE id = $1 AND locked_by = $2
        """,
        job_id, worker_id
    )
    
async def check_cancelled(job_id: str) -> bool:
    """Worker 检查是否被取消——优先查 DB"""
    status = await db.fetchval(
        "SELECT status FROM planning_jobs WHERE id = $1", job_id
    )
    return status in ("cancelling", "cancelled")
```

**可中断边界：**
- **可中断阶段**：Stage 开始前、Stage 完成后、长循环内部（每 100ms 检查一次）
- **不可中断阶段**：单次外部 LLM/HTTP 调用（最多等该调用返回或 client timeout）
- **取消承诺**：可中断阶段 5s 内停止；不可中断阶段最多等 client timeout（通常 15-30s）

### 3.4 Worker 租约与心跳

```python
class PlanningWorker:
    HEARTBEAT_INTERVAL = 10  # 秒
    LEASE_DURATION = 60      # 秒
    
    async def acquire_job(self, worker_id: str) -> Optional[PlanningJob]:
        """用 DB 租约 + SKIP LOCKED 取任务（包含 pending 和 lease 过期的 running）"""
        job = await db.fetchrow(
            """
            UPDATE planning_jobs 
            SET status = 'running', 
                locked_by = $1, 
                lock_expires_at = NOW() + INTERVAL '60 seconds',
                heartbeat_at = NOW(),
                attempt_count = attempt_count + 1
            WHERE id = (
                SELECT id FROM planning_jobs 
                WHERE (
                    status = 'pending' 
                    OR (status = 'running' AND lock_expires_at < NOW())
                )
                AND attempt_count < max_attempts
                ORDER BY created_at 
                LIMIT 1
                FOR UPDATE SKIP LOCKED
            )
            RETURNING *
            """,
            worker_id
        )
        return job
        
    async def heartbeat(self, job_id: str, worker_id: str) -> bool:
        """每 10 秒更新心跳——带 worker_id 条件防止覆盖新 worker
        Returns: True if lease still held, False if lease was taken by another worker
        """
        affected = await db.execute_affected(
            """
            UPDATE planning_jobs 
            SET heartbeat_at = NOW(),
                lock_expires_at = NOW() + INTERVAL '60 seconds'
            WHERE id = $1 AND locked_by = $2
            """,
            job_id, worker_id
        )
        # affected == 0 说明 lease 已被别人接管
        if affected == 0:
            logger.warning(f"Worker {worker_id} lost lease for job {job_id}")
            return False
        return True
        
    async def release_job(self, job_id: str, worker_id: str, 
                          status: str, error: str = None) -> bool:
        """释放任务——带 worker_id 条件防止覆盖
        Returns: True if release succeeded, False if lease was taken by another worker
        """
        affected = await db.execute_affected(
            """
            UPDATE planning_jobs 
            SET status = $1,
                locked_by = NULL,
                lock_expires_at = NULL,
                last_error = $2,
                updated_at = NOW()
            WHERE id = $3 AND locked_by = $4
            """,
            status, error, job_id, worker_id
        )
        if affected == 0:
            logger.warning(f"Worker {worker_id} failed to release job {job_id}, lease taken")
            return False
        return True
```

```python
async def chat_websocket(websocket: WebSocket, session_id: str):
    await manager.connect(session_id, websocket)
    active_job_id: Optional[str] = None
    
    try:
        while True:
            raw = await websocket.receive_text()
            msg = json.loads(raw)
            
            if msg["type"] == "chat":
                # 1. 创建 job
                job = await create_planning_job(
                    session_id=session_id,
                    user_input=msg["content"],
                )
                active_job_id = job.id
                await manager.send_json(session_id, {
                    "type": "job_created",
                    "job_id": job.id,
                    "status": "pending"
                })
                
                # 2. Redis publish 唤醒 worker（DB 本身是 queue）
                await redis.publish("jobs:available", job.id)
                
                # 3. 启动状态推送协程
                asyncio.create_task(push_job_status(job.id, session_id))
                
            elif msg["type"] == "subscribe":
                # 断线重连：按 job_id 重新订阅
                job_id = msg.get("job_id")
                last_event_id = msg.get("last_event_id", 0)
                if job_id:
                    asyncio.create_task(
                        push_job_status(job_id, session_id, from_event_id=last_event_id)
                    )
                
            elif msg["type"] == "cancel":
                if active_job_id:
                    await cancel_job(active_job_id)  # DB 更新 + Redis 通知
                    active_job_id = None
                    
    except WebSocketDisconnect:
        if active_job_id:
            asyncio.create_task(delayed_cancel(active_job_id, delay=30))
```

### 4.3 状态推送协程

```python
async def push_job_status(job_id: str, session_id: str, from_event_id: int = 0):
    """后台协程：监听 job 状态变化，推送到前端"""
    # 方式 1：Redis pub/sub（低延迟）
    pubsub = redis.pubsub()
    await pubsub.subscribe(f"job:status:{job_id}")
    
    # 方式 2：兜底轮询（Redis 断线时）
    last_event_id = from_event_id
    
    async def poll_events():
        """从 DB 拉最新事件并推送到前端"""
        nonlocal last_event_id
        events = await db.fetch(
            "SELECT * FROM planning_job_events WHERE job_id = $1 AND id > $2 ORDER BY id",
            job_id, last_event_id
        )
        for e in events:
            last_event_id = e["id"]
            await manager.send_json(session_id, {
                "event_id": e["id"],
                "type": e["event_type"],
                "stage": e["stage"],
                "payload": e["payload"],
            })
        return len(events) > 0
        
    # 首次推送所有历史事件（或从断点续传）
    while await poll_events():
        pass
        
    # Redis + 定时轮询兜底（Redis 断线时仍可持续拉取）
    poll_interval = 2.0  # 每 2 秒兜底轮询一次
    
    async def redis_listener():
        """Redis 消息监听"""
        async for message in pubsub.listen():
            if message["type"] == "message":
                await poll_events()
                
            job = await get_job(job_id)
            if job.status in ("completed", "failed", "cancelled"):
                break
    
    async def periodic_poll():
        """定时轮询兜底，Redis 断线时仍可持续拉取"""
        while True:
            await asyncio.sleep(poll_interval)
            if await poll_events():
                # 检查终止条件
                job = await get_job(job_id)
                if job.status in ("completed", "failed", "cancelled"):
                    break
    
    # 两个独立任务，任一发现终态后 cancel 另一个
    redis_task = asyncio.create_task(redis_listener())
    poll_task = asyncio.create_task(periodic_poll())
    
    # 等待任一任务完成（发现终态后退出）
    done, pending = await asyncio.wait(
        [redis_task, poll_task],
        return_when=asyncio.FIRST_COMPLETED
    )
    
    # Cancel 剩余任务
    for task in pending:
        task.cancel()
        try:
            await task
        except asyncio.CancelledError:
            pass
```

## 五、执行层改造

### 5.1 Pipeline 设计（不绑定 LangGraph）

```python
class PlanningPipeline:
    """
    规划流水线——业务 job 状态由本类管理
    LangGraph 可作为底层实现之一，但恢复能力不依赖 Graph Checkpointer
    """
    def __init__(self, worker: PlanningWorker):
        self.worker = worker
        
    async def run(self, job: PlanningJob):
        """执行完整 pipeline"""
        try:
            # Stage 1: Supervisor
            if await self._check_cancelled(job): 
                await self.worker.mark_cancelled(job.id, self.worker.worker_id)
                return
            intent = await self._stage_intent(job)
            await self._record_stage(job, "intent_ready", intent)
            
            # Stage 2: 数据收集
            if await self._check_cancelled(job):
                await self.worker.mark_cancelled(job.id, self.worker.worker_id)
                return
            data = await self._stage_data_collection(job, intent)
            await self._record_stage(job, "data_collected", data)
            
            # Stage 3: Strategy
            if await self._check_cancelled(job):
                await self.worker.mark_cancelled(job.id, self.worker.worker_id)
                return
            strategy = await self._stage_strategy(job, intent, data)
            await self._record_stage(job, "strategy_ready", strategy)
            
            # Stage 4: Planning Core
            if await self._check_cancelled(job):
                await self.worker.mark_cancelled(job.id, self.worker.worker_id)
                return
            draft = await self._stage_planning(job, strategy, data)
            
            # Stage 5: Rule Validator（强制门禁）
            max_repair_loops = 3
            for i in range(max_repair_loops):
                validation = self._stage_validate(draft, data)
                if validation.passed:
                    break
                if i < max_repair_loops - 1:
                    draft = self._stage_repair_by_rules(draft, validation.violations)
                else:
                    raise ValueError(f"Rule validation failed after {max_repair_loops} attempts")
            
            await self._record_stage(job, "draft_ready", draft)
            
            # Phase 1：直接 draft → final（Phase 2 再加 Critic/Repair）
            itinerary_final = draft
            await self._record_stage(job, "itinerary_final", {
                "itinerary": itinerary_final,
                "critic_skipped": True
            })
            
            # Stage 6: Writer（流式）
            if await self._check_cancelled(job):
                await self.worker.mark_cancelled(job.id, self.worker.worker_id)
                return
            await self._stage_writer(job, itinerary_final)
            
            await self.worker.release_job(
                job.id, self.worker.worker_id, "completed"
            )
            
        except Exception as e:
            logger.error(f"Pipeline failed for job {job.id}: {e}")
            await self.worker.release_job(
                job.id, self.worker.worker_id, "failed", str(e)
            )
            
    async def _check_cancelled(self, job: PlanningJob) -> bool:
        """检查是否被取消——查 DB（source of truth）"""
        status = await db.fetchval(
            "SELECT status FROM planning_jobs WHERE id = $1", job.id
        )
        return status in ("cancelling", "cancelled")
        
    async def _record_stage(self, job: PlanningJob, stage: str, payload: Any):
        """记录阶段完成"""
        elapsed = (datetime.now() - job.created_at).total_seconds()
        
        # 1. 写入事件日志
        await db.execute(
            """
            INSERT INTO planning_job_events (job_id, stage, event_type, payload)
            VALUES ($1, $2, 'completed', $3)
            """,
            job.id, stage, json.dumps(payload) if payload else None
        )
        
        # 2. 更新 job 状态
        await db.execute(
            """
            UPDATE planning_jobs 
            SET status = $1, 
                updated_at = NOW(),
                stage_timings = stage_timings || $2::jsonb
            WHERE id = $3
            """,
            stage, json.dumps({stage: elapsed}), job.id
        )
        
        # 3. Redis 通知 API 层（快速推送）
        await redis.publish(f"job:status:{job.id}", json.dumps({
            "type": "stage",
            "stage": stage,
            "elapsed": round(elapsed, 1),
        }))
```

### 5.2 Planning Core 算法定义

```python
@dataclass
class PlanningStrategy:
    theme: str
    interests: list[str]         # 用户兴趣标签，如 ["历史文化", "美食", "摄影"]
    must_include: list[str]      # POI name 列表
    optional: list[str]
    avoid: list[str]             # "A和B同一天" 这种规则
    preferred_areas_by_day: dict  # 结构化区域偏好，如 {"1": ["东城区"], "2": ["海淀区"]}
    pace: str                    # relaxed/moderate/intensive
    daily_activity_target: int   # 每天目标活动数
    indoor_outdoor_balance: str  # auto/indoor_preferred/outdoor_preferred

@dataclass
class RankedPOI:
    """Planning Core 内部使用——不污染原始 ScoredPOI"""
    poi: ScoredPOI               # 原始 POI 对象（来自 schemas）
    final_score: float
    score_breakdown: dict        # 可审计的分数拆解
    
    # 各维度得分（权重固定，LLM 不主导）
    landmark_score: float = 0.0
    interest_match_score: float = 0.0
    strategy_priority_score: float = 0.0
    area_fit_score: float = 0.0
    weather_fit_score: float = 0.0
    budget_fit_score: float = 0.0
    novelty_score: float = 0.0
    distance_penalty: float = 0.0
    overcrowd_penalty: float = 0.0

def calculate_final_score(ranked: RankedPOI, strategy: PlanningStrategy, 
                         day_idx: int, weather: WeatherDay,
                         last_location: Optional[Location]) -> float:
    """计算 POI 在特定天的最终得分——LLM 只提供 strategy_priority，其余由程序规则决定"""
    
    # 1. 文化地标分（程序规则：5A 景区 +25，世界遗产 +20，知名景点 +15）
    landmark_score = 0.0
    # 从 poi.tags 或 poi 属性判断（当前 schema 无 is_cultural_landmark，用 tag 匹配）
    poi_tags = [t.lower() for t in (ranked.poi.tags or [])]
    if any(k in poi_tags for k in ["5a", "世界遗产", "文化地标", "地标"]):
        landmark_score = 25.0
    elif any(k in poi_tags for k in ["知名", "著名", "热门", "经典"]):
        landmark_score = 15.0
        
    # 2. 兴趣匹配分（程序规则：tag 匹配 +10/个）
    user_interests = strategy.interests
    interest_match = sum(10.0 for tag in user_interests if any(t in poi_tags for t in [tag.lower()]))
    interest_match = min(interest_match, 50.0)
    
    # 3. LLM 策略优先级（权重最低，防止 LLM 不可解释排序主导）
    strategy_priority = 0.0
    if ranked.poi.name in strategy.must_include:
        strategy_priority = 30.0
    elif ranked.poi.name in strategy.optional:
        strategy_priority = 15.0
    elif ranked.poi.name in strategy.avoid:
        strategy_priority = -50.0
        
    # 4. 区域集中度（程序规则：和当天偏好区域匹配 +15）
    area_fit = 0.0
    day_key = str(day_idx + 1)
    if day_key in strategy.preferred_areas_by_day and ranked.poi.area:
        preferred_areas = strategy.preferred_areas_by_day[day_key]
        if any(area in ranked.poi.area for area in preferred_areas):
            area_fit = 15.0
        
    # 5. 天气适配（程序可枚举规则）
    weather_fit = 0.0
    if weather and "雨" in weather.condition:
        if ranked.poi.indoor_outdoor == "indoor":
            weather_fit = 25.0
        elif ranked.poi.indoor_outdoor == "outdoor":
            weather_fit = -15.0
    elif weather and "晴" in weather.condition and ranked.poi.indoor_outdoor == "outdoor":
        weather_fit = 10.0
        
    # 6. 预算适配
    budget_fit = 0.0
    if ranked.poi.ticket_price:
        if ranked.poi.ticket_price <= 100:
            budget_fit = 10.0
        elif ranked.poi.ticket_price > 300:
            budget_fit = -10.0
            
    # 7. 新鲜度
    novelty_score = 5.0
    
    # 惩罚项
    distance_penalty = 0.0
    if last_location and ranked.poi.location:
        dist = haversine(last_location, ranked.poi.location)
        distance_penalty = dist * 3.0
        
    overcrowd_penalty = 0.0
    
    # 加权求和（权重固定，可审计）
    final_score = (
        0.25 * landmark_score +
        0.20 * interest_match +
        0.15 * strategy_priority +
        0.15 * area_fit +
        0.10 * weather_fit +
        0.10 * budget_fit +
        0.05 * novelty_score -
        distance_penalty -
        overcrowd_penalty
    )
    
    # 记录拆解（用于调试和审计）
    ranked.landmark_score = landmark_score
    ranked.interest_match_score = interest_match
    ranked.strategy_priority_score = strategy_priority
    ranked.area_fit_score = area_fit
    ranked.weather_fit_score = weather_fit
    ranked.budget_fit_score = budget_fit
    ranked.novelty_score = novelty_score
    ranked.distance_penalty = distance_penalty
    ranked.overcrowd_penalty = overcrowd_penalty
    ranked.score_breakdown = {
        "landmark": round(landmark_score, 2),
        "interest_match": round(interest_match, 2),
        "strategy_priority": round(strategy_priority, 2),
        "area_fit": round(area_fit, 2),
        "weather_fit": round(weather_fit, 2),
        "budget_fit": round(budget_fit, 2),
        "novelty": round(novelty_score, 2),
        "distance_penalty": round(distance_penalty, 2),
        "total": round(final_score, 2),
    }
    
    return final_score

def build_schedule(strategy: PlanningStrategy, pois: list[ScoredPOI],
                   weather: list[WeatherDay], profile: UserProfile) -> list[DayPlan]:
    """程序生成候选行程——可枚举语义规则由程序处理"""
    schedule = []
    used_pois: set[str] = set()
    
    # 可枚举语义规则映射
    pace_adjustment = {"relaxed": -1, "moderate": 0, "intensive": 1}
    
    # 特殊人群调整
    traveler_type = profile.travelers_type if hasattr(profile, "travelers_type") else ""
    if traveler_type in ("老人", "亲子", "family", "elderly"):
        pace_adjustment = {k: v - 1 for k, v in pace_adjustment.items()}
        
    for day_idx in range(profile.travel_days):
        day = DayPlan(
            id=f"day_{day_idx + 1}",
            day_number=day_idx + 1, 
            date=weather[day_idx].date if day_idx < len(weather) else ""
        )
        day_weather = weather[day_idx] if day_idx < len(weather) else None
        
        # 1. 包装为 RankedPOI 并计算得分
        candidates = []
        for p in pois:
            if p.name in used_pois:
                continue
            rp = RankedPOI(poi=p, final_score=0.0)
            rp.final_score = calculate_final_score(
                rp, strategy, day_idx, day_weather,
                schedule[-1].activities[-1].location if schedule and schedule[-1].activities else None
            )
            candidates.append(rp)
        candidates.sort(key=lambda x: x.final_score, reverse=True)
        
        # 2. 按 pace 控制数量
        base_target = strategy.daily_activity_target
        target_count = max(2, min(5, base_target + pace_adjustment.get(strategy.pace, 0)))
        
        # 3. must_include 优先
        must_pois = [p for p in candidates if p.poi.name in strategy.must_include]
        optional_pois = [p for p in candidates if p.poi.name not in strategy.must_include]
        
        selected = must_pois[:target_count]
        if len(selected) < target_count:
            selected += optional_pois[:target_count - len(selected)]
            
        # 4. 排时间（程序逻辑）
        current_time = 9 * 60  # 09:00
        for rp in selected:
            poi = rp.poi
            duration = parse_duration(poi.recommended_hours or "2小时")
            
            # 午餐插入
            if current_time + duration > 11 * 60 and current_time < 12 * 60:
                lunch = Activity(
                    id=f"act_{day_idx + 1}_lunch",
                    poi_name="午餐",
                    category="restaurant",
                    start_time=minutes_to_time(current_time),
                    end_time=minutes_to_time(current_time + 90),
                    duration_min=90,
                    source="planner_generated",
                )
                day.activities.append(lunch)
                current_time += 90
                
            activity = Activity(
                id=f"act_{day_idx + 1}_{len(day.activities)}",
                poi_name=poi.name,
                category=poi.category,
                start_time=minutes_to_time(current_time),
                end_time=minutes_to_time(current_time + duration),
                duration_min=duration,
                ticket_price=poi.ticket_price,
                location=poi.location,
                source="planner_generated",
            )
            day.activities.append(activity)
            used_pois.add(poi.name)
            current_time += duration + 30
            
            if current_time > 21 * 60:
                break
                
        schedule.append(day)
        
    return schedule
```

### 5.3 Rule Validator（强制门禁）

```python
class RuleValidator:
    """硬约束检查——必须全部通过才能发布行程"""
    
    def validate(self, schedule: list[DayPlan], profile: UserProfile, 
                 strategy: PlanningStrategy) -> ValidationResult:
        violations = []
        
        # 1. 时间冲突检查
        for day in schedule:
            for i, act1 in enumerate(day.activities):
                for act2 in day.activities[i+1:]:
                    if self._time_overlap(act1, act2):
                        violations.append(Violation(
                            type="time_conflict",
                            day=day.day_number,
                            activity_ids=[act1.id, act2.id],
                            message=f"{act1.poi_name} 与 {act2.poi_name} 时间冲突"
                        ))
                        
        # 2. 预算检查（从 profile.budget_range 解析）
        budget = profile.budget_range if hasattr(profile, "budget_range") else 5000
        total_cost = sum(
            (act.ticket_price or 0) for day in schedule for act in day.activities
        )
        if total_cost > budget * 1.1:
            violations.append(Violation(
                type="budget_over",
                message=f"预算超标：{total_cost} > {budget * 1.1}"
            ))
            
        # 3. 景点重复检查
        seen_pois = set()
        for day in schedule:
            for act in day.activities:
                if act.poi_name in seen_pois:
                    violations.append(Violation(
                        type="duplicate_poi",
                        day=day.day_number,
                        activity_ids=[act.id],
                        message=f"{act.poi_name} 重复出现"
                    ))
                seen_pois.add(act.poi_name)
                
        # 4. 每天活动数上限
        for day in schedule:
            activities = [a for a in day.activities if a.category != "restaurant"]
            if len(activities) > 5:
                violations.append(Violation(
                    type="too_many_activities",
                    day=day.day_number,
                    message=f"第{day.day_number}天活动过多（{len(activities)}个）"
                ))
                
        # 5. must_include 检查
        all_pois = {act.poi_name for day in schedule for act in day.activities}
        missing = [p for p in strategy.must_include if p not in all_pois]
        if missing:
            violations.append(Violation(
                type="missing_must_include",
                message=f"遗漏必去景点：{missing}"
            ))
            
        return ValidationResult(
            passed=len(violations) == 0,
            violations=violations
        )
```

## 九、实施路线图

### Phase 1：任务隔离 + Planning Core（1 周）

**核心目标**：解决"请求协程被长任务独占"的根因

1. **新增数据表**
   - `planning_jobs`（含 lease/heartbeat 字段）
   - `planning_job_events`（阶段事件日志）
   - `trip_plan_versions`（行程版本）
   
2. **API 层改造**
   - WebSocket handler 改为"创建 job + 推送 job_id"
   - 移除 `await graph.ainvoke()`
   - 新增状态推送协程（DB 轮询 + Redis 通知）
   - 支持断线重连：`subscribe` 消息 + `last_event_id`
   
3. **后台 Worker**
   - 实现 `PlanningWorker`（含 lease、heartbeat、取消检查）
   - 实现 `PlanningPipeline`（不绑定 LangGraph，Phase 1 只跑 6 阶段）
   - Worker 主循环：DB lease + SKIP LOCKED 取 job（含 running lease 过期）
   - 取消后 `mark_cancelled()` 释放锁
   
4. **Planning Core 替代 `_plan_with_llm`**
   - 实现 `RankedPOI` 类型（不污染 `ScoredPOI`）
   - 实现 `calculate_final_score`（权重固定，LLM 仅占 0.15）
   - 实现 `build_schedule`（程序排程）
   - 实现 `RuleValidator`（强制门禁）
   
5. **取消机制**
   - DB `cancelling` 状态（source of truth）
   - Redis pub/sub 作为 fast signal
   - 可中断/不可中断边界定义

6. **前端配合**
   - 新增 job stage 显示组件
   - 显示 itinerary_final（结构化行程先出）
   - 支持取消按钮
   - 支持断线重连订阅

**Phase 1 Pipeline（6 阶段）：**
```
intent → data → strategy → planning → rule_validate → writer
```

**预期效果：**
- API 不再被长任务阻塞
- 济南/北京场景从 90s → 10-20s（TTFI）
- 前端能看到规划进度
- Worker 崩溃后 60s 内其他 worker 接管

### Phase 2：Critic + Repair + 完整流式输出（3-5 天）

1. **LLM Critic**
   - 输出机器可执行格式（含 type/activity_ids/suggested_action）
   - **不阻塞发布**（失败则 draft→final，标记 critic_skipped）
   
2. **Repair Core**
   - 根据 Critic 意见自动修正
   - 修完再跑 Rule Validator
   
3. **itinerary_draft 提前推送**
   - Rule Validator 通过后推 draft
   - Critic/Repair 后推 final
   
4. **Writer 流式增强**
   - 使用 `astream` 逐 token 返回
   - 前端 StreamingMessage 组件

**Phase 2 Pipeline（8 阶段）：**
```
intent → data → strategy → planning → rule_validate → critic → repair → writer
```

### Phase 3：多轮修改 + 性能优化（3-5 天）

1. **多轮修改支持**
   - DayPlan / Activity 加稳定 ID + source + depends_on
   - 支持锁定/解锁字段
   - 版本历史 + 回滚
   
2. **性能优化**
   - Planning Core 结果缓存
   - Strategy 结果预计算（内置城市）
   - Worker 水平扩展
   
3. **LangGraph 可选集成**
   - 如果现有 LangGraph 状态有价值，可接入作为 Pipeline 实现之一
   - 但 job 状态、恢复能力始终由业务表负责

## 十、一句话总结

> **API 只负责会话和任务控制；后台工作流负责规划执行；LLM 定策略和表达（权重受限），程序负责排程与硬约束（可审计）；DB 是唯一事实源，Redis 只是通知；结构化行程先返回，Critic 不阻塞，文案流式增强。**
