修复的是审核器对执行记录的解释：`RESEARCH_EVIDENCE_INSUFFICIENT` 守卫拒绝并未调用 provider，不能计成实际缺失返回或已执行重试；相同空模型参数在补充候选后会解析成不同实际实体参数，不能一律去重。复审逐条确认守卫拒绝前后 provider 状态及工具/solver 用量未变，且这些拒绝动作不进入监督。真正缺失的工具返回、过量相同实际请求及原有质量拒绝仍被拦截；偏好和硬约束门槛不变。

原始 40 次教师尝试、通过率与失败记录保持不变。新增 41 个可验证动作来自重新导出，不是额外模型生成；原 125 条 example 按 ID 和完整内容逐条相等。311 个教师执行状态、20 条接手来源链再次通过审计。实际 TRL 预处理和 collator 核对 166/166，490,564 个 prompt token 屏蔽、5,952 个监督 token，最长 3,927，零截断；仅微型 CPU 模型初始化检查处理链，没有 forward/backward。正式 4B 训练时仍须检查实际 batch labels。

两侧均合格的共同任务从 5 增至 8，来源于 7 个父组，包含 4 个规划、4 个有依据的安全终态。共同子集已单独导出：demo 52 动作/1,879 token；correction 37 动作/1,529 token。它们是经成功筛选的配对支持集，尚未构造等 token 训练日程，不是可直接宣称公平训练对比的完整包。

## 失败定位与下一批优先级

7 个规划失败均未实际执行 solver；全部 8 个规划任务中仅 1 个到达求解。共 13 次研究证据不足拒绝、37 次重复无进展拒绝。5 次原始策略错误分布在 4 个任务，均为 `search_pois.keywords` 参数不合法，finish_reason 为 stop；基础设施错误 0。这里只定位到已记录的失败环节，不能据此声称所有根因已经修复。

下一批应优先补 train 来源中的餐厅证据研究、候选变化后详情/路线更新、查询无进展后的换工具/换参数，以及多日证据覆盖。保留少量已掌握的预算终态作回归锚点，按规划与恢复分层评估。开发集实体、任务及状态不得拷贝为教师训练目标。新 train 来源先预检，再保留全部学生首次尝试并选择真实接手起点。

先用小批匹配任务验证 GLM max/high 与队列异常处理的速度/质量，再扩大配对采集；本轮没有实际测试新教师配置，不能宣称教师已提速。后续两个 SFT 训练组需同一初始权重、来源覆盖和实际监督 token 预算，补充已审核的共享基础能力样本。目前只有 4 对规划任务，不应当作正式规模效果实验；原 2,000–5,000 train / 300 dev / 500 locked test 目标仍未完成。本轮未启动新 SFT 或 RL。
