# Qwen3 教师—学生蒸馏与效率后训练：阶段 19–25 计划

日期：2026-08-14

## 1. 最终目标

在不牺牲旅行任务正确性和硬约束通过率的前提下，把 Qwen3-8B 的 Agent Policy 能力蒸馏到更小的 Qwen3 学生模型，并通过 SFT、偏好优化和效率导向 GRPO 进一步减少输出 Token、工具调用轮数和端到端延迟。

本路线不以“跑完训练”为成功标准，而以可复现的能力增量和线上可用性为标准。

最终服务采用双模型分工：

- Qwen3-4B 学生：搜索、澄清、错误恢复、普通权衡等高频工具决策；
- Qwen3-8B 教师/专家：复杂规划、长上下文、多约束冲突和学生失败回退；
- 确定性 Router：依据任务状态、风险和学生输出门禁选择模型，不再额外调用一个 LLM 做路由。

Qwen3-1.7B 只作为速度下限对照。若 4B 已满足性能目标，不扩大 1.7B 正式训练。

## 2. 总体验收指标

所有结论必须来自冻结的真实/对抗 holdout 和相同请求协议下的配对测试。

| 指标 | 学生模型目标 | 双模型系统目标 |
|---|---:|---:|
| 工具决策成功率 | 与 8B 相差不超过 2 个百分点 | 不低于 8B 单模型基线 |
| 硬约束通过率 | 不低于 8B 基线 | 不低于 8B 基线 |
| 平均输出 Token | 比学生 Base 降低至少 30% | 比 8B 基线降低至少 30% |
| 重复工具调用 | 比学生 Base 降低至少 30% | 比 8B 基线降低至少 30% |
| 平均端到端延迟 | 比 8B 基线降低至少 30% | 比 8B 基线降低至少 25% |
| P95 Agent 单步延迟 | 不高于 3 秒 | 不高于 3 秒 |
| 非法工具参数率 | 0 | 0 |
| 学生安全回退覆盖率 | 100% | 100% |

延迟目标是初始门槛，阶段 19 的真实 HTTP 基线完成后允许依据硬件测量结果校准，但不得在看到候选结果后降低门槛来迁就实验。

## 3. 统一评测与数据原则

1. 先冻结测试集，再生成任何教师标签；测试任务不得进入蒸馏、DPO 或 GRPO。
2. 按场景签名、模板族、城市和用户约束组合隔离 split，不能只依赖 example ID。
3. 对模型实际看到的 `messages + tools` 做全局哈希去重。
4. 教师只输出可审计的工具动作和必要解释，不保存或蒸馏隐藏思维链。
5. 教师生成的候选必须经过确定性环境、Validator、Reward 和长度门禁；教师身份本身不等于正确标签。
6. 所有实验保存配置、seed、模型版本、数据版本、原始 rollout、训练日志和拒绝原因。
7. 每一阶段先做小规模 smoke，只有通过晋升门才扩大训练。

## 4. 阶段 19：真实性能剖析与 vLLM 基线

### 目标

回答当前延迟来自模型计算、生成过长还是 Agent 多轮循环，并建立后续所有加速实验的统一基线。

### 工作项

- 在模型请求和 Agent Episode 中记录：TTFT、TPOT、prompt/completion Token、总生成时长、工具轮数、重复调用、模型名和是否启用 thinking；
- 通过真实 vLLM HTTP 服务验证 `enable_thinking=False` 确实生效；
- 对比 Transformers、vLLM BF16/NF4 或可用量化路径；
- 测试合理的 `max_tokens`、`max_model_len`、前缀缓存和并发配置；
- 对 zero-shot 8B 与阶段 18 smoke adapter 做同请求配对，解释此前 45%–68% 延迟增加的来源；
- 冻结三套评测集：常规集、真实/Shadow 难例集、对抗集。

### 产物

- 可复用的 HTTP benchmark 脚本；
- request/episode 性能 Schema；
- 8B 服务基线报告；
- 冻结 holdout manifest 和数据泄漏审计报告。

### 晋升门

- 所有成功请求均可拆解 TTFT、TPOT、Token 和 Agent 轮数；
- 同一配置重复测量波动处于可解释范围；
- thinking 模式、量化方式和服务参数被写入报告，不能只记录模型名。

## 5. 阶段 20：难例挖掘与教师轨迹蒸馏集

### 目标

把训练分布从“Qwen3-8B 已经全会的模板题”转向真实失败、边界和效率问题。

### 工作项

- 从 8B zero-shot、Shadow Episode 和对抗生成中挖掘：错误工具选择、参数错误、重复搜索、无效恢复、过早 finish、预算冲突和长链路失忆；
- 每个训练任务由 8B 教师采样多个候选，使用环境和 Verifier 选出“成功且最短”的轨迹；
- 保留失败候选及失败原因，形成偏好对；
- 建立难度标签、任务家族、教师置信证据和成本字段；
- 将阶段 18 的无重复数据仅作为能力 replay，不作为主训练分布。

### 建议规模

- 冻结 hard holdout：至少 300 个唯一任务；
- 蒸馏训练候选：3000–5000 条唯一教师轨迹；
- 偏好对：至少 1000 对，且覆盖全部核心任务家族；
- replay 占训练数据 15%–25%，防止灾难性遗忘。

### 晋升门

- 教师候选必须全部通过工具 Schema 和确定性硬约束；
- 模型可见 payload 唯一率 100%；
- train/validation/test 场景签名 overlap 为 0；
- 教师优选轨迹相对被拒轨迹在成功率或效率上存在真实差异。

## 6. 阶段 21：Qwen3-4B 学生蒸馏 SFT

### 目标

训练一个能够承担高频工具决策的学生模型，并证明提升来自蒸馏数据而非测试泄漏。

### 执行方式

- 先测 Qwen3-4B zero-shot 基线；
- 8B 教师离线完成数据生成后退出显存，再使用 4090 对 4B 做 QLoRA；
- 先用 64–256 条样本做格式 overfit，再做 8/16/32 step 价值门；
- 正式训练只在 hard validation 提升且 replay 不退化时开启；
- 保存 adapter、合并模型选项、tokenizer、训练配置和恢复 checkpoint。

### 对照

- 4B Base；
- 4B + 原阶段 18 模板数据；
- 4B + hard-example distillation；
- 8B zero-shot 教师。

### 晋升门

- hard holdout 成功率相对 4B Base 有统计稳定提升；
- 常规 replay 成功率下降不超过 1 个百分点；
- 输出 Token、工具轮数或延迟至少一个效率指标显著改善；
- 若只降低 teacher-forced loss 而行为评测无增益，立即拒绝正式 checkpoint。

## 7. 阶段 22：长度与工具效率偏好优化

### 目标

让学生在多个正确答案中稳定偏向更短、更直接、工具调用更少的轨迹。

### 工作项

- 从教师候选、学生 rollout 和规则扰动构造 chosen/rejected；
- chosen 必须首先正确，不能为了短而牺牲任务完成；
- rejected 覆盖重复搜索、无效说明、错误参数、过度澄清和过早 finish；
- 优先采用项目训练栈最稳定的 DPO/ORPO 之一，先完成单一算法基线，不同时扩张多个框架；
- 对长度偏好做分桶，防止模型学习“永远输出最短动作”。

### 晋升门

- hard holdout 成功率不低于蒸馏 SFT；
- 平均输出 Token 相对蒸馏 SFT 降低至少 15%；
- 非法工具调用、空输出和错误 finish 不增加；
- 偏好准确率提高必须同时反映在真实 rollout，而非只体现在离线 pair accuracy。

## 8. 阶段 23：效率导向的有状态 GRPO

### 目标

在真实多轮快照环境中联合优化任务成功、约束正确性和执行成本。

### 奖励设计

奖励采用硬门禁加分层软奖励：

```text
若 Schema、受保护参数或硬约束失败：直接负奖励并终止

否则：
  task_success
  + progress / recovery / user_alignment
  - completion_tokens
  - redundant_tool_calls
  - agent_steps
  - timeout_or_latency_proxy
```

训练 Reward 不直接使用易受系统噪声影响的单次墙钟时间；使用输出 Token、模型调用次数、工具次数等稳定代理。真实延迟只用于离线/HTTP 晋升评测。

### 工作项

- 仅选择存在组内结果差异的任务，过滤全成功和全失败零方差组；
- 从蒸馏/偏好 checkpoint 开始，不从 Base 直接做 GRPO；
- 先做 reward-only 回放审计和小步 smoke；
- 监控 KL、熵、组内方差、输出长度、重复动作和各 Reward 分量；
- 做 Token 惩罚、工具惩罚和恢复奖励的消融。

### 晋升门

- hard holdout 成功率不下降；
- 输出 Token、重复调用和 Agent 步数至少两项改善；
- 不出现 Reward 上升但 Validator 通过率下降；
- 若有效组比例不足或策略坍塌，停止 GRPO，保留 DPO/SFT 最佳候选。

## 9. 阶段 24：双模型 Router 与安全回退

### 目标

让学生承担大部分高频请求，复杂或高风险状态自动交给 8B，形成可部署的加速系统。

### Router 输入

- 任务类型和当前 Task DAG 状态；
- 约束数量、冲突等级和上下文长度；
- 是否为失败恢复、连续重试或最终 finish；
- 学生输出是否通过 Schema、参数和动作合法性门禁；
- 学生是否重复调用、空输出或超过预算。

### 推荐路由

- 4B：search、clarification、普通 recovery、局部 tradeoff；
- 8B：复杂 itinerary planning、长上下文、多硬约束冲突、Router 高风险任务；
- 学生任意门禁失败：当前步骤升级到 8B；
- 8B 仍失败：回退现有确定性流程。

### 产物与晋升门

- 可配置、可测试、无额外 LLM 调用的 Router；
- Shadow 双跑和回退审计日志；
- 学生流量占比、升级原因、额外延迟和成功率报告；
- Router 系统成功率不低于 8B，平均延迟降低至少 25%。

## 10. 阶段 25：最终消融、发布与项目表达

### 必须完成的对照

1. 4B Base；
2. 4B 蒸馏 SFT；
3. 4B SFT + DPO/ORPO；
4. 4B SFT + DPO/ORPO + GRPO；
5. 8B zero-shot；
6. 4B/8B Router 系统。

每个候选统一报告成功率、硬约束、TTFT、TPOT、Token、工具轮数、平均/P95延迟、显存、吞吐和失败类型。

### 项目最终可陈述能力

- 通过 verifier-guided distillation 将 8B Agent Policy 能力迁移到 4B；
- 通过偏好优化减少冗余输出与重复工具调用；
- 通过有状态效率 GRPO 联合优化成功率和执行成本；
- 通过确定性双模型路由在质量不退化条件下降低服务延迟；
- 使用独立 holdout、消融和拒绝门禁避免把模板过拟合包装成能力提升。

只有实际指标通过后才能填写具体提升数字；计划目标不能作为完成结果写入简历。

## 11. 算力与磁盘约束

- 当前 4090 24GB 不同时加载 8B 教师和 4B 学生；采用离线顺序流水线；
- 教师原始候选只保存必要文本、Token 和 verifier 证据，避免保存重复模型缓存；
- 下载学生权重前先做磁盘容量门，清点可重建缓存和已归档拒绝产物；任何清理都记录目标和恢复方式；
- 每次正式训练前估算 adapter、optimizer、checkpoint 和报告空间，至少保留一个可恢复 checkpoint 的余量；
- 云端只保留训练所需模型和当前阶段产物，最终报告、adapter 和数据 manifest 同步回本地。

## 12. 执行顺序与止损原则

严格顺序为：

`真实性能基线 → 冻结 holdout → 教师难例集 → 4B Base → 蒸馏 SFT → 偏好优化 → 效率 GRPO → Router → 最终消融`

任一阶段未通过晋升门，不自动进入下一种训练。允许最终最佳结果停在蒸馏 SFT 或 DPO；不以是否跑过 GRPO 判断项目成功，而以是否产生可验证的质量—效率 Pareto 改善判断。
