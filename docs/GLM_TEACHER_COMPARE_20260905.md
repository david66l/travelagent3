# TravelAgent2：GLM-5.3-Flash 教师实测与下一步

日期：2026-09-05。正式运行版本：`harness-glm-teacher-diagnostic24.v3`。国内智谱通用 API。

## 1. 先看结论

**GLM 已接入现有 Agent Loop，并完成全部 24 个开发诊断任务。有效行程提交：Qwen3-4B 基模 8/17，GLM 教师 16/17；必要追问 3/3；硬约束冲突处理 0/4。**

这是教师与未训练小模型的对照，还不是小模型训练后的提升。可以据此选择值得学习的决策，但教师成功轨迹仍需审核，不能直接整批复制成训练集。

**更重要的发现：约束组受到终止契约缺陷影响。4 个不可行案例都可能被固定规则标为“可求解”，有依据的停止仍拿不到成功奖励。因此先修终止判定，再采集训练示范；本轮约束分数不能单独解释为模型能力。**

| 任务组 | Qwen3-4B 基模 | GLM-5.3-Flash |
|---|---:|---:|
| 普通规划 | 4/4 | 4/4 |
| 查证开放时间 | 0/4 | 4/4 |
| 过期证据 | 0/4 | 3/4 |
| 工具故障恢复 | 3/4 | 4/4 |
| 硬约束冲突 | 0/4 | 0/4 |
| 澄清组，含 1 个信息完整对照 | 4/4 | 4/4 |

24 题中，17 题应提交有效行程，3 题应补问必要信息，4 题应合理处理不可行约束。分类报告，避免把“追问”混成“规划成功”。追问分数检查是否覆盖缺失信息，未独立量化简洁性；例如目的地缺失题还额外询问了出发地和出游偏好。这些是 6 类各 4 个城市变体的合成开发题，不代表独立测试或线上成功率。

## 2. 这为什么符合你想做的后训练

以 `evidence-01` 为例：

- 小模型得到过期开放时间后，先尝试求解，再多次重复原查询，最终没完成任务。
- 教师把查询改为“官方公告 + 当天日期”，取得更新结果，继续收集景点、详情和矩阵，求解、校验并提交。

要让小模型学的是：**看到当前结果后，判断还缺什么、是否需要换查询、下一步调用什么，以及什么时候结束。** 旅游事实仍由工具提供，时间和预算仍由求解器与校验器检查。

不过，成功也不等于每一步都好。本轮教师有 6 个成功案例经历过执行前拒绝，全部案例共 11 次这类拒绝。应保留真实失败分布，另采集经过审核的示范，避免教会学生重复操作和提前提交。

## 3. 接入实际做了什么

新增 `core/glm_tool_client.py` 作为提供商适配层，以及 `scripts/evaluate_harness_teacher.py` 作为评测入口。继续复用现有 `NativeToolAgentPolicy → SelfRepairingAgentPolicy → BoundedAgentLoop → TravelActionExecutor`。

模型自行决定工具和参数。没有增加固定旅行步骤、教师专用控制器或第二个 Loop。密钥配置在本地被 Git 忽略的 `.env`；云端运行通过 SSH 标准输入传入进程环境，评测证据不保存认证请求头。

接入前试跑发现 GLM 经常一次返回多个调用。`parallel_tool_calls=false` 实测未阻止这一行为。正式版本保留原状态和 system 提示，在消息末尾重复“每轮只调用一个工具”的接口约束，不指定哪一个工具。仍然拒绝零个或多个调用，由同一模型最多自我纠错一次，不截取第一个调用冒充成功。

正式运行有 247 次模型请求、1 次输出/参数错误、0 次提供商故障；5 次请求因取消未完成。接口故障与单题达到时限分开记录。

## 4. 对照边界和开销

两边使用相同任务、固定时间、模型可见状态的生成逻辑、研究数据、实际求解器和校验器。任务哈希一致。共同源文件中，仅轨迹模块有此前加入的旧哈希兼容处理；没有改变模型决策、工具或求解逻辑。云端实际执行的 70 个源文件均已按 manifest 哈希归档。

| 条件 | Qwen3-4B 基模 | GLM 教师 |
|---|---|---|
| 思考/采样 | 不思考、贪心解码 | max 思考，temperature=1、top_p=0.95 |
| 单次输出上限 | 384 token | 8,192 token，含思考 |
| 单题上限 | 120 秒 | 600 秒 |
| 决策步/工具/求解上限 | 24 / 24 / 3 | 24 / 24 / 3 |
| 单题输出预算 | 32,000 token | 32,000 token，含思考 |
| 请求提示 | 原有 system + 状态 | 相同状态，另加单调用协议提醒 |
| 模型调用数 | 198 | 247 |
| 已知输入 token | 503,143 | 626,086 |
| 已知输出 token | 6,211 | 229,848 |
| 思考 token | 不思考 | 已知 224,216 |
| 单题耗时之和 | 243.6 秒 | 7148.0 秒 |

这不是等算力、等时限比较。教师可用更多推理开销产生候选示范，SFT 的价值需要再由小模型训练后的同条件成绩证明。GLM 正式运行并发 4 题，耗时之和不等于批次墙钟时间；远程 API 模型也没有固定权重哈希或确定性 seed。

教师有 242/247 次请求返回思考 token 明细；5 次请求完整用量未知。缓存输入共 288,896 token。表内只统计正式 24 题收到的用量，不含前期接入探测和中断试跑，也不是账户最终账单。人民币费用应以国内账户账单核对，不套用国际站价格。

## 5. 当前仍需处理的问题

正式失败案例：

- `evidence-04`：`agent_deadline_exceeded`；最终动作 `retrieve_city_knowledge`。
- `constraint-01`：`agent_deadline_exceeded`；最终动作 `solve_itinerary`。
- `constraint-02`：`agent_deadline_exceeded`；最终动作 `validate_itinerary`。
- `constraint-03`：`agent_deadline_exceeded`；最终动作 `solve_itinerary`。
- `constraint-04`：`agent_deadline_exceeded`；最终动作 `get_poi_detail`。

`evidence-04` 的轨迹显示：教师改写查询后曾成功求解，但随后再次发出原来的过期查询，草案失效；再校验时已经没有可用的求解成果，最终达到时限。这是可定位的决策失误，不能用作正向示范。

最优先修的是终止契约：`loop.py` 的 `_refresh_post_validation_capability` 将仅含 `MUST_VISIT_MISSING` 的失败一律标为 `solvable`，没有区分尚未找到必去项、求解遗漏与闭馆/硬预算导致的不可行。`reward.py` 的 `_terminal_kind_and_report` 又只在 `infeasible/unsafe/missing_tool` 标签下认可合理停止。

独立基础设施检查使用显式脚本顺序“查询 → 详情 → 矩阵 → 求解 → 校验 → 根据证据停止”，4 个约束案例全部校验失败，能力标签却仍为 `solvable`，最终停止全部得到 `task_failed`。这些记录明确标为脚本检查，不计入教师成绩。这证明训练前必须补终止路径的可达性检查，不能只检查正例能规划、反例会被校验拒绝。

修复应让验证器提供清楚的事实和不可行依据，区分“尚未证实可行”和“已证实不可行”，由模型决定继续、追问或停止；奖励核验实际依据，不能依赖一个错误的固定标签或要求照抄单一失败原句。这仍是在现有 Harness 内修正契约。

另有两处已从代码与轨迹确认的诊断数据限制：

1. **餐厅查询没有对应结果。** `search_pois` 无论关键词如何，都返回相同的 4 个景点；当前信息查询也可能只给泛化内容。教师想落实午晚餐时，会在这里重复搜索。这类数据不适合直接生成真实餐厅决策示范。
2. **闭馆证据相互矛盾。** 闭馆题的详情含 `closed_dates`，而新的博物馆查询固定返回“当天开放 08:00–21:00”。若要测证据冲突，应明确冲突来源和验收条件；若只测闭馆约束，工具事实应一致。

本轮保留原题和原判分，确保与基模可对照；没有在看到教师失败后改题重算成绩。这两处问题需要在新训练任务中修正并检查。

## 6. 下一件事，按这个顺序

1. **先修终止契约及新数据环境。** 必去项遗漏不能一律推断为可修复；对可修复与已证实不可行的情况分别验证“继续/停止”路径。为餐厅检索提供匹配记录，让闭馆/票价事实在工具间一致；专门的冲突证据题单独定义。旧 24 题及原始成绩保留。
2. **另建一小批训练任务。** 建议先 20–30 条，优先覆盖补齐证据、过期查询改写、故障恢复和硬约束冲突。按实体、场景模板和来源与 dev/test 隔离。
3. **GLM 生成候选，Harness 实际执行，人工逐条审核首批。** 保留状态、模型动作、参数来源、工具结果和最终验收；去除无依据的参数与没有进展的示范。不把这 24 道开发题直接用于训练。
4. **再做小批 SFT。** 用每一步“当前状态 → 原生工具动作及参数”训练小模型，工具结果和教师私有思考不作为预测目标。训练后用相同学生解码、预算、环境比较，才判断小模型是否更会决策。

暂时没有启动新 SFT 或 GRPO。当前完成的是教师接入、真实运行、验证和训练前的问题定位。
