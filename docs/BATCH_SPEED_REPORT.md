# TravelAgent2 云端批量采集提速结果

已实现共享单模型的动态 GPU 微批量、并发任务队列、断点续跑与有上限的基础设施重试。此轮只运行学生模型，不调用教师 API，不训练或修改权重。

## 相同 5 个场景的云端实测

| 指标 | 串行：batch=1 / concurrency=1 | 批量：batch=4 / concurrency=4 |
|---|---:|---:|
| 采集阶段耗时（模型加载后） | 53.5 秒 | 35.6 秒 |
| 含程序启动、哈希和模型加载的命令耗时 | 91.9 秒 | 76.4 秒 |
| 任务通过 | 5/5 | 5/5 |
| 模型决策调用 | 31 | 31 |
| GPU generate 批次数 | 31 | 12 |
| GPU 峰值 allocated 显存 | 8.39 GiB | 10.63 GiB |
| 解析/参数错误 | 0 | 0 |

采集阶段实测 **1.50 倍吞吐**，耗时减少约 33.4%；包含加载等固定开销的整条命令约 1.20 倍。不是 4 并发就必然快 4 倍；此小批只有 5 个任务，还存在尾部单任务和不同输出长度的影响。尚未做千条规模或持续负载压测。

两组使用相同模型、权重哈希、解码参数、任务和 provider。5 组首轮实际 prompt token 哈希全部一致。批量没有要求与串行逐 token 相同：2 个场景的首轮搜索关键词发生变化，3 个场景动作序列相同，后续状态输入哈希也不完全相同。两组均 5/5 完成；各 31 个状态、动作对应、工具/求解预算和独立行程校验通过。不能以本结果声称所有任务质量不变。

这些仍是偏好匹配分为 0 的旧流程场景，仅用于速度与执行正确性检查；新增高质量 SFT 条目仍为 0。

## 已实现的执行机制

- 同一 GPU 只加载一份现有 Qwen3-4B + SFT adapter；独立任务的下一步请求在 15 ms 等待窗口内合为一个 generate 批次，默认最多 4 条。
- 每条任务单独保持 policy audit、Harness ledger、工具计数和故障消费状态。同一任务内部仍按工具依赖顺序执行。
- 左填充与 attention mask 保留原 prompt token；逐条在首个 EOS 后裁去批量填充，解析、允许动作和参数权限仍使用当前契约。
- 默认 padded prompt token 上限 24,000，超出时拆批；单条超上限明确失败，不静默截断。GPU OOM 也有拆批处理，本次未实际触发 OOM。
- jobs.json 原子持久化，Linux 文件锁阻止两个进程同时写同一任务队列。中断尝试保留，新尝试写入新目录。
- 默认最多重试 1 次基础设施失败；模型任务失败作为完成的失败测量保留，不自动重复尝试挑选成功结果。
- 已完成任务恢复时跳过模型加载与推理；串行、批量两条实测命令均重复启动验证了跳过行为。
- 最终版本进一步检查已完成 evidence 的 SHA-256；缺失/篡改证据、配置/权重/源码变化或重试耗尽均报错，不误报成功。恢复可从逐条结果重建汇总文件。

相关测试 **76 passed**（冻结 runtime 的相关测试范围，并非整个大仓库全量测试）。GPU 对照来自 runtime-v1；最终 runtime-v2 仅加强恢复时的证据检查和重试耗尽处理，推理引擎未改动，此处没有重新计时。原测量目录及源码保持不变。

## 云端使用

最终源码目录：`/root/autodl-tmp/travelagent-batch-speed-20260905/runtime-v2`。沿用当前云端 Python 环境与 test-deps/PYTHONPATH 配置运行：

```bash
python scripts/collect_harness_batch.py \
  --cases-file /root/autodl-tmp/travelagent-migration-rebuild12-20260905/preflight-v3/rollout-ready-cases.json \
  --checkpoint /root/autodl-tmp/harness-sft-first-20260905/sft-pilot-v2 \
  --output /root/autodl-tmp/travelagent-batch-speed-20260905/new-batch-run \
  --batch-size 4 --concurrency 4 --retries 1
```

运行中断后使用完全相同的命令恢复。输入需为显式 train、来源组去重、已通过迁移环境检查的 case；当前入口只支持迁移 provider v2，未声称是任意外部数据直接接入接口。源码变化时使用新输出目录。

现有教师采集原本已有 4 任务并发，本轮未改教师路径，也未开启付费批量任务。GLM-5.3-Flash 每批 API 含失败重试不超过 100 元的约束继续有效；未来接入自动教师大批队列仍须核对价格并落实请求级预算预留，不能把此学生 GPU 队列误当成已完成的教师计费控制器。
