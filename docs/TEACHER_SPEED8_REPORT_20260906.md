## 实施与审核

- GLM客户端新增显式reasoning_effort参数，默认max；其余温度1、top_p .95、输出上限8192、HTTP180秒、episode600秒等待与原工具/solver/token预算不变。官方模型卡列出low/high/max支持范围，实际请求与原始回复逐条保存。[官方模型卡](https://huggingface.co/zai-org/GLM-5.3-Flash)
- 4组首个API请求逐项核对，仅reasoning_effort不同；provider快照相同。初态示范的私有trajectory_id与task.updated_at不同，其余ledger字段完全相等，这两项不出现在模型输入；接手初态ledger逐字段相同。接手恢复原学生已消耗步骤、工具、solver和token预算及provider状态；未重放学生工具获得额外机会。学生源数据仍是旧冻结20题，未使用12题dev。
- 实验队列实现偶发供应商错误保留失败后继续新任务；429遵循Retry-After；认证/权限和预算失败停止；最近10请求3次供应商错误熔断。没有自动HTTP重试。旧冻结采集器没有改写，新队列仅在本试验runner启用。运行中队列事件：{"stopped_reason": null, "events": []}。
- 原总账内新增10元/160请求的原子子限额，跨重启保留已结算、未知和在途预留；没有新建独立100元账本。29项云端测试通过，覆盖参数、失败不重试、限流等待、熔断、并发预算和恢复。真实运行未出现的故障行为只能称模拟测试通过。
- 状态审计 109，学生来源链核对 4；独立原始目录/具名餐厅路线通过 8。最终可审核标签 36 动作、1143 监督token，最长 4060，截断 0；实际TRL preprocessing/collator核对通过，未训练。
- 计数核对拒绝：{"named20-00/demo/high": ["EPISODE_STEP_COUNTER_MISMATCH"]}。预算耗尽可能在提案计费后、完整step记录前结束；本轮暴露的这类轨迹保留为失败证据，并明确拒绝训练使用，没有用已记录快照哈希通过来代替完整计数一致性。冻结执行器未在实验中途修改；该终态记录缺口仍需后续执行器修复。
- 审核还修正了省略可选参数的误判：教师原始API返回空参数时，解析器可以补上默认strategy，但该默认值不是教师发出的监督内容。逐项对照原始response、model_arguments和导出标签，保留真实空参数；守卫拒绝依旧不作标签。额外3项审核测试通过，共32项测试。失败的早期审核与最终audit-v2分开保留，没有更改任务质量门槛。
- 新标签单独存放，未并入已冻结的166动作训练发布包，也不计作新增独立任务。审核器继续排除未执行守卫、控制器代答、学生前缀和私有思考标签；任务质量门槛不变。完整恢复启动已确认跳过完成任务，没有重复付费。
