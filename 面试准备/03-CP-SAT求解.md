# TravelAgent 面试准备 · 03 行程规划核心:OR-Tools CP-SAT 与 VRP-TW

这是项目**最硬核、最能拉开差距**的一块。从"什么是约束求解"讲到"为什么不用 LLM 排行程"。

---

## A. 为什么排行程是"数学难题",LLM 干不了

举例:10 个景点排 3 天,要同时满足:
- 每个景点有营业时间,必须窗口内到;周一闭馆的不能排周一
- 总预算不能超;每天走路别超老人承受强度
- 必去外滩、迪士尼;迪士尼要玩一整天
- 远郊景点别和市中心挤一天(否则一天来回 3 小时)
- 三个观景台只去最好的一个;午饭晚饭要排进饭点

这些规则**互相牵制**,可行排法是天文数字里的极少数。LLM 是"语言概率模型",会给你**看起来合理**的行程,但**不会精确累加时间/预算、不保证不撞闭馆、不算最优路线——它没有"硬约束"概念**。

**所以拆两半**:理解需求 + 润色文案 → LLM;**真正排行程 → 数学求解器**。这是项目最核心的设计决策。

---

## B. 什么是约束求解 / CP-SAT(大白话)

**约束求解**:你只描述"**有哪些规则(约束)**"和"**想优化什么(目标)**",求解器自动在所有可能里找出**满足全部规则、目标最好**的方案。你只写"要什么",不写"怎么找"。

**CP-SAT**:Google OR-Tools 的**约束规划求解器**(Constraint Programming-SAT)。不傻穷举,用**分支定界 + 剪枝**砍掉大片不可能方案,快速逼近最优。

类比:你说"要个数,大于 3、小于 8、是偶数",求解器直接给 4 或 6,不从 1 数到 100。

## C. VRP-TW:把行程映射成经典运筹问题

**VRP(车辆路径问题)**:一辆车从仓库出发访问一堆客户点,排路线使总路程最短,回仓库。
**TW(时间窗)**:每个点有营业时间,必须窗口内到。

| VRP 概念 | 你的行程 |
|---|---|
| 仓库(起点/终点) | 酒店(代码里"虚拟节点 0",每天从酒店出发回酒店) |
| 客户点 | 景点 POI |
| 一辆车的一条路线 | 一天的行程 |
| 多辆车 | 多天(travel_days) |
| 时间窗 | 景点营业时间 / 闭馆日 |
| 车的容量 | 每天预算、步行强度、时长上限 |

所以你的问题学名叫 **VRP-TW(带时间窗的车辆路径问题)**,**NP-hard**(没有已知多项式时间精确算法)的经典难题——这词一说,运筹背景的面试官会高看一眼。

## D. 怎么建模(决策变量 + 约束 + 目标)

**1) 决策变量(求解器要决定的"开关")**:
- `X[d,i,j]`:第 d 天是否从景点 i 直接走到 j(路线弧)
- `V[d,i]`:第 d 天是否去景点 i(0/1)
- `A[d,i]`:第 d 天到达 i 的时间
- 每天花费 `DC`、每天步行 `DW`

**2) 约束(代码里真有)**:
- **路线连通**:`AddCircuit` 保证每天是一条从酒店出发、串当天景点、回酒店的闭环
- **时间窗**:到达在营业时间内,玩完不超闭馆
- **时间传播**:到 j 时间 ≥ 到 i 时间 + 在 i 时长 + i→j 车程(+缓冲)
- **每天时长/预算/步行**不超上限
- **每景点最多一次**;**必去点**必排进
- **整天景点**(迪士尼)占一整天;**餐厅节点**绑定某天饭点 + `AddNoOverlap` 不和景点重叠
- **远郊隔离**:车程太远的两景点不同天;**闭馆日**不排

**3) 目标(给方案打分,最大化)**:
```
最大化:  3000×去的景点数
        − 6000×重复同类景点
        − 400×动线分散度
        − 80×总车程
        − 预算不均
        + 20×偏好匹配
        − 10×热门拥挤
        − 到达时间(尽量早出发)
```
权重是**精心设计的层级**:`景点数(3000)` 压过车程,保证"能到的景点不因多走路被丢";`去重(6000)` 又压过景点数,保证"三观景台只留最好一个"。

> 💡 这个**权重层级**是杀手锏——能讲清"为什么 3000、为什么 6000 更大",说明你真懂多目标平衡。

## E. 多目标怎么处理:epsilon-constraint

行程要同时优化"去得多、走得少、花得少、不累、偏好匹配"——这些**互相冲突**。

用 **epsilon-constraint(ε-约束法)**:**选一个主目标优化,其余转成"不能差于底线"的约束**。代码里主目标是"最大化景点数/综合分",而"步行差异、预算均衡、最低偏好、拥挤度"设成上下限约束(`eps.max_walk_diff` 等)。

> 📖 八股:多目标两大流派——**加权和法**(多目标加权成一个,即目标函数)、**ε-约束法**(主目标 + 其余转约束)。你项目**两者都用**:目标函数内部加权,外部再套 ε 约束兜底。

## F. 工程鲁棒性:热启动 + 早停 + 贪心兜底

1. **热启动(warm-start)**:先用"地理聚类"快速猜粗略分天(近的景点分同天),作为**提示(AddHint)**喂 CP-SAT,让它在好起点上**精修**而非从零瞎找。
2. **收敛早停**:`TimeoutCallback` 跑过 45% 时间后,新解只好 0.3% 以内就**提前停**——方案已收敛,剩下只是证明最优。砍掉大实例约 18 秒尾巴。
3. **贪心兜底**:CP-SAT 超时/无解时**降级**贪心(每步选当前最划算景点);**小问题(≤15 景点、≤3 天)直接贪心**——杀鸡不用牛刀。

> 💡 **追问"求解器算不出来怎么办"**:"三层兜底:热启动加速、收敛早停防无谓等待、CP-SAT 失败自动降级贪心。最坏情况也能秒级返回可行行程,不让用户卡死。"

## G. 必背 + 高频追问

**必背三句**:
1. 排行程是 **VRP-TW(带时间窗车辆路径,NP-hard)**,LLM 算不可靠,用 **OR-Tools CP-SAT** 约束求解。
2. 建模:决策变量(去不去/路线/到达时间)+ 十几种硬约束 + 加权多目标(景点数优先、去重最高优先级)。
3. 鲁棒性:热启动 + 收敛早停 + 贪心兜底,保证秒级一定出结果。

**高频追问**:
- *"为什么不用 LLM 排?"* → LLM 无硬约束概念,不保证可行/最优;求解器保证可行+最优+可复现。
- *"CP-SAT 和遗传/启发式区别?"* → CP-SAT **精确**(给足时间能证明最优),启发式(贪心/遗传)**近似**。你两者结合:CP-SAT 求质量,贪心保速度和兜底。
- *"酒店为什么虚拟节点?"* → 每天路线需固定起终点锚,把酒店设节点 0、车程清零,当每天出发/返回锚点。
- *"big-M 是什么?"* → 一种"开关约束"技巧:某弧没被选(X=0)时,用大常数 M 让相关时间约束"失效"。代码注释记了 big-M 调小会导致误判无解、退化贪心的坑——很好的"我 debug 过"故事。

> 📖 **八股底**:NP-hard、分支定界(branch & bound)、线性规划松弛(LP relaxation)、约束传播、big-M 方法、ε-约束 vs 加权和。
