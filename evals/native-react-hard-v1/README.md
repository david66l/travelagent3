# Native ReAct Hard Benchmark v1（已退役）

该版本在 Dev 首次真实运行时发现题面与标签合同问题，已由 `native-react-hard-v2` 替代。v1 只保留为审计记录，不得再用于模型比较或对外指标。

这是 TravelAgent 新 ReAct 协议的第一版正式困难评测集，共 200 个不同任务。

## 数据划分

- `dev.jsonl`：40 题，只用于评测工具开发、错误定位和 checkpoint 选择。
- `test.jsonl`：160 题，只用于最终冻结评测，不得根据结果继续调参。
- `manifest.json`：数据哈希、生成代码版本、分层数量和污染审计结果。

开发集只使用北京、上海、广州、成都；测试集使用另外 16 个城市，两个 split 没有城市重合。

## 场景矩阵

每个能力族 20 题，共 10 个能力族、40 个语义簇：

1. `clarification`：缺目的地、天数、出发地等必要字段。
2. `poi_grounding`：必去、禁去、偏好、事实核实与通勤上限。
3. `current_information`：天气、营业时间、活动和深夜餐厅。
4. `transport_grounding`：航班/高铁、出发地和到达时间窗。
5. `hard_constraint_conflict`：预算、时间窗、容量和品质要求冲突。
6. `accessibility`：轮椅、老人、孕妇和儿童约束。
7. `tool_recovery`：超时、空结果、限流和过期数据故障注入合同。
8. `revision`：增加天数、降低预算、必去/禁去和人数变化。
9. `safe_termination`：闭馆、不可达、预算不可行和容量不可行。
10. `noisy_multilingual`：中英混输、缩写、口语和错别字。

难度分布为 L2 40 题、L3 100 题、L4 60 题。预期业务终态包括 20 个澄清、60 个正常草案、100 个“草案或有证据的安全终止”和 20 个用户修改重规划。

## 审计结果

- 200 个唯一 `statistical_unit_id`。
- 200 个唯一规范化请求和任务指纹。
- 内部没有达到 0.90 阈值的近重复题。
- 扫描 291 个历史训练 JSONL，抽取 13,940 条历史请求。
- 与历史语料的原文重合为 0，达到 0.90 阈值的近重复为 0。
- 数据集 SHA-256：`ad0189175df3e0deef57e4a4472577029e3ba6f33f86ec4986a6ae83d084173f`。

## 统计与主张边界

评测主单位是独立 `statistical_unit_id`。同一道题重复采样只能衡量随机稳定性，不能扩大独立样本量。最终报告必须给出任务级成对差值和按 `cluster_id` 聚类的 Bootstrap 置信区间。

这些题由程序化组合生成，尚未经过两名独立人工标注，因此不能对外声称“200 道独立人工题”。准确说法是：**200 个不同的冻结任务，覆盖 20 个城市和 40 个语义簇，并完成训练语料污染审计。**

任何 SFT、DPO 或 GRPO 数据构建脚本都不得读取此目录。`dev` 可以用于选 checkpoint；一旦查看 `test` 结果，就不得再据此修改模型或奖励后重新复用为最终测试。
